# エラー処理（言語横断）

> 「失敗をどう呼び出し元に伝えるか」を言語をまたいで整理する。
> ここは各言語の**機構（仕組み）の比較**に徹する。どう使い分けるか（設計判断）は別ファイル → [../設計/エラー設計.md](../設計/エラー設計.md)。
> 各言語の `解説/` からここへリンクする横断ドキュメント。

## 一言で
> 失敗の伝え方は大きく「**投げる(例外)**」「**返す(値)**」の2系統。言語ごとにどちらが主流かが違う。例外言語では throw して上で catch、値で返す言語では戻り値の `err` を毎回チェック、型で強制する言語では `Result`/`Option` を開けないと先へ進めない。

## 大前提：失敗は「特別なルート」か「普通の戻り値」か
正常系の値は関数の戻り値で返る。問題は**失敗したとき**。これに2つの哲学がある:

```
投げる(例外):  失敗は「普通の流れから外れる特別なルート」。
              関数は失敗を握らず上に投げ、どこか上の catch が拾う。
              ┌── try ──┐
              │ f()  ←─ ここで throw          │
              └── catch ┘ ←─ 一気にここまで飛ぶ

返す(値):      失敗も「普通の戻り値の一部」。
              関数は (結果, エラー) のように失敗を値で返す。
              呼び出し側が毎回その場で if で確認する。
              v, err := f(); if err != nil { ... }
```

👉 例外は「**書き忘れても飛んでいく（うっかり無視しにくい）**」が、どこへ飛ぶか追いにくい。値返しは「**流れが目に見える**」が、チェックを**書き忘れると握りつぶす**。

## 3つの機構
- **例外(try/catch・throw/raise)** … 失敗を投げ、上の階層で捕まえる。捕まえなければプログラムが落ちる。多くの言語の主流。
- **戻り値でエラー** … 失敗を普通の戻り値として返す。Go の `if err != nil` が代表。呼び出し側が毎回確認する前提。
- **Result / Option 型** … 「成功か失敗か」「値があるか無いか」を**型に閉じ込める**。Rust が代表で、中身を開けないと使えないため**チェックを言語が強制**する。

## 11言語比較表
| 分野 | 言語 | 主流の方式 | null/nil の扱い | 検査の強制 |
|---|---|---|---|---|
| BE | **Java** | 例外（throw / try-catch）★チェック例外あり | `null`（NPE の温床） | **チェック例外は宣言/捕捉を強制**、実行時例外は任意 |
| BE | **Python** | 例外（raise / try-except） | `None` | なし（捕まえ忘れても文法は通る） |
| BE | **Ruby** | 例外（raise / begin-rescue） | `nil` | なし |
| BE | **PHP** | 例外（throw / try-catch）★旧来は false 返しも混在 | `null` | なし |
| BE | **Go** | **多値返りの `err`**（`if err != nil`） | ゼロ値 + `nil` | 弱い（`_` で捨てられる。linter で補強） |
| FE | **JavaScript** | 例外（throw / try-catch、非同期は reject） | `null` / `undefined` | なし |
| FE | **TypeScript** | 例外（実行時は JS）。型に Result を**自作**する流派あり | `null`/`undefined`（`strictNullChecks` で型で弾ける） | なし（例外型は型に乗らない） |
| FE | **Rust** | **`Result<T,E>` / `Option<T>`** + `?` 演算子 | `Option` で表現（生 null は無い） | **強制**（開けないとコンパイルが通らない、未使用も警告） |
| MO | **Dart** | 例外（throw / try-catch） | `null`（null 安全あり） | なし |
| MO | **Kotlin** | 例外（throw / try-catch）★`Result`・`runCatching` あり | **null 安全**（`?` 型のみ null 可） | null は強制、例外は任意 |
| MO | **Swift** | 例外風 `throws`/`try` + **`Result` / `Optional`** | **`Optional`**（生 null は無い） | **`try` の明示を強制**、`Optional` も開封必須 |

> **ざっくり**：例外が主流なのは **Java / Python / Ruby / PHP / JS / TS / Dart / Kotlin**。**Go だけが値返し（err）**。**Rust は型強制（Result/Option）**。**Swift は例外風 `throws` と `Result`/`Optional` の併用**で、検査を文法で強制する点が独特。Kotlin は例外主流だが null 安全と `Result` を併せ持つ中間型。

### 「検査の強制」の強さで並べると
```
強い ── Rust       : Result/Option を開けないと値に触れない（コンパイルで弾く）
     ── Swift      : try を書かないと throws 関数を呼べない / Optional は開封必須
     ── Java       : チェック例外だけは throws 宣言か catch を強制（実行時例外は任意）
     ── Kotlin/他言語: null は型で強制されるが、例外の捕捉は任意
弱い ── Go          : err を返すが、_ で握りつぶせる（言語は止めない）
        Python/Ruby/JS/TS/PHP/Dart: 例外を捕まえ忘れても文法は通る（落ちるだけ）
```

## それぞれの書き味
**Go：失敗は戻り値。毎行 `if err != nil`**
```text
v, err := doSomething()
if err != nil {
    return nil, fmt.Errorf("失敗: %w", err)  // wrap して上に返す
}
use(v)
```

**Rust：`Result` を返し、`?` で「失敗なら即 return」**
```text
fn run() -> Result<Data, MyError> {
    let v = do_something()?;   // 失敗(Err)なら、その場で関数から Err を返す
    Ok(use_it(v))             // 成功は Ok で包む
}
// Option も同様：let x = map.get(key)?;  // None ならここで抜ける
```

**例外言語（Java / Python / Ruby / JS / Kotlin / Dart / PHP）：throw して上で catch**
```text
try {
    v = doSomething()        // 失敗すると throw され、ここから下は飛ばされる
    use(v)
} catch (e) {                // 飛んできた失敗をここで拾う
    log(e)
}
// 捕まえなければ、上の階層へ伝播し、最後まで誰も拾わなければ落ちる
```

**Swift：`throws` 関数は `try` を明示。`Result` も選べる**
```text
// 例外風
func run() throws -> Data {
    let v = try doSomething()   // try を書かないとコンパイルが通らない
    return useIt(v)
}
do { let d = try run() } catch { log(error) }

// 値で扱いたいとき
let result: Result<Data, MyError> = Result { try run() }
switch result { case .success(let d): ...; case .failure(let e): ... }
```

## 移行時の事故
[言語間の移行ギャップ.md](./言語間の移行ギャップ.md) の④と整合。**前の言語の「失敗の伝え方」の癖がそのまま出て**事故る。

- **例外言語脳 → Go**：`err` を `_` で捨てて握りつぶす。「どうせ例外で飛ぶだろう」と思って `if err != nil` を書かず、失敗が**無言で素通り**する。Go では失敗は値なので、チェックしなければ無かったことになる。
- **Go脳 → 例外言語**：何でも戻り値やフラグで分岐し、例外を使わない不自然なコード。逆に、捕まえた例外を `rescue nil` / `catch {}` で**握りつぶして**原因を消す。
- **例外言語脳 → Rust**：`unwrap()` / `expect()` を多用し、本番で `Err`/`None` が来てパニック。本来は `?` や `match` で扱う。`Result` を無視できないのは「面倒」ではなく**失敗を見落とさせない仕組み**。
- **Rust/Swift脳 → 例外言語**：戻り値を必ず確認する癖は良いが、例外言語では throw が「上に勝手に飛ぶ」前提を忘れ、握れる失敗まで全部 try-catch で囲んで読みにくくなる。
- **Java脳 → Kotlin/他言語**：チェック例外（`throws` 宣言の強制）の感覚で「コンパイラが捕捉漏れを教えてくれる」と思い込むが、Kotlin にチェック例外は無い → **捕まえ忘れて実行時に落ちる**。
- **`Result` を無視できる言語での放置**：Kotlin の `runCatching`、TS の自作 Result、Swift の `Result` は、`Rust` と違い**開けなくても文法が通る**。返ってきた `Result` を確認せず捨てると、失敗が静かに消える。
