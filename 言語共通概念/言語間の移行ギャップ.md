# 言語間の移行ギャップ（乗り換えると事故る癖）（言語横断）

> ある言語に慣れた人が別の言語を書くと、**前の言語の癖が無意識に出て**バグる。
> 値/参照だけでなく、nil・エラー処理・文字列・型・真偽値などの「移行ギャップ」を集める。

## ひとことで言うと
言語の差は文法より**「暗黙のルールの違い」**で事故る。引数を変えると伝わるか、未設定は何になるか、文字列は変えられるか――こういう体に染み付いた前提がズレると、コンパイルは通るのに挙動が違う、というバグになる。

## ① 引数の書き換え（値か参照か）
**一番踏む。** Go/Swift/PHP配列は「コピー」なので引数を変えても呼び出し元は無傷。その癖でRuby/Python/JS/Java/Kotlin/Dartを書くと、**共有オブジェクトを破壊**する。
```ruby
# Go脳：「引数はコピーだから中で変えてOK」→ Rubyでは呼び出し元まで変わる
def normalize(user)
  user.name = user.name.strip   # 呼び出し元の user を破壊
end
def add_default(list)
  list << "default"             # 呼び出し元の配列を汚す
end
```
- **逆方向**：Ruby/Python脳でGoを書くと「引数を変えたのに反映されない」（Goは値コピー → ポインタ `*T`／ポインタレシーバが要る）。スライスを `append` で伸ばしても呼び出し元の `len` が増えず混乱。
- 詳しい比較 → [値渡しと参照.md](./値渡しと参照.md)

## ② 未設定の値（nil/null か ゼロ値か）
```
Go:           ゼロ値が入る（"" / 0 / false / nil）→ "".len も安全
Ruby/Python:  未設定は nil/None → nil.length で NoMethodError / AttributeError
Java/C系:     null → NullPointerException
Kotlin/Swift/Dart/TS: null安全。? を付けない型に null は入れられない（コンパイルで弾く）
```
- **Go脳でRuby/Python**：「空文字や0が来るはず」と思って `nil` が来て落ちる。
- **動的型脳でKotlin/Swift**：`?`/`!!`/`if let` を嫌って付けず、コンパイルが通らない or `!!` で実行時クラッシュ。
- **Java脳でKotlin**：プラットフォーム型（Java由来）経由で `null` がすり抜け、せっかくのnull安全が無効化。

## ③ 文字列は変えられるか
```
不変(immutable): Java / Python / PHP / JS / TS / Go / Dart / Kotlin / Swift
可変(mutable):   Ruby（s << "x" で中身が変わる＝共有先も変わる）
                Rust（String は可変だが &mut/所有権が要る）
```
- **Ruby脳で他言語**：`str << x` の感覚で破壊しようとして効かない／別物が返る。
- **他言語脳でRuby**：文字列を引数で受けて `<<` し、呼び出し元の文字列まで変えてしまう。`freeze` / `dup` を使う癖が要る。

## ④ エラー処理（例外 / 戻り値 / Result）
```
例外(raise/throw):      Ruby / Python / Java / PHP / JS / TS / Kotlin / Swift / Dart
戻り値で返す:           Go（if err != nil）
型で強制(Result/Option): Rust（? 演算子）、Swift も Result あり
```
- **Go脳で他言語**：何でも戻り値やフラグで分岐し、例外を使わない不自然なコード。逆に例外を握り潰す（`rescue nil`）。
- **例外脳でGo**：`err` を `_` で捨てて握り潰す／`panic` を例外代わりに濫用（Goではpanicは非常時用）。
- **例外脳でRust**：`unwrap()` を多用して本番でパニック（本来は `?` や `match` で扱う）。

## ⑤ 真偽値（何が「偽」か）
```
Ruby:   偽は nil / false だけ（0・""・[] は真）
JS:     偽は false/0/""/null/undefined/NaN（[] や {} は真）
Python: 偽は False/0/""/[]/{}/None（空コレクションも偽）
Go:     bool 型のみ。0や""は条件式に書けない（コンパイルエラー）
```
```ruby
if 0 then puts "Rubyは真" end          # 通る（0は真）
```
```python
if []: ...   # Python は空リストが偽 → 通らない
```
- **Python脳でRuby**：`if list`（空なら偽）のつもりが、Rubyでは空配列も真。`list.empty?` を使う。
- **JS/Python脳でGo**：`if str`（空かどうか）が書けない。`if str != ""` と明示する。

## ⑥ 等価性（== の意味）
```
Java:   == は参照比較。値比較は equals()（文字列で典型事故）
Ruby:   == は値、equal? が同一性、=== は case 用
Python: == は値、is が同一性
JS:     == は型変換あり（罠）、=== が厳密。常に === を使う
Go:     == は値比較（構造体も）。スライス/マップは == 不可（コンパイルエラー）
```
- **Ruby/Python脳でJava**：`"a" == "a"` が `false` になり得る（参照比較）→ `.equals`。
- **他言語脳でJS**：`==` を使って `0 == ""` が true 等でハマる → `===`。

## ⑦ コレクションのコピー / 共有
```
渡すと参照を共有: Ruby(Array/Hash) / Python(list/dict) / JS / Java / Kotlin / Dart
渡すとコピー:     PHP(配列) / Go(配列・構造体) / Swift(Array/Dict＝値型)
```
- **PHP/Go/Swift脳で他言語**：受け取ったコレクションを安心して破壊 → 共有元が壊れる。
- **他言語脳でPHP**：配列を渡して中で変えたのに反映されない（コピーだから）。`&` か戻り値で返す。

## ⑧ 並行モデル
```
Go:      goroutine + channel（軽量・大量に作る前提）
Java/Kotlin: スレッド + Virtual Threads / coroutine
Python:  GIL（CPU並列は苦手、I/Oはasyncio）
JS/TS:   シングルスレッド + イベントループ（共有メモリの競合は基本起きない）
Swift:   async/await + actor（データ競合を型で防ぐ）
Rust:    所有権で競合を防ぐ（Send/Sync）
Dart:    isolate（メモリ非共有）
```
- **Go脳でPython**：goroutine感覚でスレッドを量産しCPU並列を期待 → GILで速くならない。
- **Java脳でJS**：ロックやスレッド共有の発想を持ち込むが、JSはシングルスレッドで不要（むしろ非同期の連鎖で考える）。

## まとめ：移行時に最初に確認する4点
1. **引数を変えると呼び出し元に伝わるか**（②③のために値か参照か）
2. **未設定は nil か ゼロ値か、null安全はあるか**
3. **エラーは例外か戻り値か**
4. **何が「偽」か・`==` は値か参照か**

この4つを新しい言語で最初に確認すると、移行直後の事故が大きく減る。
