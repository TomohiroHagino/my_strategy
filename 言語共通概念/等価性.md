# 等価性（言語横断）

> 「`a == b` が true のとき、何が等しいのか？」を言語をまたいで整理する。
> 「中身が等しい（同値）」のか「同じ物（同一・参照一致）」のか、どの演算子がどっちを意味するかは言語ごとに違う。
> 各言語の `解説/` からここへリンクする横断ドキュメント。

## 一言で
> 「**中身が等しい(同値)**」と「**同じ物(同一・参照一致)**」は別物。言語ごとに**どの演算子がどっちか**が違い、ここが事故源。`==` が同値の言語もあれば参照比較の言語（Java）もあり、さらに `==` が型変換をやらかす言語（JS/PHP）もある。

## 2つの等価
等価性には大きく2種類ある。これを混同すると、「同じはずなのに false」「別物なのに true」という事故になる。

**① 同値（value equality）＝中身が等しい**
2つの物が**別インスタンスでも、保持している値が等しければ等しい**とみなす。
```
a ─→ 0x100 │ Money{ 100, "JPY" }│
b ─→ 0x200 │ Money{ 100, "JPY" }│   ← 別の本体だが中身は同じ
同値比較：a == b → true（中身が等しいから）
```

**② 同一（reference identity）＝同じ物（参照一致）**
2つの変数が**メモリ上の同じ本体を指しているか**だけを見る。中身が同じでも、別インスタンスなら等しくない。
```
a ─→ 0x100 │ Money{ 100, "JPY" }│
b ─→ 0x200 │ Money{ 100, "JPY" }│   ← 別の本体
同一比較：a is b → false（指している本体が違うから）

c ─→ 0x100 ←─ a   ← 同じ本体を指す
同一比較：a is c → true
```

👉 「住所が入った箱」の話は [値渡しと参照.md](./値渡しと参照.md) と同じ。**同一比較は箱の中身（住所）が一致するか**を見ているだけ。

**値オブジェクトは同値で比較したい。** `Money(100, "JPY")` のような値オブジェクトは「IDではなく属性で等しさが決まる」ので、同一ではなく**同値**で比較するのが正しい。等価性を自前で定義（`equals`/`==` のオーバーライド）するのはこのため。
詳細 → [../設計/ddd.md](../設計/ddd.md) の値オブジェクト

## 11言語比較表
| 分野 | 言語 | 同値（中身が等しい） | 同一（同じ物・参照一致） | 型変換を伴う緩い比較 |
|---|---|---|---|---|
| BE | **Java** | `equals()` | `==`（参照比較。**プリミティブは値**） | なし |
| BE | **Python** | `==`（`__eq__`） | `is` | なし |
| BE | **Ruby** | `==` | `equal?` | なし（`eql?`は型も厳密、`===`はcase用） |
| BE | **PHP** | `==`（**緩い・型変換あり★**） | `===`（値も型も厳密。オブジェクトは同一性も） | **`==` がそれ★** |
| BE | **Go** | `==`（比較可能型の値比較。構造体も） | `==`（ポインタ同士なら同一） | なし |
| FE | **JavaScript** | `===`（厳密） | `===`（オブジェクトは参照一致） | **`==`（型変換あり）★** |
| FE | **TypeScript** | `===`（実行時はJS） | `===`（同上） | **`==`（実行時はJS）★** |
| FE | **Rust** | `==`（`PartialEq`/`Eq`） | `Rc::ptr_eq` 等（`==`に同一性はない） | なし（暗黙の型変換自体がない） |
| MO | **Dart** | `==`（`==`演算子をオーバーライド） | `identical(a, b)` | なし |
| MO | **Kotlin** | `==`（`equals()`を呼ぶ） | `===`（参照比較） | なし |
| MO | **Swift** | `==`（`Equatable`） | `===`（**クラスの参照比較のみ**） | なし |

> **ざっくり3グループ**：
> - **`==` が同値**：Python / Ruby / Go / Rust / Dart / Kotlin / Swift（素直な多数派）
> - **`==` が参照、同値は別物**：**Java**（同値は `equals()`。文字列で典型事故★）
> - **`==` が型変換する**：**JS/TS**（厳密は `===`）・**PHP**（厳密は `===`）

## 特に事故るやつ
**JS の `==` は型変換でカオス（だから `===` を使う）**
```text
0 == ""        → true   （両方0に変換される）
0 == "0"       → true
"" == "0"      → false  （↑なのに）
null == undefined → true
[] == false    → true
[] == ![]      → true   （有名な意味不明）
→ 結論：常に === を使う。== は禁止に近い扱い
```

**PHP の緩い比較（`==`）も型変換する**
```text
PHP 8 より前は特にひどかった:
0 == "abc"     → 8.0以降は false（8未満は true だった）
"1" == "01"    → true  （数値文字列として比較）
"10" == "1e1"  → true  （指数表記も数値化）
100 == "1e2"   → true
→ 結論：PHP も基本 === を使う（型まで一致を要求）
```

**Java の文字列 `==` 罠（同値のつもりが参照比較）**
```text
String a = new String("hi");
String b = new String("hi");
a == b           → false  （別インスタンス。参照が違う）
a.equals(b)      → true   （中身は等しい）

String c = "hi";
String d = "hi";
c == d           → true   ← リテラルはintern（文字列プール）で同一になりがち
→ これが罠。「たまたま動く」ので == を使う癖がつき、new や実行時生成で破綻
→ 結論：文字列・オブジェクトの比較は必ず equals()
```

**Ruby の `===` は case 文用（等価演算子ではない）**
```text
String === "hi"        → true   （=== は「右辺は左辺の仲間か？」）
(1..10) === 5          → true   （範囲に含まれるか）
/ab/ === "abc"         → true   （正規表現マッチ）
# case 文が裏で === を使う:
case x
when Integer then ... # Integer === x を評価している
when 1..10   then ... # (1..10) === x
end
→ 結論：=== を「厳密等価」のつもりで使うと別物。値比較は ==
```

**Python の `is` を値比較に誤用**
```text
a = 1000
b = 1000
a == b     → True   （値が等しい）
a is b     → False  （別オブジェクト。CPythonの整数キャッシュ外）

x = 256; y = 256; x is y → True   ← 小整数はキャッシュで同一（-5〜256）
→ 「is が動くことがある」のが罠。値比較に is を使うと数値・文字列で不定
→ 結論：値は ==、is は None 判定（x is None）など同一性が要る時だけ
```

## 移行時の事故
[言語間の移行ギャップ.md](./言語間の移行ギャップ.md) の「⑥ 等価性（== の意味）」と整合。`==` の意味が言語でバラバラなので、前の言語の癖がそのまま事故になる。

- **Ruby/Python/Go脳で Java**：`"a" == "a"` を同値のつもりで書く → 参照比較で `false` になり得る。`.equals()` を使う。
- **多数派言語脳で JS/TS**：`==` を素直に使う → `0 == ""` が true 等の型変換でハマる。常に `===`。
- **JS/多数派脳で PHP**：`==` を使うと型変換が走る → `"1" == "01"` が true。`===` で型ごと一致を要求する。
- **Java/JS脳で Python**：`is` を「`==` の仲間」と思って値比較に使う → 整数キャッシュの内側だけ偶然動き、外で `False`。値は `==`、`is` は `None` 判定に限定。
- **他言語脳で Ruby**：`===` を「厳密等価」と誤解 → case文用なので意図と全く違う結果。値比較は `==`。
- **文字列を `==`/`is` で比較して詰む**：Java（参照）・Python（`is` は同一性）が典型。文字列は「同値で比べたい」のに、言語が同一性を見てしまうパターン。
- **値オブジェクトの未定義**：自前クラスで `equals`/`==`/`hashCode` を定義し忘れると、同値で比べたいのに**既定が同一比較**になり「中身が同じなのに別物扱い」。Set/Map のキーや重複排除が壊れる（→ [../設計/ddd.md](../設計/ddd.md)）。

### 移行時に最初に確認する3点
1. **`==` は同値か、参照か、型変換するか**（Java=参照 / JS・PHP=型変換 / それ以外=同値）
2. **同一性を見る演算子は何か**（Python `is` / Kotlin・Swift `===` / Dart `identical` / Ruby `equal?`）
3. **自前の値オブジェクトで等価性を定義したか**（しないと既定の同一比較になる）
