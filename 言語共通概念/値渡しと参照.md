# 値渡しと参照（言語横断）

> 「メソッド/関数に変数を渡したとき、中で書き換えると呼び出し元に伝わるのか？」を言語をまたいで整理する。
> 各言語の `解説/` からここへリンクする横断ドキュメント。

## ひとことで言うと
多くの言語は「**値渡し**（箱の中身をコピーして渡す）」。ただし**箱に何が入っているか**が「値そのもの」か「住所（参照）」かで挙動が変わる。住所がコピーされる場合、**中身の変更は伝わる**が**住所の差し替えは伝わらない**。これが「参照の値渡し」。

## 大前提：変数は「箱」。中身が2種類ある
プリミティブは、箱に**値そのもの**が入る:
```
int a = 10;
   a
 ┌──────┐
 │  10  │   ← 箱の中に 10 が直接入っている
 └──────┘
```
オブジェクトは、箱に**住所**が入る（本体は別の場所）:
```
user = new User("alice")
   user                    メモリ上の 0x100 番地
 ┌────────┐              ┌──────────────────────┐
 │ 0x100  │ ───────────→ │ User{ name: "alice" }│
 └────────┘              └──────────────────────┘
 箱の中身は「住所 0x100」       本体はここにいる
```
👉 **オブジェクト変数の箱は、本体ではなく住所を入れている。** これが全ての鍵。

## 「値渡し」＝箱の中身をコピーして渡す
`f(user)` を呼ぶと、`user` の箱の中身（住所 0x100）を引数の箱にコピー → 2つの箱が同じ本体を指す。ここから2パターンに割れる:

**③ 中身を変更（伝わる）** `u.name = "bob"`
```
住所 0x100 の本体を書き換える
 ┌──────────────────────┐
 │ User{ name: "bob" }  │ ← 0x100 の中身が変わった
 └──────────────────────┘
   ↑          ↑
  user        u   ← 両方この本体を指す → 両方から "bob" に見える ✓
```

**② 住所を再代入（伝わらない）** `u = new User("bob")`
```
   user ─→ 0x100 │ User{ name:"alice" }│  （元のまま）
   u    ─→ 0x200 │ User{ name:"bob"   }│  （新しく作った別の本体）
 u の箱だけ 0x200 に変わった。user の箱は 0x100 のまま → ✗
```

## 一言で
> 渡すのは「本体」ではなく「**本体の住所のコピー**」。だから**中身の変更は伝わり、住所の差し替えは伝わらない**。

## 言語ごとの違い（この教材の全言語）
| 分野 | 言語 | 中身変更(③) | 再代入(②) | コレクション | 明示的な参照渡し |
|---|---|---|---|---|---|
| BE | **Java** | 伝わる | 伝わらない | 参照＝伝わる | なし |
| BE | **Python** | 伝わる | 伝わらない | list/dict＝伝わる | なし |
| BE | **Ruby** | 伝わる | 伝わらない | Array/Hash＝伝わる | なし |
| BE | **PHP** | 伝わる | 伝わらない | **配列＝コピーで伝わらない★** | **`&` であり★** |
| BE | **Go** | ポインタ次第★ | 伝わらない | スライス/マップ＝伝わる、**構造体＝コピー★** | ポインタ `*T` で明示 |
| FE | **JavaScript** | 伝わる | 伝わらない | 配列/オブジェクト＝伝わる | なし |
| FE | **TypeScript** | 伝わる | 伝わらない | 同上（実行時はJS） | なし |
| FE | **Rust** | **`&mut` の時だけ★** | 伝わらない | **既定はムーブ★** | `&`/`&mut`（借用） |
| MO | **Dart** | 伝わる | 伝わらない | List/Map＝伝わる | なし |
| MO | **Kotlin** | 伝わる | 伝わらない | MutableList等＝伝わる | なし |
| MO | **Swift** | class は伝わる / **struct はコピー★** | 伝わらない | Array/Dict＝**値（コピー）★** | `inout` であり |

> **ざっくり**：Java / Python / Ruby / JavaScript / TypeScript / Dart / Kotlin は**同じ**（参照の値渡し）。**PHP（配列はコピー＋`&`）・Go（構造体はコピー＋ポインタ）・Swift（値型はコピー＋`inout`）・Rust（ムーブ＋借用）の4つが独自**。

### Java / Python / Ruby は同じ
「参照の値渡し」モデル。中身変更は伝わり、再代入は伝わらない。コレクションも参照なので中で `append`/`push` すれば伝わる。
```python
# Python
def rename(u):  u.name = "bob"        # ③ 伝わる
def replace(u): u = User("bob")       # ② 伝わらない
def add(lst):   lst.append(4)         # list は参照 → 伝わる
```
```ruby
# Ruby
def rename(u) = u.name = "bob"        # ③ 伝わる
def replace(u) = u = User.new("bob")  # ② 伝わらない
def add(arr) = arr.push(4)            # Array は参照 → 伝わる
```

### PHP だけ2点違う ★
```php
// オブジェクトは Java と同じ
function rename($u){ $u->name = "bob"; }      // ③ 伝わる
function replace($u){ $u = new User("bob"); } // ② 伝わらない

// ★違い1：配列は「値（コピー）」。中で変えても呼び出し元に伝わらない
function add($a){ $a[] = 4; }                 // 伝わらない（Pythonのlist/RubyのArrayと逆）

// ★違い2：& を付けると明示的な参照渡し（再代入も中身も伝わる）
function addRef(&$a){ $a[] = 4; }             // 伝わる
```

### Go：住所を自分で書く ★
オブジェクトという区別はなく、**構造体は代入・引数渡しでコピー**される（中身も伝わらない）。変えたいなら**ポインタ `*T` を明示的に渡す**。スライス/マップは内部が参照的なので伝わる。
```go
func rename(u User)   { u.Name = "bob" }   // 値コピー → 伝わらない
func renameP(u *User) { u.Name = "bob" }   // ポインタ → 伝わる
```
詳細 → [../バックエンド/go/解説/go1.23.md](../バックエンド/go/解説/go1.23.md)（ポインタ）

### JavaScript / TypeScript：Java と同じモデル
オブジェクト/配列は参照。中身変更は伝わり、再代入は伝わらない。TypeScript は実行時には JS なので挙動は同じ（型は消える）。
```js
function rename(u){ u.name = "bob"; }      // ③ 伝わる
function replace(u){ u = { name: "bob" }; } // ② 伝わらない
function add(arr){ arr.push(4); }           // 配列は参照 → 伝わる
let a = 10; (x => x + 1)(a);                 // プリミティブはコピー → 元は10
```

### Dart / Kotlin：Java と同じモデル
Dart は「すべてオブジェクト」、Kotlin は JVM。どちらも中身変更は伝わり、再代入は伝わらない。List/Map（KotlinはMutableList等）は参照。
```dart
// Dart
void rename(User u) { u.name = "bob"; }    // ③ 伝わる
void add(List<int> xs) { xs.add(4); }      // 伝わる
```
```kotlin
// Kotlin（var プロパティ / MutableList）
fun rename(u: User) { u.name = "bob" }     // ③ 伝わる
fun add(xs: MutableList<Int>) { xs.add(4) } // 伝わる
```
※ Kotlin は `val`・データクラスの `copy()` で「変えない」設計が推奨されるため、③に頼らないコードが多い。

### Swift：値型は本当にコピー ★
`struct`/`enum`/`Array`/`Dictionary` は**値型**で、渡すと丸ごとコピー（中身変更も伝わらない）。`class` だけ参照型で伝わる。呼び出し元を変えたい時は `inout`。
```swift
func rename(_ u: inout User) { u.name = "bob" }  // inout で伝わる
```

### Rust：所有権と借用（独自モデル）★
既定は**ムーブ**（所有権が関数へ移り、呼び出し元はもう使えない）。読むだけなら `&`（不変借用）、変えたいなら `&mut`（可変借用）を**明示的に**渡す。コンパイラが借用規則を強制する。
```rust
fn read(u: &User)      { println!("{}", u.name); }    // & 不変借用：読むだけ
fn rename(u: &mut User){ u.name = "bob".into(); }      // &mut 可変借用：③ 伝わる
fn take(u: User)       { /* 所有権ごと受け取る＝ムーブ */ }

let mut u = User { name: "alice".into() };
rename(&mut u);   // 呼ぶ側も &mut を明示
read(&u);
// take(u);  の後は u をもう使えない（ムーブ済み）
```

## 言語ごとの「文字列」の例外
文字列が**不変(immutable)**か**可変(mutable)**かで、③が「起きるように見えるか」が変わる:
- **Java / Python / PHP / JavaScript / TypeScript / Dart / Kotlin / Swift / Go**：文字列は不変 → 中身を変えられず②しか起きない＝「変わらない」ように見える。
- **Ruby**：文字列は**可変** → `s << "!"` で中身変更＝③が起きる（呼び出し元にも伝わる）。
- **Rust**：`String` は可変だが、変えるには `&mut`（や所有権）が要る＝借用規則の範囲でのみ③。
```ruby
def bang(s) = s << "!"   # Ruby は文字列が可変 → 伝わる
x = "hi"; bang(x); puts x   # hi!
```

## つまずきの定番
- 「メソッドに渡して**再代入**したのに呼び出し元が変わらない」→ ②なので正常（住所を差し替えただけ）。
- 「**中身を変えただけ**なのに呼び出し元まで変わった（バグだと思った）」→ ③なので正常（同じ本体を共有）。意図せぬ共有を避けたいなら**コピーを作って渡す**（防御的コピー）。
- 「PHPで配列を関数に渡して変えたのに反映されない」→ PHP配列は値（コピー）。反映したいなら `&` か戻り値で返す。
- 「Goで構造体メソッドが状態を変えない」→ 値レシーバはコピー。ポインタレシーバにする。
