# ハンズオン：小さなアプリを Docker で動かす（build → run → compose）

> **このファイルの位置づけ**：他のファイル（[dockerfile.md](./dockerfile.md) / [compose.md](./compose.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- 自分の小さなアプリ（Node か Python）に **Dockerfile を書いて `docker build` でイメージにできる**
- `docker run -p` で起動して **`curl` で応答を確認できる**
- `docker compose` で **アプリ + DB の2コンテナを一括起動できる**
- `docker logs` / `docker exec` で **中の様子を確認できる**
- わざと **ポート競合 / CMD間違い / COPY漏れ を起こして、自分で直せる**
- ここまでやると [dockerfile.md](./dockerfile.md) / [compose.md](./compose.md) / [commands.md](./commands.md) が「読める」ようになる

**所要時間**：25〜35分　**前提**：Docker が動くこと（それ以外の知識は不要）

---

## 準備：Docker が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（または docker サービス）が起動していない。起動してから再実行。

作業用フォルダを作る:
```bash
mkdir -p ~/docker-handson && cd ~/docker-handson
```

> このハンズオンは **Node 版**で進めます（Python の人は各ステップ末尾の「Python 版」を使えば同じことができます）。

## ステップ1：小さなアプリを書く
**やること**：HTTP で1行返すだけのアプリを作る。
**なぜ**：Docker は「アプリを箱に詰める道具」。まず**詰める中身（アプリ）**を用意する。

```bash
cat > server.js <<'EOF'
const http = require('http');
const PORT = process.env.PORT || 3000;
http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello from Docker!\n');
}).listen(PORT, () => console.log(`listening on ${PORT}`));
EOF
```
**確認**（Docker なしで一応動くか。Node が入っていなければ飛ばしてOK）:
```bash
node server.js &   # バックグラウンドで起動
sleep 1
curl -s http://localhost:3000
kill %1            # 止める
```
**成功**：`Hello from Docker!` が返る。
**失敗**：`node: command not found` → ローカルに Node が無いだけ。問題なし。**この先は Docker の中の Node を使う**ので進めてよい。

> **Python 版**：`server.js` の代わりに下記を作る。以降 `node server.js` は `python3 app.py` に読み替え。
> ```bash
> cat > app.py <<'EOF'
> import os
> from http.server import BaseHTTPRequestHandler, HTTPServer
> PORT = int(os.environ.get('PORT', 3000))
> class H(BaseHTTPRequestHandler):
>     def do_GET(self):
>         self.send_response(200); self.end_headers()
>         self.wfile.write(b'Hello from Docker!\n')
> HTTPServer(('', PORT), H).serve_forever()
> EOF
> ```

## ステップ2：Dockerfile（作り方のレシピ）を書く
**やること**：「どの土台を使い、何をコピーし、起動時に何を実行するか」を書く。
**なぜ**：これがあると**誰がビルドしても同じイメージ**になる（→ [dockerfile.md](./dockerfile.md)）。

```bash
cat > Dockerfile <<'EOF'
# 土台：軽量なNode公式イメージ
FROM node:20-slim
# 以降の基準ディレクトリ
WORKDIR /app
# アプリ本体をイメージの中へコピー
COPY server.js ./
# このアプリが使うポート（宣言。公開ではない）
EXPOSE 3000
# 起動時に実行するコマンド（配列＝exec形式で書くのが定番）
CMD ["node", "server.js"]
EOF
```
- `FROM`＝土台イメージ、`WORKDIR`＝作業フォルダ、`COPY 左 右`＝ホスト→イメージへコピー、`CMD`＝既定の起動コマンド。

> **Python 版の Dockerfile**：`FROM python:3.12-slim` / `COPY app.py ./` / `CMD ["python", "app.py"]` に変える。

## ステップ3：`docker build` でイメージを焼く
**やること**：Dockerfile からイメージ（読み取り専用テンプレ）を作る。
**なぜ**：イメージは「配れる・どこでも同じに動く成果物」。run の元になる。

```bash
docker build -t myapp:1.0 .
```
- `-t myapp:1.0`＝イメージに名前(tag)を付ける、末尾の `.`＝Dockerfile があるフォルダ。

確認:
```bash
docker images | grep myapp
```
**成功**：`Successfully tagged myapp:1.0` が出て、`docker images` に `myapp 1.0` が並ぶ。
**失敗**：
- `Cannot locate ... server.js` / `COPY failed` → `server.js` が同じフォルダに無い。`ls` で確認。
- ネットワークで `FROM` の取得に失敗 → 回線確認後に再実行。

---

## ステップ4：`docker run -p` で起動して `curl` で確認
**やること**：イメージからコンテナ（実行中のインスタンス）を起動する。
**なぜ**：build しただけでは動かない。`run` で初めて動く。

```bash
docker run -d --name app -p 8080:3000 myapp:1.0
```
- `-d`＝バックグラウンド、`--name app`＝名前、`-p 8080:3000`＝PCの8080番をコンテナの3000番へ繋ぐ。

確認:
```bash
curl -s http://localhost:8080
```
**成功**：`Hello from Docker!` が返る。→ **自分のアプリが箱の中で動いた証拠**。
**失敗**：
- `port is already allocated` → 8080 が使用中。`docker rm -f app` の後、`-p 8081:3000` に変えて再実行（確認も 8081 に）。
- 何も返らない → `docker ps` で `app` が `Up` か確認。落ちていたら `docker logs app`。

---

## ステップ5：`docker logs` と `docker exec` で中を見る
**やること**：標準出力ログを見る／動いているコンテナの中に入る。
**なぜ**：障害時に**まず見るのがログ、次に中の状態**。ここで操作に慣れておく。

```bash
docker logs app                 # アプリの出力（listening on 3000 が見えるはず）
docker exec -it app sh          # コンテナの中に入る（shが開く）
```
中に入ったら:
```bash
ls                              # /app に server.js があるはず
cat server.js | head -3
exit                            # 出る
```
**成功**：`logs` に `listening on 3000`、中に `server.js` がある。
**失敗**：`exec` で `OCI runtime exec failed` → コンテナが起動していない。`docker ps` で確認。

いったん片付ける（次は compose で作り直す）:
```bash
docker rm -f app
```

## ステップ6：`docker compose` でアプリ + DB の2コンテナを起動（本題）
**やること**：アプリと PostgreSQL を1ファイルにまとめて一括起動する。
**なぜ**：実アプリは単体で完結しない（Web＋DB…）。compose は**起動構成をコード化**して `up` 一発で再現する（→ [compose.md](./compose.md)）。

`compose.yaml` を書く:
```bash
cat > compose.yaml <<'EOF'
services:
  app:
    build: .                       # カレントの Dockerfile からビルド
    ports:
      - "8080:3000"                # ホスト8080 → コンテナ3000
    environment:
      - DATABASE_URL=postgres://app:secret@db:5432/appdb  # "db" はサービス名
    depends_on:
      db:
        condition: service_healthy # db が healthy になってから app 起動
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: appdb
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      timeout: 3s
      retries: 5
EOF
```
- `app` から DB への接続先は `localhost` ではなく **サービス名 `db`**（同じネットワーク内で名前解決できる）。
- `depends_on` + `condition: service_healthy` で「DB が受付可能になってから app を起動」する。

起動:
```bash
docker compose up -d --build
```
状態とログ:
```bash
docker compose ps                 # app と db が両方 Up / healthy
docker compose logs db | tail -5  # DBの起動ログ
```
アプリ確認:
```bash
curl -s http://localhost:8080
```
**成功**：
- `docker compose ps` で `app`（Up）と `db`（Up, healthy）が並ぶ。
- `curl` で `Hello from Docker!`。→ **2コンテナが連動して立ち上がった**。
**失敗**：
- `app` が `db` を待たずに落ちる → `depends_on` の `condition: service_healthy` が抜けていないか確認。
- `port is already allocated` → ステップ4の `app` が残っている。`docker rm -f app`。

DB に入って動作確認（exec をサービス名で）:
```bash
docker compose exec db psql -U app -d appdb -c "SELECT 1;"
```
**成功**：`?column?` の下に `1` が1行返る。→ DB も生きている。

## ステップ7：わざと壊して直す（3連発）
**なぜ**：build/run の失敗は実務で必ず出会う。**自分で起こして直す**と一生忘れない。

### 壊し方A：ポート競合（`port is already allocated`）
今 compose の app が 8080 を使っている。同じポートでもう1つ起動してぶつける:
```bash
docker run -d --name app2 -p 8080:3000 myapp:1.0
```
**症状**：`Bind for 0.0.0.0:8080 failed: port is already allocated`。
**原因**：ホストの 8080 は1プロセスしか使えない。すでに compose の app が占有している。
**直す**：別ポートにするか、競合相手を止める。
```bash
docker run -d --name app2 -p 8081:3000 myapp:1.0   # 別ポートなら成功
curl -s http://localhost:8081
docker rm -f app2                                   # 後片付け
```
> 実務の `port is already allocated` も原因は同じ。→ [compose.md](./compose.md#ハマりどころ--アンチパターン) / [pitfalls.md](./pitfalls.md)

### 壊し方B：CMD の書き間違い（コンテナが即終了）
存在しないファイルを起動するイメージを作って動かす:
```bash
cat > Dockerfile.bad <<'EOF'
FROM node:20-slim
WORKDIR /app
COPY server.js ./
CMD ["node", "serverr.js"]
EOF
docker build -t myapp:bad -f Dockerfile.bad .
docker run -d --name bad myapp:bad
docker ps -a | grep bad
```
**症状**：`docker ps` には出ず、`docker ps -a` で `Exited (1)`（すぐ落ちている）。
**確認コマンド**：
```bash
docker logs bad
```
→ `Cannot find module '/app/serverr.js'`。
**原因**：`CMD` のファイル名 typo（`serverr.js`）。コンテナは CMD が終わると終了する。
**直す**：`server.js` に直して焼き直す。
```bash
docker rm -f bad
# Dockerfile.bad の serverr.js を server.js に直してもよいが、正しい myapp:1.0 を使えば済む
docker run -d --name good -p 8082:3000 myapp:1.0
curl -s http://localhost:8082
docker rm -f good
```
> 「起動した直後に Exited」を見たら、まず `docker logs`。→ [commands.md](./commands.md) / [pitfalls.md](./pitfalls.md)

### 壊し方C：COPY 漏れ（イメージにファイルが入っていない）
`server.js` をコピーし忘れた Dockerfile を作る:
```bash
cat > Dockerfile.nocopy <<'EOF'
FROM node:20-slim
WORKDIR /app
# COPY server.js ./   ← わざと COPY を書かない
CMD ["node", "server.js"]
EOF
docker build -t myapp:nocopy -f Dockerfile.nocopy .
docker run -d --name nocopy myapp:nocopy
docker logs nocopy
```
**症状**：`Cannot find module '/app/server.js'`（B と似ているが原因が違う）。
**切り分け**：本当にイメージの中に無いのか、`exec` で確認する。
```bash
docker run --rm myapp:nocopy ls -la /app
```
→ `/app` が空（`server.js` が無い）。**ファイル名は合っているのに無い → COPY 漏れ**と確定。
**直す**：Dockerfile に `COPY server.js ./` を戻して焼き直す。
```bash
docker rm -f nocopy
docker build -t myapp:1.0 .          # COPY のある正しい Dockerfile で焼き直し
docker run --rm myapp:1.0 ls /app    # server.js が見えれば直った
```
> B（CMD の typo）と C（COPY 漏れ）は症状がそっくりだが、**`ls /app` で中身を見れば区別できる**。

## 片付け
```bash
docker compose down               # app/db を停止・削除（ネットワークも消える）
docker rm -f app2 bad good nocopy 2>/dev/null   # 残骸があれば消す
docker rmi myapp:bad myapp:nocopy 2>/dev/null   # 練習用イメージを消す
# フォルダごと消すなら: rm -rf ~/docker-handson
```
