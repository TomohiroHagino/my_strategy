# ハンズオン：nginx をアプリの前段に置いて動かす

> **このファイルの位置づけ**：他のファイル（[nginx.md](./nginx.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- nginx を起動して、**自分のHTMLが表示される**
- `/api/` へのアクセスを**裏のアプリへ転送（リバースプロキシ）できる**
- わざと **502 を起こして、自分で直せる**
- ここまでやると [nginx.md](./nginx.md) / [リバースプロキシ.md](./リバースプロキシ.md) が「読める」ようになる

**所要時間**：15〜20分　**前提**：Docker が動くこと（それ以外の知識は不要）

---

## 準備：Docker が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（またはdockerサービス）が起動していない。起動してから再実行。

作業用フォルダを作る:
```bash
mkdir -p ~/nginx-handson/html && cd ~/nginx-handson
```

---

## ステップ1：とりあえず nginx を起動して表示を見る
**やること**：公式nginxイメージをそのまま起動する。
**なぜ**：まず「nginxはWebサーバ＝ブラウザにページを返すもの」を目で見るため。
```bash
docker run -d --name web -p 8080:80 nginx:alpine
```
- `-d`＝バックグラウンド実行、`-p 8080:80`＝PCの8080番をコンテナの80番に繋ぐ、`--name web`＝名前を付ける。

ブラウザで **http://localhost:8080** を開く（or 下記）:
```bash
curl -s http://localhost:8080 | head -5
```
**成功**：`<title>Welcome to nginx!</title>` を含むHTMLが返る。
**失敗**：
- `port is already allocated` → 8080が使用中。`-p 8081:80` に変えて再実行。
- 何も返らない → `docker ps` で `web` が動いているか確認。

いったん消す（次で設定を変えて作り直すため）:
```bash
docker rm -f web
```

---

## ステップ2：自分のHTMLを配信する
**やること**：自分で書いたHTMLをnginxに返させる。
**なぜ**：nginxの一番基本の仕事＝「静的ファイル配信」を体験する。

HTMLを作る:
```bash
cat > html/index.html <<'EOF'
<!doctype html>
<h1>これは自分のページ</h1>
<p><a href="/api/">/api/ を見る</a></p>
EOF
```
自分のHTMLフォルダを nginx に渡して起動:
```bash
docker run -d --name web -p 8080:80 \
  -v "$PWD/html:/usr/share/nginx/html:ro" \
  nginx:alpine
```
- `-v 左:右`＝PCのフォルダをコンテナ内の場所に「マウント（貸す）」。`:ro`＝読み取り専用。
- `/usr/share/nginx/html` は nginx が既定で配信するフォルダ。

確認:
```bash
curl -s http://localhost:8080
```
**成功**：`これは自分のページ` が返る（Welcomeページが置き換わった）。
**失敗**：まだWelcomeが出る → マウントパスのtypo。`$PWD` が `~/nginx-handson` か `pwd` で確認。

```bash
docker rm -f web
```

## ステップ3：裏にアプリを置いて `/api/` を転送する（本題）
**やること**：「アプリ役」のコンテナを立て、nginx が `/api/` だけそのアプリへ取り次ぐ。
**なぜ**：これが**リバースプロキシ**＝実務でnginxを置く一番の理由。

### 3-1. ネットワークとアプリを用意
```bash
docker network create handson
docker run -d --name api --network handson traefik/whoami
```
- `traefik/whoami` は「受け取ったリクエストの中身を返すだけ」の確認用アプリ（80番で待受）。
- `docker network` は「コンテナ同士が名前で通信できる仮想ネットワーク」。これで nginx から `api` という名前でアクセスできる。

### 3-2. nginx の設定を書く
```bash
cat > nginx.conf <<'EOF'
events {}
http {
  server {
    listen 80;

    # /api/ は裏の api コンテナへ転送
    location /api/ {
      proxy_pass http://api:80/;
      proxy_set_header Host            $host;
      proxy_set_header X-Real-IP       $remote_addr;
      proxy_set_header X-Forwarded-For $remote_addr;
    }

    # それ以外は自分のHTML
    location / {
      root /usr/share/nginx/html;
    }
  }
}
EOF
```
- `location /api/ { proxy_pass http://api:80/; }` ＝「`/api/` で来たら `api` コンテナに渡せ」。
- `proxy_set_header X-Forwarded-For` ＝裏のアプリに「本当の接続元はこのIPだよ」と伝える（無いとアプリ側はnginxのIPしか分からない）。

### 3-3. nginx を設定ごと起動
```bash
docker run -d --name web --network handson -p 8080:80 \
  -v "$PWD/html:/usr/share/nginx/html:ro" \
  -v "$PWD/nginx.conf:/etc/nginx/nginx.conf:ro" \
  nginx:alpine
```
**重要**：`--network handson` を付けること（付け忘れると nginx は `api` を見つけられない）。

### 3-4. 確認
```bash
curl -s http://localhost:8080/        # 自分のHTML
curl -s http://localhost:8080/api/    # 裏のアプリの応答
```
**成功**：
- `/` → `これは自分のページ`
- `/api/` → `Hostname: ...` `IP: ...` `X-Forwarded-For: ...` など whoami の出力。
  → **これが「nginxが裏のアプリへ取り次いだ」証拠**。`X-Forwarded-For` にあなたのIPが見えるはず。
**失敗**：
- `/api/` が **502 Bad Gateway** → 次のステップで扱う（むしろ好都合）。

## ステップ4：わざと 502 を起こして、直す
**なぜ**：502は実務で必ず出会うエラー。「自分で起こして直す」と一生忘れない。

裏のアプリを止める:
```bash
docker stop api
curl -i http://localhost:8080/api/   # もう一度アクセス
```
**結果**：`HTTP/1.1 502 Bad Gateway` が返る。
nginx のエラーログを見る:
```bash
docker logs web | tail -3
```
→ `connect() failed (111: Connection refused) while connecting to upstream` のような行が出る。
**読み解き**：`upstream`（＝裏のアプリ `api`）に繋げなかった、という意味。**502は「nginxは生きているが、裏が応答しない」**を表す。

直す（アプリを起こす）:
```bash
docker start api
sleep 1
curl -s http://localhost:8080/api/   # 復活
```
**成功**：また whoami の出力が返る。→ 502の原因＝裏のアプリ、を体験で理解できた。

> 実務の502も原因は同じ系統：アプリが落ちている／ポート違い／ソケットのパス違い。切り分けの起点になる。→ [リバースプロキシ.md](./リバースプロキシ.md#gateway系エラーの意味)

## 次のステップ（やってみると伸びる）
- `proxy_pass http://api:80/;` の **末尾 `/` を消して** `curl /api/` がどう変わるか試す → [nginx.md](./nginx.md) の「proxy_passの末尾スラッシュ」が腹落ちする。
- `location /api/` を `location = /api` に変えて挙動の違いを見る → location判定の理解。
- HTMLを増やして `try_files` を足す → SPA配信の体験。
