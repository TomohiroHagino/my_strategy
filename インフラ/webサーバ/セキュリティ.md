# セキュリティ（Webサーバの防御設定）（Webサーバ）

## ひとことで言うと
Webサーバ前段で行う防御設定一式。**TLSの適正化・セキュリティヘッダ・レート制限・アクセス制御・情報隠蔽**を担う。アプリ側の対策と二重で効かせる「最初の壁」。

## 役割・なぜ必要か
- 前段で弾けるもの（不正メソッド・大量リクエスト・隠しファイルへのアクセス）はアプリに届く前に止める方が安全・軽量。
- TLSやセキュリティヘッダは設定漏れが直接脆弱性になるため、Webサーバ層で一元管理する。

## TLS設定の実務
```nginx
ssl_protocols TLSv1.2 TLSv1.3;          # SSLv3/TLS1.0/1.1は無効（脆弱）
ssl_ciphers   'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:...';
ssl_prefer_server_ciphers off;          # TLS1.3ではクライアント選好で可
ssl_session_cache shared:SSL:10m;       # ハンドシェイク削減
ssl_session_timeout 1d;
ssl_stapling on;                        # OCSP Stapling（証明書失効確認を高速化）
ssl_stapling_verify on;
```
- 暗号スイートは手書きせず **Mozilla SSL Configuration Generator** の "Intermediate" を使うのが安全・最新。
- 証明書は **Let's Encrypt（certbot）** で取得・自動更新（`certbot renew` をcron/systemd timer）。
```nginx
# HTTP→HTTPS 強制 ＋ HSTS（以後HTTPSのみで接続させる）
server { listen 80; server_name example.com; return 301 https://$host$request_uri; }
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
```

## セキュリティヘッダ
| ヘッダ | 目的 | 例 |
|---|---|---|
| `Strict-Transport-Security` | 常時HTTPS強制 | `max-age=31536000; includeSubDomains` |
| `X-Content-Type-Options` | MIMEスニッフィング防止 | `nosniff` |
| `X-Frame-Options` | クリックジャッキング防止 | `DENY` / `SAMEORIGIN` |
| `Content-Security-Policy` | XSS緩和（読み込み元制限） | `default-src 'self'` |
| `Referrer-Policy` | リファラ漏れ抑制 | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | 機能(カメラ等)制限 | `camera=(), geolocation=()` |
```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: https:;" always;
```
- **`always` を付ける**：付けないとエラー応答（4xx/5xx）にヘッダが乗らない。
- CSPはアプリの実情に合わせる（フロントのCSPと整合）。→ [../../フロントエンド/](../../フロントエンド/)

## レート制限・DoS緩和
```nginx
# httpコンテキスト：IPごとに毎秒10リクエストのゾーンを定義
limit_req_zone  $binary_remote_addr zone=api:10m rate=10r/s;
limit_conn_zone $binary_remote_addr zone=conns:10m;

location /api/ {
    limit_req  zone=api burst=20 nodelay;   # 瞬間的に20まで許容、超過は429
    limit_conn conns 10;                     # 同時接続を10まで
    proxy_pass http://app;
}
# Slowloris対策（だらだら送る接続を切る）
client_body_timeout   10s;
client_header_timeout 10s;
```
- `burst`＝瞬間的な許容量、`nodelay`＝バースト分を遅延なく通す。超過は **429 Too Many Requests**。

## アクセス制御
```nginx
# 管理画面をIP制限＋Basic認証
location /admin/ {
    allow 203.0.113.0/24;
    deny  all;
    auth_basic "restricted";
    auth_basic_user_file /etc/nginx/.htpasswd;   # htpasswd -c で作成
    proxy_pass http://app;
}
```
- 細かい条件分岐は `geo` / `map` で変数化して使う。

## 情報隠蔽・ハードニング
```nginx
server_tokens off;                       # Server: nginx のバージョンを隠す
autoindex off;                           # ディレクトリ一覧を出さない

# 隠しファイル(.git/.env/.htaccess)へのアクセスを遮断（.well-knownは許可）
location ~ /\.(?!well-known) { deny all; }

# 不要メソッドを拒否
if ($request_method !~ ^(GET|POST|PUT|DELETE|PATCH|OPTIONS|HEAD)$) { return 405; }
```
- **`.env` をWebルートに置かない**こと自体が大前提（置くと直URLで漏洩）。→ [../../バックエンド/](../../バックエンド/)

## WAF
- **ModSecurity**：Apache(mod_security)/nginx で動くWAF。OWASP CRS（コアルールセット）で既知攻撃をブロック。
- **クラウドWAF**：AWS WAF / Cloudflare / GCP Cloud Armor。前段で広域に守れる。→ [../aws/](../aws/)
- 自前 vs マネージドは運用コストで選ぶ。小規模はクラウドWAFが手軽。

## 実務での使い方・定番パターン
- **TLSはプロキシで終端**し、裏へ `X-Forwarded-Proto https` を伝える（リダイレクトループ防止）。→ [リバースプロキシ.md](./リバースプロキシ.md)
- **本物IPでレート制限**：前段にALB/CDNがあると `$binary_remote_addr` がプロキシIPになり全体が1つ扱いに。`real_ip` で復元してから制限。
- **ヘッダ・TLSはテンプレ化**：`include /etc/nginx/snippets/security-headers.conf;` で全serverに共通適用。
- 設定後は **SSL Labs / securityheaders.com** 等でスコア確認。

## ハマりどころ / アンチパターン
- **`add_header` が継承されず消える**：`location` 内で別の `add_header` を書くと親の分が消える。各所で再宣言 or `always`＋snippet共通化。
- **HSTSを安易に入れる**：`max-age` が長いとブラウザがHTTPSを強制キャッシュし、HTTPに戻せない。段階的に延ばす。
- **mixed content**：HTTPSページからHTTPリソース読込でブロック。すべてHTTPS化。
- **`.env`/`.git` 露出**：Webルート配置＋遮断設定漏れで丸見え。配置とlocation遮断を両方。
- **レート制限のゾーン不足**：`zone=...:10m` が小さいとメモリ不足で制限が効かない/エラー。
- **プロキシ下で本物IPに制限がかからない**：`X-Forwarded-For`/`real_ip` 未設定だと全リクエストが同一IP扱い。
- **server_tokens on のまま**：バージョンが見え、既知脆弱性を狙われやすい。
