# 初動対応（Triage・エスカレーション）（障害対応）

## ひとことで言うと
アラートを受けてから最初の数分で、**「どれだけヤバいか（SEV判定）」「誰を呼ぶか（招集）」「誰に伝えるか（連絡）」「何を記録するか（記録開始）」**を一気に固める動き。原因究明より先に、被害を止める体制を作るフェーズ。

## 役割・なぜ必要か
- 障害発生直後は情報が少なく混乱する。**最初の動きを型化**しておかないと、原因調査に飛びついて連絡・記録が抜け、被害が広がる。
- **止血優先**：ユーザーが困っている時間を1秒でも短くするのが目的。「なぜ壊れたか」は後回しでよい。
- **指揮系統を1本化**（インシデント指揮官＝IC）：複数人がバラバラに触ると二次災害になる。誰が舵を取るかを最初に決める。

## 基本（手順・考え方）

### 最初の5分でやること（順番）
```
1. 受信・確認 ：アラートが本物か。誤報か実害か。1分で「本物」と判断したら次へ
2. 影響範囲   ：誰が・何が・どれくらい困っているか（全体か一部か / お金・データに影響か）
3. SEV判定    ：影響範囲から重大度を決める（下表）。迷ったら高めに
4. 招集       ：SEVに応じてIC・対応者を呼ぶ。1人で抱えない
5. 連絡       ：ステークホルダー（社内/顧客/ステータスページ）へ第一報
6. 記録開始   ：専用チャンネル/ドキュメントを切り、時刻つきで全行動を残す
```

### 重大度（SEV）の定義表
| SEV | 状態 | 判定の目安 | 招集・連絡 |
|---|---|---|---|
| **SEV1** | 全停止・データ損失・情報漏洩 | サービス全断、決済不能、個人情報流出 | IC即招集＋経営＋顧客＋ステータスページ |
| **SEV2** | 主要機能の重大障害 | ログイン不可、主要APIのエラー率が急騰 | IC招集＋関係チーム＋顧客連絡 |
| **SEV3** | 一部機能・回避策あり | 一部画面のみ不調、軽い性能劣化 | 担当者で対応・社内共有 |
| **SEV4** | 軽微・ユーザー影響ほぼなし | 内部ツール不調、ログの軽微な異常 | バックログ化 |

> 判定の核：**「顧客に見えているか」「お金/データに触るか」**。両方Yesなら最低SEV2。

### インシデント指揮官（IC）の役割
- 手を動かす人ではなく**全体を仕切る人**。判断・役割分担・連絡の交通整理に専念する。
- 主な配下ロール：**実作業担当（Ops）**／**連絡担当（Comms：社内外への発信）**／**記録担当（Scribe：タイムライン記録）**。小規模なら兼任可。
- ICが決めること：「今の最優先は止血か調査か」「ロールバックするか」「誰を追加で呼ぶか」「次の連絡は何分後か」。

## 実務での使い方・定番パターン
- **専用チャンネルを即作成**：`#incident-2026-0612-login` のように切り、関係者を集めて会話と記録を一元化。DMで進めない（履歴が散る）。
- **第一報のテンプレ**（詳細不要、5分以内に出す）：
  ```
  【障害発生 SEV2】ログイン不可
  発生時刻: 14:32頃 / 影響: 全ユーザーのログイン
  状況: 調査中。IC: @taro / 次報: 15分後
  ```
- **タイムラインは「気づいたこと全部・時刻つき」**で記録担当が残す。後のポストモーテムの一次資料になる。
  ```
  14:32 アラート受信（5xxエラー率 急騰）
  14:35 SEV2判定、ICを@taroに
  14:38 14:20のデプロイが疑わしいと判断
  14:41 ロールバック開始
  14:46 エラー率 正常化、復旧確認
  ```
- **「沈黙させない」連絡リズム**：SEV1/2では**15分ごと**に進捗を出す（進展がなくても「調査継続中」と出す）。沈黙は不安と問い合わせを生む。
- **ステータスページ**（Statuspage等）：顧客向けに「障害発生中／復旧作業中／復旧済み」を機械的に更新。問い合わせ殺到を防ぐ。→ [チェックリストとランブック.md](./チェックリストとランブック.md)

## ハマりどころ / アンチパターン
- **いきなり原因調査に没頭**：連絡・記録を飛ばして1人でログに潜る → 周りが状況を把握できず、被害も止まらない。**まず体制と止血**。
- **SEVを低く見積もる**：「たぶん一部だろう」で放置 → 実は全断だった。迷ったら**高めに倒す**。下げるのは後でできる。
- **指揮系統がない（全員が船頭）**：複数人が同時にコマンドを叩き、設定を上書きし合って二次災害。**ICを必ず1人立てる**。
- **記録を後回し**：「落ち着いたら書く」→ 時系列が曖昧になり再発防止が薄くなる。**リアルタイムで時刻つき**に残す。
- **アラート疲れ（狼少年）で本物を見逃す**：誤報を放置すると本物に鈍感になる。アラートは定期的に精査し、誤報は仕組みで減らす。→ [ログと監視.md](./ログと監視.md)
- **連絡の沈黙**：進捗を出さないと顧客と社内から問い合わせが殺到し、対応リソースを奪う。**定時連絡を約束して守る**。
