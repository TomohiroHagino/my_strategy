# 対応判断フロー（どういうときに何をするか）（障害対応）

## ひとことで言うと
切り分けで「どこが・なぜ」が見えたら、**状況別に「まず何をするか（止血）」を即決める**ための判断フロー。原則は **「止血を最優先、根本対処は後」**。迷ったら下のフローと早見表で決める。

## 大原則（最初に決める2つ）
1. **直近に変更したか？** → **Yes なら、まず戻す（rollback / revert / フラグ off）**。原因究明より速い。
2. 変更が無い / 戻しても直らない → **切り分け（範囲・症状・時間・飽和）で原因タイプを特定 → タイプ別の止血**。→ [切り分け.md](./切り分け.md)

## 意思決定フロー
```
障害発生
  │
  ├─ 直近30分〜数h に デプロイ/設定/インフラ変更 があった？
  │     ├─ Yes → ★まず rollback / revert / フィーチャーフラグ off（止血）
  │     │          └─ 直った → 収束宣言 → 原因究明＆ポストモーテム
  │     └─ No  → 切り分けで原因タイプを特定
  │                 │
  │                 ▼ タイプ別の止血（下の早見表）
  │
  └─ 影響大（SEV1/2）なら、止血と並行して エスカレ＆ステークホルダー連絡 → [初動対応.md](./初動対応.md)
```

## 状況 → 取るアクション（止血 → 根本）早見表
| 切り分けで分かった状況 | まずやる（止血・即） | 根本対処（あとで） |
|---|---|---|
| **直近デプロイが原因** | **ロールバック** | バグ修正・テスト追加・カナリアデプロイ |
| 設定変更が原因 | 設定を戻す | 設定の検証・IaC化・レビュー必須化 |
| 特定機能のバグ | **フィーチャーフラグで off** / revert | 修正して再リリース |
| CPU 100%（暴走/スロークエリ） | 暴走プロセス/クエリを kill・スケールアウト | クエリ最適化・インデックス・無限ループ修正 |
| メモリ枯渇 / OOM | 再起動・メモリ増強 | リーク修正・ヒープ上限調整 |
| ディスクフル | 不要ファイル削除・ボリューム拡張 | ログローテ・保持期間設定・監視 |
| **DBコネクション枯渇** | 滞留接続を kill・プール上限調整 | close漏れ修正・プール設計見直し |
| スロークエリ / N+1 | 重いクエリ kill・該当機能を一時 off | インデックス・JOIN化・キャッシュ |
| **証明書期限切れ** | 証明書を更新・再発行 | 自動更新(certbot)＋期限監視 |
| DNS設定ミス | レコード修正 or 旧向き先へ戻す | 変更手順・TTL設計・確認フロー |
| 外部API依存ダウン | タイムアウト短縮・フォールバック・キャッシュ | サーキットブレーカー・依存削減 |
| **カスケード障害** | 最初に倒れた所を止血・リトライ抑制・CB作動 | タイムアウト/リトライ上限/隔離設計 |
| トラフィックスパイク | スケールアウト・レート制限・CDN・異常元を遮断 | オートスケール調整・キャパシティ計画 |
| 特定1台のみ異常 | その1台を LB から外す・入れ替え | プロビジョニング差分の解消 |
| 特定AZ障害 | 別AZへ寄せる・フェイルオーバー | マルチAZ/リージョン設計 |

→ 各止血手段の具体コマンドは [復旧手順.md](./復旧手順.md)、症状からの逆引きは [よくある障害パターン.md](./よくある障害パターン.md)。

## 迷ったときの優先順位
1. **人命・データ損失・お金に関わるか？**（決済・個人情報・不可逆操作）→ 最優先で止める
2. **影響は広いか？（SEV）** → 広いほど「完璧な原因究明」より「素早い止血」を選ぶ
3. **戻せる変更があるか？** → あれば戻す（一番速くて安全な止血）
4. **観測は非破壊・変更は最小で1つずつ**（効果を確認できる単位で打つ）

## ハマりどころ / アンチパターン
- **原因究明を優先して止血が遅れる**：ユーザーが困っている間は、まず止める。原因は戻してから掘る。
- **複数の止血を同時に打つ**：何が効いたか分からず、再発防止もできない。1つ打って効果確認。
- **止血で満足して根本対処を放置**：再起動・flag off は一時しのぎ。必ずポストモーテムでアクション化。→ [ポストモーテム.md](./ポストモーテム.md)
- **「直近変更なし」と思い込む**：自分のデプロイ以外（他チーム・cron・証明書失効・外部API・データ増加）も「変更」。
- **止血と原因究明を1人で抱える**：指揮（IC）・作業・連絡を分担する。→ [初動対応.md](./初動対応.md)
