# ハンズオン：LocalStack で AWS を「課金ゼロ」で触る

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [s3.md](./s3.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## 💰 課金に関する注意（最初に必ず読む）
- **この実習は課金ゼロで完結します。** 本物のAWS（あなたのアカウント・クレジットカード）には一切アクセスしません。
- 使うのは **LocalStack** ＝ AWSの主要サービスを**自分のPCの中で再現するエミュレータ**。S3もLambdaもDynamoDBも、PC上の偽AWSに対して作ります。請求は発生しません。
- 本物のAWSとの違い（IAM / リージョン / 課金）は末尾「本物のAWSでやる場合の差分」に短くまとめます。
- それでも最後は **必ず片付け**（コンテナ削除）まで行ってください。下記「必ず片付ける」章を実行すれば完全に消えます。

## ゴール（終わったら何ができる？）
- LocalStack を起動して、**本物そっくりの `aws` コマンド（`awslocal`）でAWSを操作できる**
- **S3バケットを作り、ファイルをput/getできる**
- **DynamoDBテーブルを作り、データを書いて読める**
- わざと **存在しないバケットにアクセスして失敗 → 自分で直せる**
- ここまでやると [s3.md](./s3.md) / [dynamodb.md](./dynamodb.md) / [getting_started.md](./getting_started.md) が「読める」ようになる

**所要時間**：15〜25分　**前提**：Docker と Python（pip）が動くこと（それ以外の知識は不要）

---

## 準備：Docker と pip が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（またはdockerサービス）が起動していない。起動してから再実行。

```bash
python3 -m pip --version
```
**成功**：`pip XX.X from ...` が出る。
**失敗**：`No module named pip` → `python3 -m ensurepip --upgrade` を実行、または OS のパッケージで `python3-pip` を入れる。

作業用フォルダを作る:
```bash
mkdir -p ~/aws-handson && cd ~/aws-handson
```

---

## ステップ1：LocalStack を起動する
**やること**：`localstack/localstack` イメージをdockerで起動する。
**なぜ**：これが「自分のPCの中の偽AWS」。ここに対してS3やDynamoDBを作るので、本物に触れず課金もされない。
```bash
docker run -d --name localstack -p 4566:4566 localstack/localstack
```
- `-d`＝バックグラウンド実行、`-p 4566:4566`＝LocalStackの入口（全AWSサービス共通で 4566番）をPCに繋ぐ、`--name localstack`＝名前を付ける。

起動を確認（数秒待ってから）:
```bash
sleep 8
curl -s http://localhost:4566/_localstack/health
```
**成功**：`{"services": {...}, ...}` というJSONが返る（`"s3": "available"` 等が並ぶ）。
**失敗**：
- 何も返らない / 接続拒否 → まだ起動中。あと10秒待って再実行。`docker logs localstack | tail -5` に `Ready.` が出れば準備完了。
- `port is already allocated` → 4566が使用中。`docker rm -f localstack` してから、`-p 4567:4566` に変えて起動し直し、以降の `4566` を `4567` に読み替える。

---

## ステップ2：`awslocal`（課金ゼロ版のawsコマンド）を入れる
**やること**：`awscli-local` を入れて、`awslocal` コマンドを使えるようにする。
**なぜ**：本物の `aws` コマンドは初期設定（アクセスキー）が必要で、設定を間違えると本物に飛ぶ恐れがある。`awslocal` は **自動でLocalStack（localhost:4566）に向く** ラッパー。これを使えば事故が起きない。
```bash
python3 -m pip install --user awscli-local
```
- `awscli-local` は内部で `awscli` も入れる。`awslocal` は「`aws --endpoint-url=http://localhost:4566` を毎回打つ手間」を省くだけのもの。

確認:
```bash
awslocal --version
```
**成功**：`aws-cli/2.x ...` のようなバージョンが出る。
**失敗**：
- `command not found: awslocal` → インストール先の `~/.local/bin` にPATHが通っていない。`export PATH="$HOME/.local/bin:$PATH"` を実行してから再確認。
- それでも出ない → `python3 -m awscli_local --version` でも代用可（ただし以降は `awslocal` を使う前提）。

## ステップ3：S3バケットを作って、ファイルをput/getする（本題その1）
**やること**：偽AWS上にS3バケットを作り、ファイルを置いて、取り出す。
**なぜ**：S3＝AWSで最も使うストレージ。「バケットを作る→キーでファイルを置く→取り出す」がS3の全ての基本。

### 3-1. バケットを作る
```bash
awslocal s3 mb s3://handson-bucket
```
- `mb`＝make bucket（バケット作成）。`s3://handson-bucket` がバケット名。

**成功**：`make_bucket: handson-bucket` と返る。
**失敗**：`Could not connect to the endpoint URL` → LocalStackが起動していない。ステップ1のhealth確認に戻る。

バケット一覧で確認:
```bash
awslocal s3 ls
```
**成功**：`handson-bucket` を含む行が出る。

### 3-2. ファイルを置く（put）
```bash
echo "hello localstack $(date)" > sample.txt
awslocal s3 cp sample.txt s3://handson-bucket/sample.txt
```
- `cp 左 右`＝コピー。ローカルの `sample.txt` を、バケット内のキー `sample.txt` として置く。

**成功**：`upload: ./sample.txt to s3://handson-bucket/sample.txt` と返る。

バケットの中身を確認:
```bash
awslocal s3 ls s3://handson-bucket/
```
**成功**：`sample.txt` が一覧に出る。

### 3-3. 取り出す（get）
```bash
awslocal s3 cp s3://handson-bucket/sample.txt downloaded.txt
cat downloaded.txt
```
**成功**：`hello localstack ...`（さっき書いた内容）が表示される。
→ **これが「S3に置いたファイルを取り戻した」証拠**。本物のAWSでも全く同じコマンドで動く（向き先が違うだけ）。

---

## ステップ4：DynamoDB テーブルを作って、書いて読む（本題その2）
**やること**：偽AWS上にDynamoDBテーブルを作り、1件書いて、読み出す。
**なぜ**：DynamoDB＝AWSの代表的NoSQL。「テーブルを作る→キー付きでアイテムを入れる→キーで引く」を体験する。

### 4-1. テーブルを作る
```bash
awslocal dynamodb create-table \
  --table-name handson-users \
  --attribute-definitions AttributeName=userId,AttributeType=S \
  --key-schema AttributeName=userId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
```
- `--attribute-definitions`＝キーに使う属性 `userId` は文字列（`S`=String）。
- `--key-schema`＝`userId` をパーティションキー（`HASH`）にする＝この値でアイテムを一意に引く。
- `--billing-mode PAY_PER_REQUEST`＝従量モード指定（LocalStackでは課金なし。本物でも初心者はこれが安全）。

**成功**：JSONが返り、中に `"TableStatus": "ACTIVE"`（または `CREATING`）が見える。
**失敗**：`Table already exists` → 既に作成済み。次へ進んでよい。

テーブル一覧で確認:
```bash
awslocal dynamodb list-tables
```
**成功**：`"handson-users"` が一覧に出る。

### 4-2. アイテムを1件書く（put）
```bash
awslocal dynamodb put-item \
  --table-name handson-users \
  --item '{"userId": {"S": "u001"}, "name": {"S": "Taro"}}'
```
- DynamoDBの値は `{"S": "文字列"}` のように **型を明示**する（`S`=文字列）。これがDynamoDBの書式の特徴。

**成功**：エラーなく、何も表示されずにプロンプトが戻る（put-itemは成功時に出力なし）。

### 4-3. キーで読む（get）
```bash
awslocal dynamodb get-item \
  --table-name handson-users \
  --key '{"userId": {"S": "u001"}}'
```
**成功**：`{"Item": {"userId": {"S": "u001"}, "name": {"S": "Taro"}}}` が返る。
→ **これが「キーでアイテムを引けた」証拠**。NoSQLの基本動作を体験できた。

## ステップ5：わざと失敗させて、直す
**なぜ**：実務で必ず出会う「名前の打ち間違い」を、安全な場所で起こして直すと一生忘れない。

存在しないバケットを覗いてみる:
```bash
awslocal s3 ls s3://handson-bucketX/
```
**結果**：`An error occurred (NoSuchBucket) ... The specified bucket does not exist` というエラーが返る。
**読み解き**：`NoSuchBucket`＝「そんなバケット無い」。本物のAWSでもこのエラーは頻出で、ほぼ**名前のtypo**か**リージョン違い**が原因。

正しい名前でやり直す:
```bash
awslocal s3 ls s3://handson-bucket/
```
**成功**：`sample.txt` が出る。→ 原因＝名前の不一致、を体験で理解できた。

> 本物のAWSでは、同じ `NoSuchBucket` でも「実は別リージョンに作っていた」が原因のこともある。切り分けの起点になる。→ [s3.md](./s3.md) / [pitfalls.md](./pitfalls.md)

## 必ず片付ける（このまま閉じない）
**LocalStackはPC内なので課金は発生しませんが、コンテナが残り続けるとメモリを使います。** 必ず消しましょう。
```bash
# LocalStackコンテナを止めて削除（中のS3/DynamoDBもまるごと消える）
docker rm -f localstack

# 作業フォルダごと消すなら
rm -rf ~/aws-handson
```
**確認**：`docker ps -a | grep localstack` で何も出なければ完全に消えている。

> `awslocal` コマンド本体（pipで入れたもの）は残しても無害です。消したい場合は `python3 -m pip uninstall awscli-local`。

## 本物のAWSでやる場合の差分（重要）
| 項目 | LocalStack（この実習） | 本物のAWS |
|---|---|---|
| コマンド | `awslocal`（自動でlocalhost:4566） | `aws`（`aws configure` でキー設定が必要） |
| 認証 / IAM | ダミーで素通り | **IAMユーザー/ロールと権限が必須**。最小権限が鉄則 → [iam.md](./iam.md) |
| リージョン | 実質意味なし | `ap-northeast-1`（東京）等を必ず意識。バケットはリージョンに紐づく |
| 課金 | **ゼロ** | 使った分だけ**実際に請求**。Billingアラート必須 → [getting_started.md](./getting_started.md) |
| 片付け | コンテナ削除で全消去 | リソースを**個別に削除**しないと課金が続く → [pitfalls.md](./pitfalls.md) |

> 本物に移るときは、まず [getting_started.md](./getting_started.md) で IAMユーザー作成・課金アラートを整えてから。`awslocal` を `aws` に置き換えるだけで、ほぼ同じコマンドが通る。
