# 始め方（AWS）

## ひとことで言うと
AWSを使い始めるための初期セットアップ一式。**アカウント作成 → 安全な入り口（IAMユーザー＋MFA）→ 操作手段（コンソール / CLI）→ 課金の見張り（Billingアラート）** までを最初に整える工程。

## 役割・なぜ必要か
- AWSは「クレジットカードを登録した瞬間に、世界中のサーバーを従量課金で借りられる」サービス。便利な反面、**事故が直接お金とセキュリティ被害につながる**。最初の設計が後の安全を決める。
- 作成直後のアカウントには **ルートユーザー**（メール＋パスワードでログインする最高権限）しか居ない。ルートは全権限を持ち、無効化も削除もできない危険な存在。日常作業に使うと、漏洩＝アカウント全損になる。
- そこで「ルートは封印し、**権限を絞ったIAMユーザー**を作って普段使いする」「**MFA（多要素認証）** を全員に付ける」「**課金アラート**で異常な支出に即気づく」という土台を最初に作る。

## 基本の使い方（CLI / コンソール）
コンソール（ブラウザ）でやる初期作業の順序：
1. アカウント作成（メール・カード登録）
2. **ルートユーザーにMFAを設定**（仮想MFAアプリ等）
3. IAMでまず**管理用IAMユーザー**を1つ作る（後述。普段はこちらでログイン）
4. リージョンを **東京 `ap-northeast-1`** に切り替え（画面右上で選ぶ）
5. Billingアラートを設定（後述）

IAMユーザーにアクセスキーを発行したら、ローカルにCLIを設定する：
```bash
# AWS CLI v2 をインストール後
aws configure
# AWS Access Key ID     : AKIA...（IAMユーザーのもの。ルートでは作らない）
# AWS Secret Access Key : ****
# Default region name   : ap-northeast-1   ← 東京
# Default output format  : json

# 設定確認（今のアカウント/ユーザーを表示。これでログインできているか分かる）
aws sts get-caller-identity
```

```bash
# 設定ファイルの場所（中身を覗くとき）
cat ~/.aws/config        # region / output
cat ~/.aws/credentials   # access key / secret（git管理厳禁）

# 複数アカウントは「プロファイル」で切替
aws configure --profile work
aws s3 ls --profile work
```

Billingアラート（予算超過の通知）はコンソールの **Billing → Budgets**、または **CloudWatch請求アラーム**で作る。例：月$10を超えたらメール、など。
```bash
# 無料枠の使用状況・コストはCLIでも確認できる
aws ce get-cost-and-usage \
  --time-period Start=2026-06-01,End=2026-06-30 \
  --granularity MONTHLY --metrics "UnblendedCost"
```

## 実務での勘所
- **リージョンは「東京 ap-northeast-1」に固定**して始めると混乱が減る。リソースはリージョンごとに独立（東京で作ったEC2は大阪やバージニアからは見えない）。
- 無料枠（Free Tier）は **12か月無料**（EC2 t2.micro 750h/月 など）と**常時無料**（Lambda 100万リクエスト/月 など）が混在。「無料枠の範囲＝無制限」ではない。超えた瞬間に課金される。
- **Billingアラートは最初の30分で必ず設定**する。設定していないと、不正利用や消し忘れで数万〜数十万の請求に気づくのが請求書を見た時、になる。
- ルートユーザーは「請求情報の変更」「アカウント解約」など一部の作業でしか使わない。普段は触らない。
- IAM Identity Center（旧SSO）を使えるなら、長期アクセスキーより安全。最初は `aws configure` で十分。

## ハマりどころ / アンチパターン
- **ルートユーザーの常用**：最大のアンチパターン。漏洩すると全権限を奪われ、止める手段がほぼ無い。ルートはMFAを付けて封印し、IAMユーザーで作業する。→ [iam.md](./iam.md)
- **リージョン取り違え**：バージニア（us-east-1）のまま作業し「あれ、さっき作ったリソースが無い」。実は別リージョンに居る、はよくある。画面右上のリージョン表示を常に確認。
- **課金アラート未設定で高額請求**：消し忘れたEC2/RDS、アクセスキー漏洩によるマイニング悪用などで青天井に。Budgets/CloudWatchアラームは必須。
- **アクセスキーをコードやgitに直書き**：漏洩の定番。→ [iam.md](./iam.md) のアクセスキー項を参照。
- **MFA未設定**：パスワード漏洩だけで侵入される。ルート・全IAMユーザーに付ける。
