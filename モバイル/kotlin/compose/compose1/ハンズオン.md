# ハンズオン：Android Studio で Compose アプリを画面に出す

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にやれば、0から「画面が出て操作できる」ところまで行けます。

## 最初に正直に言っておくこと（前提が重い）
モバイル開発は Web と違い、**Docker だけでは完結しません**。Jetpack Compose でアプリを動かすには下記が要ります。

- **Android Studio**（無料。**SDK・エミュレータ・Gradle がすべて同梱**。これ1本でほぼ揃う）。
  - Windows / macOS / Linux のどれでもOK（SwiftUI と違い OS を選ばない）。
  - **初回はダウンロードと SDK 取得に時間がかかる**。
- アプリを映す **Android エミュレータ**（Android Studio から作成・起動する）か **実機**（USB デバッグ ON）。
- このハンズオンは**コマンドより Android Studio の GUI 操作が中心**。スクリーンショットは載せられないので、「どのメニュー → こう表示されたら成功」を文章で丁寧に書きます。

> Compose は Gradle に密に乗っているため、**プロジェクト初期設定（Gradle）が正しいこと**が前提。Android Studio のテンプレートから作れば自動で整います。→ [getting_started.md](./getting_started.md)

**所要時間**：60〜120分（Android Studio・SDK・エミュレータ・初回 Gradle ビルドを含むため長め）
**ゴール**：Android エミュレータで **カウンターアプリが起動して、ボタンで数が増える**。さらに **Preview** を体験し、最後に **`LazyColumn` で一覧**を表示できる。

---

## 準備A：Android Studio が入っているか確認
**やること**：Android Studio がインストール済みか確認する。
**なぜ**：Compose のビルド・エミュレータ・SDK 管理がすべてこの中にあるため、まず本体が要る。

- まだ無いなら [developer.android.com/studio](https://developer.android.com/studio) から入れる。初回起動時の **Setup Wizard** で「Android SDK」「エミュレータ」をまとめて入れる（時間がかかる）。
- 入っているなら Android Studio を起動する。

**成功**：Welcome 画面（または既存プロジェクト）が開く。
**失敗**：Setup Wizard が SDK のダウンロードで止まる → ネットワークを確認し、ウィザードを再実行。

---

## ステップ1：Empty Compose Activity で新規プロジェクトを作る
**やること**：Compose テンプレートでプロジェクトを生成する。
**なぜ**：Gradle 設定込みの「動く完成形」を一度起動するため。手で Gradle を書くより圧倒的に速い。

操作:
1. Welcome 画面で **「New Project」** をクリック（メニュー `File > New > New Project` でも可）。
2. テンプレート一覧から **「Empty Activity」**（説明に **Jetpack Compose** と書かれているもの）を選び **Next**。
   - ※古いバージョンでは「Empty Compose Activity」という名前。
3. 設定:
   - **Name**：`MyApp`
   - **Package name**：既定のまま（例 `com.example.myapp`）
   - **Language**：**Kotlin**
   - **Minimum SDK**：既定のまま **Finish**。
4. プロジェクトが開くと、右下や上部に **「Gradle sync」**が走る。**緑のチェック / 「sync finished」**まで待つ。

**成功**：左ペインにファイル一覧、`MainActivity.kt` が開ける。Gradle sync が完了している。
**失敗**：
- Gradle sync が赤くなる → 「わざと壊す」章で扱う典型パターン。まずは下記まで進めてOK。
- テンプレートに Compose が無い → Android Studio が古い。`Help > Check for Updates` で更新。

---

## ステップ2：エミュレータ（仮想デバイス）を作る
**やること**：アプリを映す Android 仮想デバイス（AVD）を1つ用意する。
**なぜ**：実機が無くても、エミュレータで画面を出せる。これが無いと「画面が出る」体験ができない。

操作:
1. メニュー `Tools > Device Manager`（または右側の Device Manager アイコン）を開く。
2. **「Create Device」** をクリック。
3. **Pixel 7** など適当な端末を選び **Next**。
4. システムイメージ（OSバージョン）を選ぶ。横に **Download** があれば押して取得（時間がかかる）。取得後 **Next → Finish**。

**成功**：Device Manager の一覧に作った仮想デバイスが並ぶ。**▶（起動）** で仮想 Android スマホが立ち上がる。
**失敗**：
- システムイメージの Download が進まない → ネットワーク確認。別バージョンのイメージを試す。
- 起動しても黒い画面のまま → 初回は数分かかる。待っても進まなければ Device Manager から一度 **Cold Boot**。

---

## ステップ3：Run でアプリを起動して「画面が出る」を確認する（本題の入口）
**やること**：作ったアプリをエミュレータで実行する。
**なぜ**：これが「環境構築が成功した」最大の証拠。

操作:
1. Android Studio 上部の **デバイス選択**に、作った仮想デバイス（例 `Pixel 7 API 34`）が選ばれていることを確認。
2. 上部の **▶（Run 'app'）** を押す（ショートカット `⌃R` / `Shift+F10`）。

**成功**：初回 Gradle ビルドのあと、**エミュレータにアプリがインストールされて起動**し、「Hello Android!」などの初期画面が出る。
→ **これが「アプリが起動した」証拠**。環境構築は成功です。
**失敗**：
- デバイスが選べない → 先に Device Manager でエミュレータを起動（ステップ2）。
- Gradle ビルドで赤エラー → 「わざと壊す」章で扱う。
- 初回が極端に遅い → 正常。ビルドとインストールに数分かかることがある。

## ステップ4：`@Composable` を編集して状態（カウンター）を作る
**やること**：`MainActivity.kt` の中身をカウンターに書き換える。
**なぜ**：Compose の核「**状態（`mutableStateOf`）が変わると再コンポーズされ、画面が状態に追従する**」を手で確かめる。

`MainActivity.kt` を開き、`setContent { ... }` の中身を下記の `CounterScreen()` 呼び出しに変え、ファイル下部に関数を足す（テーマ名はテンプレが付けた `MyAppTheme` 等に合わせる）:
```kotlin
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp

// setContent の中をこの呼び出しに：
//   setContent { MyAppTheme { Surface { CounterScreen() } } }

@Composable
fun CounterScreen() {
    // remember { mutableStateOf(...) } = 再コンポーズしても保持される状態
    var count by remember { mutableStateOf(0) }

    Column(
        modifier = Modifier.fillMaxSize().padding(24.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Center
    ) {
        Text("ボタンを押した回数：$count")
        Spacer(Modifier.height(16.dp))
        Button(onClick = { count++ }) {   // 手でTextを書き換えない。状態を変えるだけ
            Text("押す")
        }
    }
}
```
**反映する**：上部の **▶（Run）** をもう一度押す（Android Studio は保存→再ビルドで反映）。
**成功**：「ボタンを押した回数：0」と「押す」ボタンが出て、押すと数字が増える。
**読み解き**：`count++` で状態が変わると、その状態を読んでいる `@Composable` が**再コンポーズ**されて画面が作り直される。手で `Text` を更新していない。→ [state.md](./state.md)

## ステップ5：一覧（LazyColumn）を表示する
**やること**：カウンターの下に、スクロールできる一覧を足す。
**なぜ**：Compose の一覧は `LazyColumn`（見えている分だけ描画＝大量でも軽い）が定番。実務アプリに必ず出てくる。

`CounterScreen` を下記に置き換える:
```kotlin
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp

@Composable
fun CounterScreen() {
    var count by remember { mutableStateOf(0) }
    val items = listOf("コーヒー", "ケーキ", "アイス", "ピザ")

    Column(modifier = Modifier.fillMaxSize().padding(24.dp)) {
        Text("ボタンを押した回数：$count")
        Spacer(Modifier.height(8.dp))
        Button(onClick = { count++ }) { Text("押す") }
        Spacer(Modifier.height(16.dp))

        // LazyColumn = スクロールする一覧。items で各要素を描く
        LazyColumn {
            items(items) { item ->
                Text("・$item", modifier = Modifier.padding(vertical = 8.dp))
            }
        }
    }
}
```
**反映する**：▶（Run）。
**成功**：カウンターの下に項目が縦に並び、件数が多ければスクロールできる。
**失敗**：
- `items` が赤い（未解決）→ `import androidx.compose.foundation.lazy.items` を追加（補完の候補から選ぶ）。
- 一覧が出ない → `LazyColumn` が `Column` の高さに収まっているか確認（`fillMaxSize` を付ける）。

> `LazyColumn` は画面に見えている分だけ描画するので、件数が増えても軽い。→ [lists.md](./lists.md)

## わざとエラーを起こして、直す：Gradle sync 失敗 / エミュレータ未作成
**なぜ**：Android 開発で初心者が最も詰まるのが、コードのバグではなく **Gradle**（ビルド設定の同期）と **エミュレータの不在**。自分で再現して直し方を覚える。

### ケース1：Gradle sync が失敗する
**起こりやすい状況**：依存（ライブラリ）のバージョンを手で変えた、ネットワークが切れた、Gradle のバージョン不一致、など。
**症状**：上部に赤い帯で **「Gradle sync failed」**、エラーに `Could not resolve ...` や `Plugin ... not found` が出る。
**意味**：Gradle が「ビルドに必要な部品を揃えられなかった」。コードを動かす以前の段階で止まっている。
**直す（順に試す）**:
1. エラーメッセージの**最後の数行**を読む（`Could not resolve` の直後に、足りない依存名が出る）。
2. 自分で `build.gradle` を変えた直後なら、その変更を**元に戻す**。
3. ネットワーク不調なら、上部の **「Try Again」/ Sync Now**（象アイコン）を押して再同期。
4. キャッシュ不整合なら、メニュー `File > Invalidate Caches... > Invalidate and Restart`。
5. それでもダメなら `File > Sync Project with Gradle Files`。

**成功**：赤帯が消えて「sync finished」になり、▶ が押せるようになる。
**ポイント**：Compose は Gradle に強く依存する。**「sync が緑になるまでコードは動かせない」**と覚えておく。→ [pitfalls.md](./pitfalls.md)

### ケース2：エミュレータが無くて Run できない
**起こす**：Device Manager のデバイスを削除した状態（または最初から作っていない状態）で ▶ を押す。
**結果**：上部のデバイス選択が空で、Run しても **「No target device found」** などで起動できない。
**意味**：アプリを映す先（仮想デバイス）が存在しない。
**直す**：`Tools > Device Manager > Create Device` で仮想デバイスを1つ作って起動する（ステップ2）。
**成功**：デバイス選択にエミュレータが現れ、▶ で起動できる。

## 片付け（必要なら）
- エミュレータは閉じてよい（次回また Device Manager の ▶ で起動）。
- プロジェクトを消すなら、保存先フォルダごと削除する。
