# ハンズオン：Expo で React Native アプリを画面に出す

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にやれば、0から「画面が出て操作できる」ところまで行けます。

## 最初に正直に言っておくこと（前提が重い）
モバイル開発は Web と違い、**Docker だけでは完結しません**。React Native（RN）でアプリを動かすには下記が要ります。

- **Node.js（LTS版）**（`npx` を使うため）
- アプリを映す画面のどれか1つ:
  - **Expo Go**（スマホアプリ。**一番ラク**。手持ちの iPhone / Android に入れるだけ）
  - **Android エミュレータ**（要 Android Studio）
  - **iOS シミュレータ**（要 Mac + Xcode）
- エディタは **VS Code** 推奨（このハンズオンはコマンド中心なので何でも可）

> このハンズオンは**敷居を一番下げるため Expo を使います**。Expo はネイティブ環境構築を肩代わりしてくれるので、最短で「画面が出る」を体験できます。
> **Expo と「素のRN」の違い**：素のRN（`@react-native-community/cli`）は `ios/` `android/` を最初から自前管理し、Xcode / Android Studio が必須。Expo はそれを抽象化して、まず JS/TS だけで動かせる。迷ったら Expo でよい（後から `npx expo prebuild` で素のRN相当に展開もできる）。→ [getting_started.md](./getting_started.md)

**所要時間**：40〜70分（Node 確認・パッケージ取得・初回起動を含む）
**ゴール**：Expo Go（またはエミュレータ）で **カウンターアプリが起動して、ボタンで数が増える**。さらに **`useState` を編集**し、最後に **`FlatList` で一覧**を表示できる。

---

## 準備A：Node.js が入っているか確認
**やること**：Node と npm（npx）が使えるか見る。
**なぜ**：Expo の作成・起動は `npx`（Node 同梱）で行うため、これが無いと何も始まらない。
```bash
node --version      # v18 以上が目安（LTS推奨）
npm --version
```
**成功**：`v20.x.x` のようにバージョンが出る。
**失敗**：`command not found: node` → 未インストール。公式（[nodejs.org](https://nodejs.org/)）の **LTS** を入れるか、`nvm` でインストール。入れ直したらターミナルを開き直して再確認。

---

## 準備B：アプリを映す画面を1つ用意する
下記のどれか1つでOK。**一番ラクなのは Expo Go**。

- **Expo Go（推奨・最短）**
  手持ちのスマホに、App Store / Google Play から「**Expo Go**」を入れる。後で QR を読むだけで画面が出る。
  **注意**：PC とスマホが**同じ Wi-Fi**に繋がっていること（別ネットワークだと QR で繋がらない）。
- **Android エミュレータ**：Android Studio を入れ、Device Manager で仮想デバイスを起動しておく。
- **iOS シミュレータ**：Mac + Xcode を入れ、`Xcode > Settings > Components` でシミュレータを用意。

## ステップ1：Expo プロジェクトを作る
**やること**：Expo の標準テンプレート（TypeScript）でアプリ雛形を生成する。
**なぜ**：自分で書く前に、動く完成形を一度動かすため。
```bash
cd ~
npx create-expo-app@latest my-app
cd my-app
```
**成功**：`my-app` フォルダができ、依存のインストールが終わって `✅ Your project is ready!` 系のメッセージが出る。
**失敗**：
- 途中で固まる → ネットワーク。`my-app` 内で `npm install` を再実行。
- 権限エラー → `sudo` は使わず、npm のグローバル設定（prefix）を見直す。

---

## ステップ2：開発サーバ（Metro）を起動して画面を出す（本題の入口）
**やること**：Metro バンドラを起動し、Expo Go かエミュレータに映す。
**なぜ**：RN は「**Metro（JSバンドラ）＋ネイティブの画面**」の2層。Metro が起動して画面が出れば、環境構築は成功。
```bash
npx expo start
```
ターミナルに **QR コード**と操作メニューが出る:
```
› Press a │ open Android
› Press i │ open iOS simulator
› Press w │ open web
› Press r │ reload app
```
画面の出し方（どれか）:
- **Expo Go**：スマホの Expo Go（Android）/ カメラ（iOS）で **QR を読む**。
- **Android エミュレータ**：ターミナルで `a` を押す。
- **iOS シミュレータ**：ターミナルで `i` を押す。

**成功**：「Open up App.tsx to start working on your app!」のような初期画面がスマホ/エミュレータに表示される。
→ **これが「アプリが起動した」証拠**。環境構築は成功です。
**失敗**：
- QR を読んでも繋がらない → PC とスマホが**同じ Wi-Fi**か確認。ダメなら `npx expo start --tunnel`（トンネル経由で繋ぐ）。
- `a` を押しても起動しない → エミュレータが起動していない。先に Device Manager で起動。

> このターミナルは**起動したまま**にしておく（止めると編集の即時反映ができない）。

## ステップ3：画面を自分のコードに書き換える
**やること**：`App.tsx`（または `app/index.tsx`）の中身を、シンプルなカウンターに置き換える。
**なぜ**：RN の中心「`useState` の状態が変わる → 再レンダリング → ネイティブUIが変わる」を手で確かめるため。

> テンプレートにより入口ファイルが `App.tsx` か `app/index.tsx` のどちらか。`my-app` 直下に `App.tsx` があればそれ、無ければ `app/index.tsx` を編集する。

ファイルの中身をまるごと下記に置き換える:
```tsx
import { useState } from 'react';
import { View, Text, Button, StyleSheet } from 'react-native';

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <View style={styles.container}>
      {/* RN ではテキストは必ず <Text> の中に書く（<div>感覚で文字を置くと落ちる） */}
      <Text style={styles.label}>ボタンを押した回数：{count}</Text>
      <Button title="押す" onPress={() => setCount(count + 1)} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 16 },
  label: { fontSize: 20 },
});
```
保存する。Expo は**保存しただけで自動反映（Fast Refresh）**される。
**成功**：「ボタンを押した回数：0」と「押す」ボタンが出て、押すと数字が増える。
**失敗**：
- 赤いエラー画面（Text 関連）→ 文字を `<Text>` で囲み忘れていないか確認。
- 反映されない → ターミナルで `r` を押して手動リロード。

**読み解き**：`setCount(...)` を呼ぶと state が変わり、関数コンポーネントが再実行されて画面が作り直される。手で数字を書き換えていない。→ [components_state.md](./components_state.md)

## ステップ4：一覧（FlatList）を表示する
**やること**：カウンターの下に、スクロールできる一覧を足す。
**なぜ**：RN の一覧は `FlatList`（大量データでも速い）が定番。実務アプリに必ず出てくる。

`App.tsx` を下記に置き換える:
```tsx
import { useState } from 'react';
import { View, Text, Button, FlatList, StyleSheet } from 'react-native';

const ITEMS = [
  { id: '1', name: 'コーヒー' },
  { id: '2', name: 'ケーキ' },
  { id: '3', name: 'アイス' },
  { id: '4', name: 'ピザ' },
];

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <View style={styles.container}>
      <Text style={styles.label}>ボタンを押した回数：{count}</Text>
      <Button title="押す" onPress={() => setCount(count + 1)} />

      <FlatList
        style={styles.list}
        data={ITEMS}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => <Text style={styles.row}>・{item.name}</Text>}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, paddingTop: 80, paddingHorizontal: 24, gap: 16 },
  label: { fontSize: 20 },
  list: { marginTop: 16 },
  row: { fontSize: 18, paddingVertical: 8 },
});
```
保存して自動反映。
**成功**：カウンターの下に項目が縦に並び、項目が多ければスクロールできる。
**失敗**：
- リストが出ない → `FlatList` に `data` と `renderItem` が渡っているか確認。
- `key` 警告 → `keyExtractor` で一意な `id` を返しているか確認。

> `FlatList` は画面に見えている分だけ描画するので、件数が増えても軽い。→ [lists.md](./lists.md)

## わざとエラーを起こして、直す：Metro のポート / キャッシュ問題
**なぜ**：RN で最頻出の詰まりが「**Metro が変な状態になって反映されない / 起動しない**」。原因がコードでなく Metro 側のことが多く、知らないと延々ハマる。自分で起こして直し方を覚える。

### ケース1：ポートが使用中（Port already in use）
すでに `npx expo start` が動いている状態で、**別のターミナルからもう一度** `npx expo start` してみる:
```bash
npx expo start
```
**結果**：`Port 8081 is running this app in another window` / `Port 8081 is already in use` のような表示が出る。
**意味**：Metro が使う **8081 番ポート**が、さっき起動した方に占有されている。
**直す（どちらか）**：
- 前の Metro を止める（前のターミナルで `Ctrl + C`）。
- 別ポートで起動する:
  ```bash
  npx expo start --port 8082
  ```
**成功**：ポート衝突が消えて Metro が起動する。

### ケース2：キャッシュが壊れて反映されない
編集したのに画面が変わらない・古いコードが出続ける、という時はキャッシュを疑う。
**直す**：Metro を一度止めて、キャッシュを消して起動し直す。
```bash
npx expo start --clear
```
`--clear` は Metro のキャッシュを捨ててからバンドルし直すオプション。
**成功**：最新のコードで画面が再構築される。
**それでも直らない**：`node_modules` の取り直し（`rm -rf node_modules && npm install`）→ 再度 `npx expo start --clear`。

> ポイント：RN で「直したのに変わらない」と思ったら、まず疑うのは自分のコードではなく **Metro のキャッシュ**。`--clear` は覚えておくと一生役立つ。→ [pitfalls.md](./pitfalls.md)
