# ハンズオン：Flutter を入れてアプリを画面に出す

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にやれば、0から「画面が出て操作できる」ところまで行けます。

## 最初に正直に言っておくこと（前提が重い）
モバイル開発は Web と違い、**Docker だけでは完結しません**。アプリを動かすには下記が要ります。

- **Flutter SDK**（本体）
- **エミュレータ or 実機 or Chrome**（アプリを映す画面）
  - Android エミュレータを使うなら **Android Studio**（SDK・エミュレータ込み）
  - iOS シミュレータを使うなら **Mac + Xcode**
  - とりあえず一番ラクに「画面が出る」を体験するなら **Chrome（Web実行）**でもよい
- エディタは **VS Code** か **Android Studio** のどちらか（このハンズオンはコマンド中心なので、どちらでも可）

> 環境構築でつまずきやすいので、このハンズオンは **`flutter doctor` で“環境が整ったか”を確認する手順**から丁寧に書きます。

**所要時間**：60〜90分（SDK ダウンロードとエミュレータ初回起動を含むため長め）
**ゴール**：エミュレータ（または Chrome）で **カウンターアプリが起動して、ボタンを押すと数が増える**。さらに自分でコードを直して **Hot Reload で即反映**、最後に **一覧（ListView）を表示**できる。

---

## 準備A：Flutter SDK が入っているか確認
```bash
flutter --version
```
**成功**：`Flutter 3.x.x ... Dart 3.x.x` のようにバージョンが出る。
**失敗**：`command not found: flutter` → まだ入っていない。下の「準備A-2」へ。

### 準備A-2：入っていない場合の導入確認
Flutter SDK は公式手順（[docs.flutter.dev/get-started/install](https://docs.flutter.dev/get-started/install)）でOSごとに入れる。導入後、**PATH を通したか**を必ず確認する。
```bash
which flutter      # Flutter本体のパスが出ればPATHは通っている
```
**成功**：`/.../flutter/bin/flutter` のようなパスが出る。
**失敗**：何も出ない → PATH 未設定。`flutter/bin` をシェルの設定（`.zshrc` / `.bashrc`）の `PATH` に追加して、ターミナルを開き直す。

---

## 準備B：`flutter doctor` で環境の欠けを潰す（最重要）
**やること**：Flutter が「アプリをビルドできる状態か」を自己診断させる。
**なぜ**：ここで ✗ を放置すると、後で必ず「ビルドできない」「デバイスが見えない」で詰まる。先に潰すのが一番速い。
```bash
flutter doctor
```
出力はこんな形になる（環境で増減する）:
```
[✓] Flutter (Channel stable, 3.x.x, ...)
[✓] Android toolchain - develop for Android devices
[✓] Chrome - develop for the web
[!] Android Studio (not installed)
[✓] Connected device (1 available)
```
**読み方**：
- `[✓]` … OK。触らなくてよい。
- `[!]` … 警告。使わない項目（例：iOSを使わないのに Xcode 警告）なら無視してよい。
- `[✗]` … エラー。**そのデバイス/プラットフォームでは動かない**。下の「わざと壊す」章で典型例を直す。

**成功**：少なくとも「**Chrome**」か「**Connected device**（エミュレータ）」のどちらかが `[✓]` で、デバイスが1つ以上見える。
**失敗**：両方とも ✗ → アプリを映す先がない。Chrome を入れる（Web実行用）か、Android Studio でエミュレータを用意する（準備C）。

---

## 準備C：アプリを映す画面（デバイス）を1つ用意する
今つながっているデバイスを確認:
```bash
flutter devices
```
**成功**：`Chrome (web) ...` や `sdk gphone64 ... (mobile)` のような行が1つ以上出る。
**失敗（何も出ない）**：下のどちらかを用意する。

- **一番ラク：Chrome を使う**
  Chrome ブラウザが入っていれば `flutter devices` に `Chrome (web)` が出る。これで十分「画面が出る」体験ができる。
- **Android エミュレータを使う**
  Android Studio を入れ、`Device Manager` から仮想デバイス（AVD）を1つ作成し、▶ で起動する。起動後にもう一度 `flutter devices` を実行すると `sdk gphone...` が出る。

> どちらでもOK。まず1個動かすのが目的なので、**Chrome が手っ取り早い**。

## ステップ1：アプリの雛形を作る
**やること**：Flutter の標準サンプル（カウンターアプリ）を生成する。
**なぜ**：自分でゼロからコードを書く前に、「動く完成形」を一度見るため。
```bash
cd ~        # 作業しやすい場所へ
flutter create --org com.example my_app
cd my_app
```
**成功**：`my_app` フォルダができ、`Running "flutter pub get"... ` のあと `All done!` が出る。
**失敗**：
- `Unable to find git` → Flutter は git を使う。git を入れてから再実行。
- 途中で止まる → ネットワーク。`flutter pub get` を `my_app` 内で再実行。

---

## ステップ2：起動して「画面が出る」を確認する（本題の入口）
**やること**：作った雛形をデバイスで起動する。
**なぜ**：これが「環境構築が成功した」最大の証拠。ここを越えれば後はコードを触るだけ。
```bash
flutter run -d chrome        # Web（Chrome）で起動
# Android エミュレータがあるなら:
# flutter run                # デバイスが1つなら自動選択
```
しばらくビルドが走り、やがて**画面が出る**。
**成功**：中央に大きく `0`、右下に **`+` ボタン**のある画面が表示される。`+` を押すと数字が増える。
→ **これが「アプリが起動して操作できた」状態**。おめでとうございます、環境構築は成功です。
**失敗**：
- `No supported devices connected` → デバイス未起動。`flutter devices` で確認（準備Cへ戻る）。
- Chrome なのにビルドが進まない → `flutter run -d chrome --web-renderer html` を試す。
- Android で `Gradle` 関連エラー → 初回はビルドに数分かかることがある。失敗時は `flutter clean` 後に再実行。

> このターミナルは**起動したまま**にしておく（止めると次の Hot Reload ができない）。

## ステップ3：コードを直して Hot Reload を体験する
**やること**：表示文字を書き換え、保存（リロード）して即反映を見る。
**なぜ**：Flutter 開発の核は **Hot Reload**＝「保存した瞬間に画面が変わる」。これを体感すると開発体験が一変する。

別のエディタで `lib/main.dart` を開き、`'You have pushed the button this many times:'` の行を探して、文言を変える。例:
```dart
// 変更前
const Text('You have pushed the button this many times:'),
// 変更後
const Text('ボタンを押した回数：'),
```
保存したら、**`flutter run` を実行中のターミナル**で `r` キーを押す（Hot Reload）。
**成功**：エミュレータ/Chrome の文言が**一瞬で**「ボタンを押した回数：」に変わる。カウントの値は保持されたまま。
**失敗**：
- 変わらない → 保存し忘れ。エディタで保存し直して再度 `r`。
- `r` で反映されない種類の変更（`main()` や定数の変更など）→ `R`（大文字＝ホットリスタート）を押す。

---

## ステップ4：状態（カウンター）の仕組みを少し触る
**やること**：増える量を 1 → 2 に変える。
**なぜ**：「ボタンを押す → 状態(`_counter`)が変わる → 画面が再ビルドされる」という Flutter の中心の流れを、手で確かめる。

`lib/main.dart` の `_incrementCounter` を探して直す:
```dart
void _incrementCounter() {
  setState(() {
    _counter++;        // 変更前：1ずつ増える
    // _counter += 2;  // 変更後：2ずつ増えるようにする
  });
}
```
`_counter++;` を `_counter += 2;` に書き換えて保存 → ターミナルで `r`。
**成功**：`+` を押すたびに **2ずつ**増える。
**読み解き**：`setState(() { ... })` が「状態を変えたよ」と Flutter に伝え、`build()` が呼ばれて画面が作り直される。手で数字を書き換えていない点が重要。→ [state_management.md](./state_management.md)

---

## ステップ5：一覧（ListView）を表示する
**やること**：カウンター画面の本文を、スクロールできる一覧に置き換える。
**なぜ**：実務アプリの大半は「一覧」を含む。`ListView` は最頻出。

`lib/main.dart` の `body:` の中身（`Center(...)` のかたまり）を、まるごと下記に置き換える:
```dart
body: ListView(
  children: const [
    ListTile(leading: Icon(Icons.coffee), title: Text('コーヒー')),
    ListTile(leading: Icon(Icons.cake),   title: Text('ケーキ')),
    ListTile(leading: Icon(Icons.icecream), title: Text('アイス')),
    ListTile(leading: Icon(Icons.local_pizza), title: Text('ピザ')),
  ],
),
```
保存 → ターミナルで `r`。
**成功**：アイコン付きの一覧が縦に並び、項目が多ければ**スクロール**できる。
**失敗**：
- 赤い画面（エラー表示）→ かっこ `(` `)` `[` `]` の対応ミス。エラーの行番号を見て直す。
- `r` で直らない → `R`（ホットリスタート）を押す。

> 件数が多い・データから作る場合は `ListView.builder` を使う。→ [lists.md](./lists.md)

## わざとエラーを起こして、直す：`flutter doctor` が赤い時の典型
**なぜ**：実務で最初に必ず出会う詰まりが、まさに `flutter doctor` の `[✗]`。「自分で再現して直す」と一生忘れない。ここでは Android 開発で**最頻出の2つ**を扱う。

### ケース1：Android ライセンス未承認（`[✗]` または `[!]` でライセンス警告）
`flutter doctor` でこんな行が出ることがある:
```
[!] Android toolchain - develop for Android devices
    ✗ Android license status unknown.
      Run `flutter doctor --android-licenses` to accept the SDK licenses.
```
**意味**：Android SDK のライセンスに同意していないので、Android 向けにビルドできない。
**直す**：
```bash
flutter doctor --android-licenses
# 規約が次々出るので、すべてに y（yes）で答える
```
終わったら再確認:
```bash
flutter doctor
```
**成功**：`[✓] Android toolchain` に変わる。
→ これで Android エミュレータ向けの `flutter run` が通るようになる。

### ケース2：Android SDK のパスが見つからない（`Unable to locate Android SDK`）
**意味**：Flutter が Android SDK の場所を知らない。
**直す**：Android Studio をインストールすると SDK も入る。場所を Flutter に教える:
```bash
# SDKの場所（例）を Flutter に登録
flutter config --android-sdk ~/Library/Android/sdk     # mac の例
# flutter config --android-sdk ~/Android/Sdk           # Linux の例
flutter doctor
```
**成功**：`Unable to locate Android SDK` が消える。
**それでも消えない**：Android Studio の `SDK Manager` で「Android SDK Command-line Tools」を入れてから再実行。

> ポイント：`flutter doctor` は**何が足りないかを日本語/英語で具体的に教えてくれる**。エラー文の `Run ...` の行をそのまま実行するのが最短の直し方。
