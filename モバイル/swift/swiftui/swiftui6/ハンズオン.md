# ハンズオン：Xcode で SwiftUI アプリを画面に出す

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にやれば、0から「画面が出て操作できる」ところまで行けます。

## 最初に正直に言っておくこと（前提が重い）
SwiftUI 開発は、他のFW以上に前提が固定されています。**Docker では完結しません**。

- **macOS が必須**（Windows / Linux では Xcode が動かず、SwiftUI のビルド・シミュレータが使えない）。
- **Xcode**（App Store から無料。**数GBあるのでダウンロードに時間がかかる**）。Xcode に **Swift・SwiftUI・iOS シミュレータ**が同梱されている。
- このハンズオンは**コマンドよりも Xcode の GUI 操作が中心**。スクリーンショットは載せられないので、「どのボタンを押す → こう表示されたら成功」を文章で丁寧に書きます。

> Windows / Linux の人は、ここは「読み物」として流し、手を動かす実習は [Flutter](../../../dart/flutter/flutter3/ハンズオン.md) か [React Native](../../../react_native/react_native0/ハンズオン.md) で行うとよい（Mac 不要で画面まで出せる）。

**所要時間**：60〜120分（Xcode のダウンロード・初回ビルドを含むため長め）
**ゴール**：iOS シミュレータで **カウンターアプリが起動して、ボタンで数が増える**。さらに **Canvas のプレビュー**を体験し、最後に **`List` で一覧**を表示できる。

---

## 準備A：Xcode が入っているか確認
**やること**：Xcode 本体とコマンドラインツールの有無を見る。
**なぜ**：Xcode が無いと SwiftUI は1行もビルドできない。最初に確認する。

ターミナルで:
```bash
xcodebuild -version
```
**成功**：`Xcode 16.x` のようにバージョンが出る。
**失敗**：
- `xcode-select: error: ... no developer tools` → Xcode 未インストール。**App Store**で「Xcode」を検索して入れる（時間がかかる）。
- Xcode は入っているのにエラー → 一度 Xcode を起動して**初回セットアップ（追加コンポーネントのインストール）**を済ませ、ライセンスに同意:
  ```bash
  sudo xcodebuild -license accept
  ```

---

## 準備B：iOS シミュレータがあるか確認
**やること**：アプリを映すシミュレータが用意されているか見る。
**なぜ**：実機が無くても、シミュレータ（Mac 上で動く仮想 iPhone）で画面を出せる。
```bash
xcrun simctl list devices available | grep iPhone
```
**成功**：`iPhone 15 (...) (Shutdown)` のような行が1つ以上出る。
**失敗（何も出ない）**：Xcode を起動し、`Xcode > Settings > Components`（または Platforms）から **iOS シミュレータ**をダウンロードする。

---

## ステップ1：新規 SwiftUI プロジェクトを作る
**やること**：Xcode の GUI で App テンプレートのプロジェクトを作る。
**なぜ**：自分で書く前に、動く完成形を一度起動するため。

操作:
1. **Xcode を起動**する。
2. ようこそ画面で **「Create New Project...」** をクリック（出ない場合はメニュー `File > New > Project`）。
3. 上部タブ **iOS** → **App** を選び **Next**。
4. 設定を入れる:
   - **Product Name**：`MyApp`
   - **Interface**：**SwiftUI**（重要。Storyboard ではない）
   - **Language**：**Swift**
   - 他は既定のまま **Next**。
5. 保存場所を選んで **Create**。

**成功**：左ペインにファイル一覧、中央にコードエディタが出る。`ContentView.swift` と `MyAppApp.swift` がある。
**失敗**：
- Interface に SwiftUI が無い → 古い Xcode。App Store で更新。
- 開いた直後に何も表示されない → 左上のファイル `ContentView.swift` をクリックして開く。

---

## ステップ2：Canvas（プレビュー）で見た目を確認する
**やること**：シミュレータを起動せずに、Xcode の右側 Canvas で見た目を見る。
**なぜ**：SwiftUI の最大の利点が **`#Preview`（ライブプレビュー）**。保存するだけで右側に画面が出る。これを先に体験しておく。

操作:
1. `ContentView.swift` を開く。
2. 右上の **エディタ切り替えアイコン**から **Canvas** を表示（メニュー `Editor > Canvas` でも可）。
3. Canvas 内の **「Resume」/ ▶（再開）** ボタンを押す。

**成功**：右側の Canvas に、地球儀アイコンと「Hello, world!」が表示される。
**失敗**：
- Canvas が真っ白・「Preview paused」→ **Resume** ボタンを押す（自動更新が止まっているだけ）。
- 「固まる」場合は後述の「わざと壊す」章で扱う。

---

## ステップ3：シミュレータで実行して「画面が出る」を確認する（本題の入口）
**やること**：実際の iOS シミュレータでアプリを起動する。
**なぜ**：これが「環境構築が成功した」最大の証拠。

操作:
1. Xcode 上部の **ビルド対象（スキーム）**を確認。`MyApp > iPhone 15` のように **実行先のシミュレータ**が選ばれていること。
2. 左上の **▶（Run）** ボタンを押す（ショートカット `⌘R`）。

**成功**：初回ビルドのあと **シミュレータ（仮想 iPhone）が立ち上がり**、地球儀と「Hello, world!」の画面が出る。
→ **これが「アプリが起動した」証拠**。環境構築は成功です。
**失敗**：
- ▶ が押せない / グレー → ビルド対象が「Any iOS Device」など実機向けになっている。プルダウンから **シミュレータ（iPhone 15 等）**を選び直す（「わざと壊す」章でも扱う）。
- ビルドエラー → エラー（赤）の行をクリックして内容を読む。初回は時間がかかるだけのこともある。

---

## ステップ4：コードを編集して状態（カウンター）を作る
**やること**：`ContentView.swift` をカウンターに書き換える。
**なぜ**：SwiftUI の核「**`@State` が変わると body が再評価され、画面が状態に追従する**」を手で確かめる。

`ContentView.swift` の `struct ContentView` を下記に置き換える:
```swift
import SwiftUI

struct ContentView: View {
    // @State = この View が持つ状態。変わると body が再評価される
    @State private var count = 0

    var body: some View {
        VStack(spacing: 16) {
            Text("ボタンを押した回数：\(count)")
                .font(.title2)
            Button("押す") {
                count += 1   // 手で画面を更新しない。状態を変えるだけ
            }
            .buttonStyle(.borderedProminent)
        }
        .padding()
    }
}

#Preview {
    ContentView()
}
```
保存（`⌘S`）すると Canvas が自動更新される。シミュレータで確認するなら再度 **▶（⌘R）**。
**成功**：「ボタンを押した回数：0」と「押す」ボタンが出て、押すと数字が増える。
**読み解き**：`count += 1` で状態が変わると、SwiftUI が `body` を再評価して画面を作り直す。手で `Text` を書き換えていない。→ [state.md](./state.md)

## ステップ5：一覧（List）を表示する
**やること**：カウンターの下に、スクロールできる一覧を足す。
**なぜ**：SwiftUI の一覧は `List`（＋ `ForEach`）が定番。実務アプリに必ず出てくる。

`ContentView` を下記に置き換える:
```swift
import SwiftUI

struct ContentView: View {
    @State private var count = 0
    let items = ["コーヒー", "ケーキ", "アイス", "ピザ"]

    var body: some View {
        VStack(spacing: 16) {
            Text("ボタンを押した回数：\(count)")
                .font(.title2)
            Button("押す") { count += 1 }
                .buttonStyle(.borderedProminent)

            // List = スクロールする一覧。id: \.self で各要素を区別
            List(items, id: \.self) { item in
                Text(item)
            }
        }
        .padding(.top)
    }
}

#Preview {
    ContentView()
}
```
保存 → Canvas またはシミュレータ（▶）で確認。
**成功**：カウンターの下に項目が縦に並び、スクロールできる一覧になる。
**失敗**：
- 一覧が出ない → `List(items, id: \.self)` の `id:` を書き忘れていないか確認。
- 赤いエラー → かっこ `{ }` の対応ミス。エラー行を見て直す。

> データ件数が増える・モデルから作る場合は `Identifiable` を使う。→ [lists.md](./lists.md)

## わざとエラーを起こして、直す：Preview が固まる / ビルド対象が未選択
**なぜ**：SwiftUI で初心者が最も詰まるのが、コードのバグではなく **Xcode 側の状態**（Preview が止まる・実行先が間違っている）。自分で再現して直し方を覚える。

### ケース1：Canvas のプレビューが固まる / 更新されない
**起こす**：コードを何度か編集していると、Canvas が「Preview paused」や白いまま固まることがある（重い処理や一時的な不調で起きやすい）。
**意味**：プレビューのプロセスが止まっただけ。**コードが間違っているとは限らない**。
**直す（順に試す）**:
1. Canvas 右上の **Resume**（または ▶）ボタンを押す。
2. それでもダメなら、Canvas のエラー帯にある **「Diagnostics」** を開いて原因を読む。
3. プレビュー自体を再起動：メニュー `Editor > Canvas` を一度オフ→オンにする。
4. 最終手段：`Product > Clean Build Folder`（`⇧⌘K`）でビルド成果物を消し、▶ し直す。

**成功**：Canvas に再び画面が描画される。
**ポイント**：「Preview が固まった＝自分のコードが壊れた」ではない。まず **Resume** を押す癖をつける。

### ケース2：ビルド対象（実行先）が選ばれていなくて ▶ が押せない
**起こす**：上部のスキーム選択で、実行先を **「Any iOS Device (arm64)」** に変えてみる。
**結果**：▶（Run）がグレーになる、または実機が無いと「No devices」でビルドできない。
**意味**：シミュレータではなく**実機向け**にビルドしようとしている。実機が繋がっていないので実行できない。
**直す**：上部のデバイス選択プルダウンから **「iPhone 15」などのシミュレータ**を選び直す。
**成功**：▶ が押せるようになり、シミュレータが起動する。

> ポイント：ビルドできない時は、まず**「実行先がシミュレータになっているか」**を確認する。SwiftUI 学習中は基本シミュレータでよい。→ [pitfalls.md](./pitfalls.md)
