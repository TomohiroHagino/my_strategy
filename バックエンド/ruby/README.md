# Ruby

## 一言で
「書いていて楽しい」「開発者の幸福」を最優先に設計された、動的型付けの純オブジェクト指向スクリプト言語（まつもとゆきひろ作）。すべてがオブジェクト。

## 特徴
- **純オブジェクト指向**: 数値も nil も全部オブジェクト。メソッドチェーンが自然。
- **表現力の高い柔軟な構文**: 同じ処理を何通りにも書ける。可読性の高いコードを書きやすい。
- **ブロックと高階関数**: `each` / `map` / `select` などイテレータが言語の中心。
- **メタプログラミング / DSL が得意**: `method_missing`・`define_method` 等で、RSpec や Rake のような「Rubyなのに別言語っぽい」DSLを作れる。
- **mixin（module）と duck typing**: 継承に頼らず振る舞いを合成。型より「そのメソッドに応答するか」。
- **実行速度は遅め**だが、Ruby 3.x の **YJIT** で大きく改善。並行性は **GVL（GIL）** の制約あり。

## どういう使い方をするのか
- **Webアプリ開発**（実質 Rails 中心）。スタートアップ〜SaaSの定番。
- **CLIツール・自動化スクリプト**（Rake タスク、運用スクリプト）。
- **プロトタイピング / MVP**: 少ないコードで素早く形にする。
- **DSL構築**: テスト（RSpec）、ビルド（Rake）、インフラ（旧Chef）など。

## 強み
- 開発速度と可読性。少人数で速く作れる。
- gem エコシステムが豊富で成熟。
- テスト文化が成熟（RSpec / Minitest）。
- メタプロで抽象化・DSLが書きやすい。

## 弱み・注意点
- 実行速度・CPUバウンド処理は不利（YJITで緩和中）。
- GVLにより**CPU並列**は苦手（I/O並行は可）。重い並列はSidekiq等で外に出す。
- 動的型ゆえ大規模で安全性が落ちる → **RBS / Sorbet / steep** で型を補完。
- フロント・モバイル・組み込みには不向き。

## 向いている場面 / 向かない場面
- 向いている: Webサービスの素早い立ち上げ、CRUD中心の業務アプリ、スクリプト・自動化。
- 向かない: 超高スループット/低レイテンシ、CPUバウンドな計算、モバイル/組み込み。

## エコシステム・周辺ツール
- パッケージ: RubyGems / Bundler
- バージョン管理: rbenv / rvm / mise
- テスト: RSpec / Minitest、品質: RuboCop
- 非同期ジョブ: Sidekiq、アプリサーバ: Puma、高速化: YJIT
- 型: RBS / Sorbet
