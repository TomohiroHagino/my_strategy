# ハンズオン：Rails 7 で 0 から CRUD を1つ動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [controller.md](./controller.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- `rails new` でアプリを作り、`rails server` で**ブラウザに表示**できる
- `scaffold` で **1リソースのCRUD（一覧・作成・編集・削除）画面**を出せる
- わざと **マイグレーション忘れでエラーを起こして、自分で直せる**
- ここまでやると [active_record.md](./active_record.md) / [controller.md](./controller.md) / [routing.md](./routing.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Docker が動くこと（Ruby を自分で入れる必要はありません）

---

## 準備：Docker が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（またはdockerサービス）が起動していない。起動してから再実行。

作業用フォルダを作る:
```bash
mkdir -p ~/rails-handson && cd ~/rails-handson
```

---

## ステップ1：Ruby + Rails が入ったコンテナに入る
**やること**：Ruby が最初から入った公式イメージのコンテナに入り、その中で作業する。
**なぜ**：自分のPCに Ruby や Rails を入れなくても、コンテナの中なら同じ環境がすぐ手に入るため。
```bash
docker run -it --name rails-dev \
  -p 3000:3000 \
  -v "$PWD:/work" -w /work \
  ruby:3.2 bash
```
- `-it`＝対話的にシェルを使う、`-p 3000:3000`＝PCの3000番をコンテナの3000番に繋ぐ（Railsの既定ポート）。
- `-v "$PWD:/work" -w /work`＝今のフォルダをコンテナの `/work` に貸して、そこを作業場所にする（中で作ったファイルがPCにも残る）。

**成功**：プロンプトが `root@xxxx:/work#` のように変わる（＝コンテナの中に入った）。
**失敗**：`port is already allocated` → 3000番が使用中。一度 `exit` して `-p 3001:3000` に変えて再実行（後でブラウザは http://localhost:3001 を開く）。

> **以降の `#` で始まるコマンドは、すべてこのコンテナの中で実行**します。

Rails をインストール:
```bash
gem install rails -v "~> 7.1"
rails -v
```
**成功**：`Rails 7.1.x` のように表示される（数分かかることがあります）。
**失敗**：`Could not find...` → ネットワーク未接続。接続を確認して再実行。

---

## ステップ2：アプリを作って起動し、ブラウザで見る
**やること**：`rails new` で雛形を生成し、`rails server` で起動する。
**なぜ**：「Railsアプリが起動してブラウザに出る」状態をまず目で確認するため。

アプリを生成（SQLite・テスト雛形なしで最小構成）:
```bash
rails new blog --skip-test --skip-bundle
cd blog
bundle install
```
- `blog` がアプリ名。`--skip-test` でテスト雛形を省略、`--skip-bundle` で生成直後の自動インストールを止めて、後で手動で `bundle install` する（失敗時に切り分けやすい）。
- DBは指定しなければ **SQLite**（ファイル1つで動くDB＝今回は追加のDBサーバ不要）。

**成功**：`blog/` フォルダができ、`bundle install` の最後に `Bundle complete!` が出る。
**失敗**：`bundle install` が遅い/止まる → ネットワークの問題。再実行すると続きから進む。

サーバを起動:
```bash
bin/rails server -b 0.0.0.0
```
- `-b 0.0.0.0`＝コンテナの外（あなたのブラウザ）からアクセスできるように、全アドレスで待ち受ける。**これを忘れるとブラウザから繋がらない**。

ブラウザで **http://localhost:3000** を開く。
**成功**：`Rails version` `Ruby version` が書かれた**Railsの初期ページ**が出る。
**失敗**：
- ページが出ない → `-b 0.0.0.0` を付け忘れていないか確認。
- ステップ1でポートを変えた人は http://localhost:3001 を開く。

確認できたら、いったんサーバを止める（`Ctrl + C`）。プロンプトが `# ` に戻る。

## ステップ3：scaffold で CRUD を1つ作る（本題）
**やること**：`scaffold` で「記事（Article）」の一覧・作成・編集・削除を**まとめて生成**する。
**なぜ**：Railsの規約（ルート→コントローラ→モデル→ビュー）が**1コマンドで全部つながる様子**を体験するため。

```bash
bin/rails generate scaffold Article title:string body:text
```
- `Article` がリソース名、`title:string body:text` が持たせる項目（文字列のタイトルと長文の本文）。
- これで `model / controller / view / route / migration` が**一式生成**される。

**成功**：`create  app/models/article.rb` `create  db/migrate/..._create_articles.rb` などズラッと出る。
- 生成物の対応 → [model.md](./model.md) / [controller.md](./controller.md) / [view.md](./view.md) / [routing.md](./routing.md)

> ここで **わざと先にブラウザを見て、エラーを体験**します（次のステップ）。**まだ `db:migrate` しません**。

---

## ステップ4：わざと「マイグレーション忘れ」のエラーを起こして、直す
**なぜ**：「テーブルを作る前に画面を開く」のは初心者が必ずやる失敗。**自分で起こして直す**と一生忘れない。

サーバを起動:
```bash
bin/rails server -b 0.0.0.0
```
ブラウザで **http://localhost:3000/articles** を開く。
**結果**：`ActiveRecord::PendingMigrationError`（保留中のマイグレーションがあります）という赤いエラー画面が出る。
**読み解き**：`scaffold` は「articles テーブルを作る指示書（マイグレーション）」を生成しただけで、**まだDBに実行していない**。だからテーブルが無くてエラーになる。

サーバを止めて（`Ctrl + C`）、マイグレーションを実行:
```bash
bin/rails db:migrate
```
**成功**：`CreateArticles: migrating` → `CreateArticles: migrated` のような行が出る（articles テーブルが作られた）。
**失敗**：`SQLite3::...` が出る → SQLiteならまず出ないが、出たら `rails new` をやり直す。

もう一度サーバを起動して、画面を開き直す:
```bash
bin/rails server -b 0.0.0.0
```
ブラウザで **http://localhost:3000/articles** を再読み込み。
**成功**：今度は **`Articles` の一覧ページ**（最初は空）が表示される。→ マイグレーション忘れの原因＝「指示書はあるがDBに未適用」を体験で理解できた。

> 実務でも「`db:migrate` 忘れ」「他人の追加したマイグレーションを取り込んだのに未実行」で同じエラーに出会う。出たら **まず `bin/rails db:migrate`** が定石。→ [active_record.md](./active_record.md)

---

## ステップ5：CRUD を一周してみる
**やること**：画面から実際にデータを作り、編集し、消す。
**なぜ**：scaffold が「作成・表示・編集・削除」を全部つないでいることを確認するため。

ブラウザの一覧ページで:
1. **「New article」** を押す → `title` と `body` を入力 → **「Create Article」**。
2. 一覧に戻り、作った記事の **「Show」「Edit」「Destroy」** を押して挙動を見る。

**成功**：作成・編集・削除がすべて画面から動く。これが **1リソースのCRUD**。
- どの操作がどのURL/アクションに対応するかは → [routing.md](./routing.md)（`resources :articles`）/ [controller.md](./controller.md)

確認できたらサーバを止める（`Ctrl + C`）。
