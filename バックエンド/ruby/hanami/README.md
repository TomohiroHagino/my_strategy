# Hanami

## 一言で
Ruby のモダンな**フルスタック代替フレームワーク**。Rails の「規約・統合・マジック」に対し、**明示性・モジュール性・クリーンアーキテクチャ**を重視。**DI（依存性注入）コンテナが標準**で、ORM は ActiveRecord ではなく **ROM（Ruby Object Mapper）**。dry-rb エコシステムの上に立つ。

## 特徴
- **アクション = 1クラス**（Rails の「1コントローラに複数アクション」ではない）。
- **Slices**：サブアプリケーション単位でモジュール分割。
- **DIコンテナ**：コンポーネントを自動登録し、`Deps[...]` で注入。
- **ROM**：リポジトリ/リレーションで永続化（ActiveRecordと別思想）。
- **dry-rb**：dry-validation（契約）/ dry-types / dry-system。
- **明示的・疎結合**：何がどこに依存しているか追いやすい。

## Rails との違い（ざっくり）
| | Rails | Hanami |
|---|---|---|
| 思想 | 規約・統合・速い立ち上げ | 明示・分離・保守性 |
| アクション | 1コントローラ×多アクション | **1アクション=1クラス** |
| 永続化 | Active Record | **ROM（リポジトリ）** |
| 依存 | 暗黙・グローバル寄り | **DIコンテナ（明示）** |
| 規模感 | 立ち上げ最速 | 大規模で構造を保ちやすい |
| コスト | 情報・人材多い | 学習コスト高・エコシステム小 |
