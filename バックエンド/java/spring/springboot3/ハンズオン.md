# ハンズオン：Spring Boot で `/hello` と `/greet` を動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- Spring Initializr から **curl で雛形 zip を取得**し、`./mvnw spring-boot:run` で起動できる
- `@RestController` で **`/hello` と JSON を返す `/greet`** を作り、`curl` で叩ける
- わざと **ポート8080競合 / Bean が見つからない（@SpringBootApplication の外に置く）を起こして、自分で直せる**
- ここまでやると [getting_started.md](./getting_started.md) / [controller.md](./controller.md) / [ioc_di.md](./ioc_di.md) が「読める」ようになる

**所要時間**：30〜45分（**初回ビルドは依存DLとコンパイルで数分かかります**。ネットワーク必須）
**前提**：**JDK 17 以上**が動くこと（`java -version` で確認）。Maven/Gradle は雛形同梱の wrapper を使うので未導入でOK。

---

## 準備：Java が使えるか確認
```bash
java -version
```
**成功**：`openjdk version "17"` 以上が出る（21でも可）。
**失敗**：
- `command not found` または `17` 未満 → JDK 17+ を入れる（`sdk install java 21-tem`（SDKMAN）等）。Boot 3 は **Java 17未満では起動できない**。

`curl` と `unzip` があるか:
```bash
curl --version >/dev/null && unzip -v >/dev/null && echo "tools ok"
```
**成功**：`tools ok`。**失敗**：足りないツールを入れる（`unzip` が無ければ後述の代替手順あり）。

作業用フォルダ:
```bash
mkdir -p ~/spring-handson && cd ~/spring-handson
```

## ステップ1：Spring Initializr から雛形を取得する
**やること**：`start.spring.io` から「Web スターター入りの最小プロジェクト zip」を curl で落として展開する。
**なぜ**：Spring Boot は「設定より規約」。雛形を生成すれば、起動クラス・ビルド設定・wrapper が一式そろう。→ [getting_started.md](./getting_started.md)

```bash
curl https://start.spring.io/starter.zip \
  -d type=maven-project -d language=java \
  -d bootVersion=3.3.0 -d javaVersion=17 \
  -d dependencies=web \
  -d groupId=com.example -d artifactId=demo -d name=demo \
  -d packageName=com.example.demo \
  -o demo.zip && unzip -o demo.zip -d demo
cd demo
```
**成功**：`demo/` 配下に `pom.xml` `mvnw` `src/main/java/com/example/demo/DemoApplication.java` が出る。
```bash
ls && ls src/main/java/com/example/demo
```
**失敗**：
- zip が0バイト／HTMLが返る → ネットワーク不通。少し待って再実行。
- `unzip: command not found` → 代替：`python3 -c "import zipfile;zipfile.ZipFile('demo.zip').extractall('demo')"`。

---

## ステップ2：そのまま起動して「動く土台」を確認する
**やること**：何も足さずに `./mvnw spring-boot:run` で起動する。
**なぜ**：まず「組込Tomcat入りの実行可能アプリが立ち上がる」状態を体感するため。**初回は依存DLで数分**かかる（2回目以降は速い）。

```bash
./mvnw spring-boot:run
```
**成功**：ASCIIバナーの後、`Tomcat started on port 8080` と `Started DemoApplication in X seconds` が出る。
**失敗**：
- `Permission denied: ./mvnw` → `chmod +x mvnw` してから再実行。
- `Web server failed to start. Port 8080 was already in use.` → ステップ5でわざと起こす内容。今は別プロセスを止めるか、`./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8081` で起動。

まだ `/hello` は作っていないので、別タブで叩くと 404 が返る（正常）。**Ctrl+C で一度止める**。
```bash
curl -i http://localhost:8080/hello    # 今は 404 Not Found（コントローラ未作成のため）
```

## ステップ3：`@RestController` で `/hello` を作る
**やること**：文字列を返す最小コントローラを足す。
**なぜ**：`@RestController` ＝「HTTPの受付。戻り値をそのままレスポンスボディにする」。Spring の入口。→ [controller.md](./controller.md)

`src/main/java/com/example/demo/HelloController.java` を**新規作成**する:
```java
// src/main/java/com/example/demo/HelloController.java
package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController                       // このクラスはHTTPの受付係。戻り値=レスポンス本文
public class HelloController {

    @GetMapping("/hello")             // GET /hello
    public String hello() {
        return "Hello Spring Boot 3";
    }
}
```
> **置き場所が重要**：`DemoApplication.java` と**同じ `com.example.demo` パッケージ（か、その配下）**に置く。理由はステップ5で体験する。

起動して確認:
```bash
./mvnw spring-boot:run
```
```bash
# 別タブで（サーバは起動したまま）
curl -s http://localhost:8080/hello
```
**成功**：`Hello Spring Boot 3` が返る。
**失敗**：404 → クラスの置き場所（パッケージ）か `@RestController` / `@GetMapping` の付け忘れ。

## ステップ4：JSON を返す `/greet?name=...` を作る
**やること**：クエリパラメータを受け取り、Map を返して JSON にする。
**なぜ**：`@RestController` は戻り値が POJO/Map なら **Jackson が自動でJSON化**する。これが REST API の基本形。→ [controller.md](./controller.md)

`HelloController.java` に**メソッドを追加**する:
```java
    // import を追加
    // import org.springframework.web.bind.annotation.RequestParam;
    // import java.util.Map;

    @GetMapping("/greet")             // GET /greet?name=Taro
    public Map<String, String> greet(@RequestParam(defaultValue = "world") String name) {
        return Map.of("message", "Hello, " + name + "!");
    }
```
import 2行をファイル冒頭の import 群に足す:
```java
import org.springframework.web.bind.annotation.RequestParam;
import java.util.Map;
```
DevToolsを入れていないので、**一度 Ctrl+C で止めて起動し直す**:
```bash
./mvnw spring-boot:run
```
```bash
curl -s "http://localhost:8080/greet?name=Taro"
curl -s "http://localhost:8080/greet"
```
**成功**：
- `?name=Taro` → `{"message":"Hello, Taro!"}`
- パラメータ無し → `{"message":"Hello, world!"}`（`defaultValue` が効く）
→ **これが「クエリ受取 → Map → 自動JSON化」が繋がった証拠**。
**失敗**：500 → import 不足（`RequestParam` / `Map`）。ログを見て不足 import を足す。

## ステップ5：わざと「ポート競合」「Beanが見つからない」を起こして直す
**なぜ**：この2つは Spring 初心者が必ず出会う。「自分で起こして直す」と一生忘れない。

### 5-1. ポート8080競合
**いまサーバを起動したまま**、もう1つ別タブで同じアプリを起動してみる:
```bash
./mvnw spring-boot:run     # 2つ目の起動
```
**結果**：`Web server failed to start. Port 8080 was already in use.` で2つ目が落ちる。
**読み解き**：8080 は1プロセスしか掴めない。すでに掴んでいるプロセスがいる、という意味。

**直す（2通り）**：
```bash
# A) 犯人を探して止める（mac/Linux）
lsof -i :8080          # PID を確認
kill <PID>             # そのPIDを止める

# B) ぶつからないポートで起動する
./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8081
curl -s http://localhost:8081/hello
```
**成功**：B なら `8081` で `Hello Spring Boot 3` が返る。→ **「ポートは1プロセス占有」を体験**。

### 5-2. Bean が見つからない（component scan の範囲外に置く）
すべて Ctrl+C で止める。`HelloController.java` の**パッケージ行だけ**を、起動クラスの**外側**に変える:
```java
package com.other.outside;            // ← com.example.demo の外。わざとスキャン対象外にする
```
そのままだと import 解決でも崩れるので、ここでは**パッケージ宣言だけ変えて挙動を見る**のが目的。起動する:
```bash
./mvnw spring-boot:run
```
```bash
curl -i http://localhost:8080/hello
```
**結果**：起動はするが `/hello` は **404 Not Found**。
**読み解き**：`@SpringBootApplication`（＝ `DemoApplication`）は **自分のいるパッケージ配下だけ**を component scan する。`com.other.outside` はその外なので、`@RestController` が **Bean として登録されず**、ルートが生えない。「クラスは書いたのに 404／Beanが見つからない」の典型原因。

**直す**：パッケージ宣言を起動クラスと同じ配下に戻す:
```java
package com.example.demo;             // ← 元に戻す（スキャン対象内）
```
```bash
./mvnw spring-boot:run
curl -s http://localhost:8080/hello
```
**成功**：また `Hello Spring Boot 3` が返る。→ **「Beanは @SpringBootApplication 配下しか拾われない」が腹落ちした**。
