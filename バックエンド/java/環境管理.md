# JVM 環境管理 — SDKMAN! の使い方

> **SDKMAN!** は JVM 系 SDK（**Java / Kotlin / Scala / Groovy / Gradle / Maven / sbt / Spring Boot CLI** など）の**複数バージョンを並行インストールし、コマンド一発で切り替える**ツール。
> Python の [../python/環境管理.md](../python/環境管理.md) と同じ「**何を・どの層で隔離するか**」の話の JVM 版。nvm(Node) / pyenv(Python) の JVM 版だと思えばよい。

---

## 0. ひとことで言うと
- Java は **バージョン（8 / 11 / 17 / 21…）×ディストリビューション（Temurin / Zulu / GraalVM / Corretto…）** を使い分ける世界。手で `JAVA_HOME` と `PATH` を張り替えるのは地獄。
- SDKMAN! が `~/.sdkman/` 配下に各SDKを置き、**シンボリックリンクの差し替えで一瞬で切替**してくれる。
- **対象OS**：macOS / Linux / **WSL**（Unix系）。素のWindows(CMD/PowerShell)は非対応 → **WSL か Git Bash** を使う。

```
        Java 8        Java 17 (Temurin)     Java 21 (GraalVM)
          │                  │                    │
          └────────── SDKMAN! が一元管理 ──────────┘
                   sdk use java 21...  ← 一瞬で切替
```

## 1. インストール
**前提**：`curl` / `zip` / `unzip` / `bash`（or `zsh`）。
```bash
curl -s "https://get.sdkman.io" | bash          # 取得＆インストール
source "$HOME/.sdkman/bin/sdkman-init.sh"        # 今のシェルに読み込む（初回は必須）
sdk version                                       # 入ったか確認
```
- **成功**：`SDKMAN x.x.x` とバージョンが出る。
- **失敗の原因**：`sdk: command not found` → `source` を忘れている（新しいシェルでは自動で読まれるが、初回や設定によっては手動 source）。`unzip` 無し → OSに入れる。

## 2. いちばん使うコマンド（Java を例に）
```bash
sdk list java                 # 入手可能なJavaの一覧（ベンダー別・installed/local表示つき）
sdk install java 21.0.5-tem   # Temurin 21 を入れる（識別子は list からコピペ）
sdk install java 17.0.13-tem  # 別バージョンも並行で入れられる

sdk use java 17.0.13-tem      # ★今のシェルだけ切替（タブを閉じると戻る）
sdk default java 21.0.5-tem   # ★既定にする（以後すべてのシェルで既定）
sdk current java              # 今どれが有効か
sdk current                   # 全SDKの現在バージョン一覧

sdk upgrade java              # より新しいパッチが出ていれば案内
sdk uninstall java 17.0.13-tem
sdk home java 21.0.5-tem      # そのJDKの絶対パスを表示（IDE/JAVA_HOME設定に使う）
```
> **`use` / `default` / `env` の違い（最重要）**
> - `sdk use` … **そのシェルだけ**一時的に切替（新タブでは元に戻る）。
> - `sdk default` … **マシン全体の既定**を変える（永続）。
> - `sdk env` … **プロジェクト単位**で切替（後述 `.sdkmanrc`）。

## 3. Java 識別子（ベンダー）の読み方
`21.0.5-tem` の `-xxx` がディストリビューション。代表：
| サフィックス | ディストリ | ひとこと |
|---|---|---|
| `-tem` | Eclipse Temurin（Adoptium） | 迷ったらこれ。広く使われる無償JDKの定番 |
| `-zulu` | Azul Zulu | 長期サポート・幅広いバージョン |
| `-amzn` | Amazon Corretto | AWS製・長期サポート |
| `-graal` / `-graalce` | GraalVM（Oracle / CE） | **native-image**（ネイティブ実行ファイル化）用 |
| `-librca` | BellSoft Liberica | JavaFX同梱版などもある |
| `-ms` | Microsoft Build of OpenJDK | |
| `-oracle` | Oracle JDK | ライセンス条件に注意 |
> 何を選ぶか：通常開発は **Temurin**。ネイティブ化したいなら **GraalVM**。会社/クラウド指定があればそれに従う。

## 4. Java 以外も同じノリ（候補=candidate）
```bash
sdk install gradle 8.10        # Gradle
sdk install maven 3.9.9        # Maven
sdk install kotlin             # Kotlin コンパイラ（最新）
sdk install scala 3.5.2        # Scala
sdk install springboot         # Spring Boot CLI
sdk list gradle                # 候補一覧（どの候補でも list が効く）
```
> 候補は他にも sbt / groovy / micronaut / quarkus / jbang など多数。`sdk list` で全候補を表示。

## 5. プロジェクト単位でバージョンを固定（`.sdkmanrc`）← 実務の肝
nvm の `.nvmrc`、pyenv の `.python-version` に相当。**チームで「このリポジトリは Java 21 + Gradle 8.10」を強制**できる。
```bash
cd my-project
sdk env init           # 現在のバージョンで .sdkmanrc を生成
```
```ini
# .sdkmanrc（リポジトリにコミットする）
java=21.0.5-tem
gradle=8.10
```
```bash
sdk env                # .sdkmanrc の内容に切替（そのシェル）
sdk env install        # .sdkmanrc にあるが未インストールの版を入れる（新メンバーの初手）
sdk env clear          # 切替を解除（既定へ戻す）
```
- **`cd` で自動切替**したいなら、設定で有効化：`~/.sdkman/etc/config` の `sdkman_auto_env=true`（ディレクトリに入ると自動で `sdk env` 相当）。

## 6. 手元の自前JDKを登録する（ローカルインストール）
SDKMAN管理外のJDK（社内配布・手動DL）も登録できる：
```bash
sdk install java 21-corp /opt/jdk/corp-21   # ラベル 21-corp としてパスを登録
sdk use java 21-corp
```

## 7. 更新・メンテ
```bash
sdk selfupdate         # SDKMAN本体を更新
sdk update             # 入手可能バージョンのリストを更新（list の鮮度）
sdk upgrade            # 入れているSDKで古いものを一覧
sdk flush              # キャッシュ等の掃除（archives/temp/metadata）
```

## 8. 仕組み（PATH の張り替え）
```
~/.sdkman/candidates/java/
   ├── 17.0.13-tem/        ← 実体
   ├── 21.0.5-tem/         ← 実体
   └── current  ──────────► 21.0.5-tem（シンボリックリンク）
PATH に ~/.sdkman/candidates/java/current/bin を通している
→ current の張り替え＝バージョン切替。JAVA_HOME も SDKMAN が面倒を見る。
```

## 9. 他ツールとの棲み分け
| ツール | 守備範囲 | いつ |
|---|---|---|
| **SDKMAN!** | **JVM系SDK全部**（Java/Kotlin/Gradle/Maven/Scala…） | JVM開発の標準。これ1本で足りることが多い |
| jenv | **Javaのバージョン切替だけ**（インストールはしない） | 既に入れたJDKをディレクトリ単位で切替たい時 |
| asdf / mise | **多言語**（Node/Python/Ruby/Java…を1つで） | 複数言語のバージョンを統一ツールで管理したい時 |
| Docker | OS・依存まるごと | 「どこでも同じ」を完全再現（→ [../../インフラ/docker/](../../インフラ/docker/)） |
| brew/apt 直 | システムに1バージョン | 切替不要・固定で良い軽い用途 |
> 思想は [../python/環境管理.md](../python/環境管理.md) と同じ：**SDKMAN=「JVMの依存だけ」を分ける軽い隔離、Docker=「環境まるごと」固定**。競合しないし併用する。

## 10. CI / Docker での使い方
- **CI**：非対話で入れる。`.sdkmanrc` を置いて `sdk env install` が手堅い。
```bash
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk env install          # .sdkmanrc の版を入れて切替
./gradlew build
```
- **Docker**：ビルドの再現性が最優先なら、**SDKMANよりベースイメージ（`eclipse-temurin:21` 等）でJDKを固定**する方が軽い。SDKMANはローカル開発・複数版切替向き。

## ハマりどころ / アンチパターン
- **`source` 忘れ**：インストール直後の同じシェルでは手動 `source ...sdkman-init.sh`。新しいシェルなら自動で読まれる（`~/.bashrc`/`~/.zshrc` に追記済み）。
- **IDE/非ログインシェルがPATHを拾わない**：IntelliJ等は SDKMAN の PATH を見ないことがある。**`sdk home java 21.0.5-tem` で出たパスをIDEのSDK設定に直接登録**する。
- **`sdk use` を永続と勘違い**：`use` はそのシェルだけ。永続は `default`、プロジェクト固定は `.sdkmanrc`。
- **`JAVA_HOME` を手で固定したまま**：別ツールが古い `JAVA_HOME` を見て食い違う。SDKMANに任せるなら手動設定は外す（必要なら `export JAVA_HOME=$(sdk home java <ver>)`）。
- **素のWindowsで動かそうとする**：CMD/PowerShellは非対応。**WSL** か Git Bash で。
- **GradleはWrapper優先**：ビルドはリポジトリの `./gradlew`（=`gradle-wrapper.properties` の版）が正。SDKMANの `gradle` はCLI操作・新規プロジェクト作成用と割り切る。
- **ベンダー取り違え**：`-tem` と `-graalce` では用途が違う（後者はnative-image用）。識別子は `sdk list java` からコピペして間違えない。
