# ハンズオン：FastAPI で「APIを叩いて、Swaggerで試して、422を直す」まで

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- venv を作り、FastAPI と Uvicorn を入れて**最小APIを起動できる**
- **`/docs`（Swagger UI）**でAPIをブラウザから叩ける
- **Pydanticモデル**でリクエストの型を宣言し、**自動バリデーション**を体験できる
- わざと **型に合わない値を送って 422 を起こし、自分で直せる**
- ここまでやると [getting_started.md](./getting_started.md) / [pydantic_models.md](./pydantic_models.md) / [openapi_docs.md](./openapi_docs.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Python 3.9+ が動くこと（`python --version` で確認）。それ以外の知識は不要。

## 準備：Python が使えるか確認
```bash
python --version
```
**成功**：`Python 3.9.x` 以上が出る。
**失敗**：`command not found` → `python3 --version` を試す。出たら以降 `python` を `python3` に読み替え。

作業用フォルダを作る:
```bash
mkdir -p ~/fastapi-handson && cd ~/fastapi-handson
```

## ステップ1：仮想環境を作って FastAPI を入れる
**やること**：このプロジェクト専用の venv を作り、FastAPI 一式を入れる。
**なぜ**：グローバルに入れると他プロジェクトと衝突する。隔離するのが Python の鉄則。

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
```
**成功**：プロンプト先頭が `(.venv)` になる。

```bash
pip install fastapi uvicorn
python -c "import fastapi, uvicorn; print('ok')"
```
**成功**：`ok` が出る。
**失敗**：`(.venv)` が出ていない状態で入れた → グローバルに入る。`source .venv/bin/activate` してから入れ直す。

---

## ステップ2：最小APIを書いて起動する
**やること**：1つだけエンドポイントを持つ `main.py` を作り、Uvicorn で起動する。
**なぜ**：まず「Python のコードが HTTP で叩ける」状態を最短で作るため。`app = FastAPI()` がアプリ本体、`@app.get(...)` でパスに関数を紐づける。

`main.py` を次の内容で作る:
```python
# main.py
from fastapi import FastAPI

app = FastAPI()                       # アプリ本体（ASGIアプリ）

@app.get("/")                         # GET /
def read_root():
    return {"hello": "world"}         # dict を返すと自動でJSON化される
```

起動する:
```bash
uvicorn main:app --reload
```
- `main:app` ＝「**main.py の中の app という変数**」を指す。`--reload` は保存即反映（開発用）。

**成功**：`Uvicorn running on http://127.0.0.1:8000` が出る。別タブで:
```bash
curl -s http://127.0.0.1:8000/
```
→ `{"hello":"world"}` が返る。
**失敗**：
- `Error loading ASGI app. Could not import module "main"` → `main.py` のあるフォルダで起動していない。`ls` で `main.py` があるか確認。
- `address already in use` → `uvicorn main:app --reload --port 8001` で別ポート。

> 以降、Uvicorn は**起動したまま**で進めます（`--reload` なので保存すれば自動反映）。

## ステップ3：`/docs`（Swagger UI）で叩く
**やること**：自動生成されたAPIドキュメントをブラウザで開く。
**なぜ**：FastAPI 最大の売りは**コードから仕様書 兼 動作確認ツールが自動で出る**こと。curl の代わりにここから試せる。→ [openapi_docs.md](./openapi_docs.md)

ブラウザで **http://127.0.0.1:8000/docs** を開く。
**成功**：Swagger UI が出て `GET /` が一覧にある。`GET /` を開いて「Try it out」→「Execute」で `{"hello":"world"}` が返る。
**失敗**：真っ白／404 → Uvicorn が起動しているか（ステップ2のログ）を確認。

> 読みやすい版は **http://127.0.0.1:8000/redoc** にもある。

## ステップ4：Pydanticモデルで型を宣言する（本題）
**やること**：POSTで受け取るリクエストボディの形を Pydantic のクラスで宣言し、エンドポイントを足す。
**なぜ**：型を書くだけで**検証・変換・ドキュメント**が自動で付く。これが FastAPI の核。→ [pydantic_models.md](./pydantic_models.md)

`main.py` を次の内容に**書き換える**:
```python
# main.py
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):                # リクエストの形を宣言
    name: str                         # 文字列・必須
    price: float                      # 数値・必須
    in_stock: bool = True             # 真偽・省略可（既定 True）

@app.get("/")
def read_root():
    return {"hello": "world"}

@app.post("/items")                   # POST /items
def create_item(item: Item):          # 引数の型に Item を指定 = 自動で検証・変換
    return {"received": item, "price_with_tax": item.price * 1.1}
```
保存すると Uvicorn が自動リロードする（ログに `Reloading...` が出る）。

正しいリクエストを送ってみる:
```bash
curl -s -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "pen", "price": 100}'
```
**成功**：`{"received":{"name":"pen","price":100.0,"in_stock":true},"price_with_tax":110.0...}` が返る。
→ `in_stock` を送っていないのに既定値 `true` が入り、`price` が `100.0`（float）に変換されている。**これが「型が仕様になる」証拠**。
**失敗**：`Method Not Allowed` → `-X POST` を付け忘れ、または URL の typo。

`/docs` を再読込すると **`POST /items` が増えていて**、スキーマ（name/price/in_stock）も表示される。コードを書いただけで仕様書が更新される。

## ステップ5：わざと型不一致で 422 を起こして、直す
**なぜ**：422（Unprocessable Entity）は FastAPI のバリデーションが弾いたときに必ず出るステータス。「自分で起こして直す」と一生忘れない。

`price` に**数値でない文字列**を入れて送る:
```bash
curl -s -i -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "pen", "price": "高い"}'
```
**結果**：先頭行に `HTTP/1.1 422 Unprocessable Entity`。本文に:
```json
{"detail":[{"type":"float_parsing","loc":["body","price"],"msg":"Input should be a valid number...","input":"高い"}]}
```
**読み解き**：`loc: ["body","price"]` ＝「**body の price が悪い**」、`msg` ＝「数値であるべき」。FastAPI が**ハンドラに入る前に**型を検証し、合わなければ自動で 422 を返してくれている。自分で `if` 検証を書かなくてよい。

必須項目を**落として**も試す:
```bash
curl -s -i -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"price": 100}'
```
**結果**：また `422`。`loc: ["body","name"]`・`msg: "Field required"`（name が必須なのに無い）。

**直す**：型と必須を満たす正しい値を送る:
```bash
curl -s -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "pen", "price": 100}'
```
**成功**：200 で `price_with_tax` 入りの JSON が返る。→ **422の原因＝送ったデータが型/必須に合っていない、を体験で理解できた**。

> 実務の 422 も原因は同じ系統：必須欠落・型違い・範囲外。`detail` の `loc` を見れば「どのフィールドが悪いか」が即わかる。→ [validation.md](./validation.md)
