# ハンズオン：CodeIgniter 4 で 0 からコントローラを1つ動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [controllers.md](./controllers.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- `composer create-project` でアプリを作り、`spark serve` で**ブラウザに表示**できる
- コントローラとルートを1つ書いて、URL に応答できる
- わざと **ルート未設定の 404** と **baseURL 未設定によるリンク崩れ** を起こして、自分で直せる
- ここまでやると [getting_started.md](./getting_started.md) / [routing.md](./routing.md) / [controllers.md](./controllers.md) / [config_env.md](./config_env.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Docker が動くこと（PHP / Composer を自分で入れる必要はありません）

---

## 準備：Docker が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（またはdockerサービス）が起動していない。起動してから再実行。

作業用フォルダを作る:
```bash
mkdir -p ~/ci4-handson && cd ~/ci4-handson
```

---

## ステップ1：PHP + Composer が入ったコンテナに入る
**やること**：PHP と Composer が最初から入った公式イメージのコンテナに入り、その中で作業する。
**なぜ**：自分のPCに PHP や Composer を入れなくても、コンテナの中なら同じ環境がすぐ手に入るため。CI4 は **PHP 8.1 以上**が前提だが、このイメージは満たしている。
```bash
docker run -it --name ci4-dev \
  -p 8080:8080 \
  -v "$PWD:/work" -w /work \
  composer:2 bash
```
- `composer:2` は PHP 8 + Composer 入りの公式イメージ。
- `-p 8080:8080`＝PCの8080番をコンテナの8080番に繋ぐ（`spark serve` の既定ポート）。
- `-v "$PWD:/work" -w /work`＝今のフォルダをコンテナの `/work` に貸して、そこを作業場所にする。

**成功**：プロンプトが `xxxx:/work#` に変わる。`php -v` で `PHP 8.1` 以上が出る。
**失敗**：`port is already allocated` → 8080番が使用中。`exit` して `-p 8081:8080` に変えて再実行（その場合ブラウザは http://localhost:8081）。

> **以降の `#` で始まるコマンドは、すべてこのコンテナの中で実行**します。

CI4 が必要とする拡張を確認:
```bash
php -m | grep -iE "intl|mbstring"
```
**成功**：`intl` `mbstring` が出る。
**失敗**：出ないものがあれば `docker-php-ext-install intl` のように追加（composer公式イメージなら通常は揃っています）。

## ステップ2：アプリを作って起動し、ブラウザで見る
**やること**：`composer create-project codeigniter4/appstarter` で雛形を生成し、`spark serve` で起動する。
**なぜ**：「CI4 アプリが起動してブラウザに出る」状態をまず目で確認するため。

アプリを生成:
```bash
composer create-project codeigniter4/appstarter myapp
cd myapp
```
- `appstarter` は CI4 公式の雛形テンプレート。`app/Config/Routes.php` にルート、`app/Controllers/` にコントローラを置く。
- 生成時に `Home.php`（サンプルコントローラ）と、トップにマッピングするルートが既に入っている。

環境ファイルを用意:
```bash
cp env .env
```
- `env`（ドットなしの雛形）を `.env`（実体）にコピーする。**この `cp env .env` を忘れると設定が反映されない**ので注意。

サーバを起動（コンテナ外から繋がるよう全アドレスで待ち受ける）:
```bash
php spark serve --host 0.0.0.0 --port 8080
```
- `--host 0.0.0.0`＝コンテナの外（あなたのブラウザ）からアクセスできるようにする。**これを忘れるとブラウザから繋がらない**。

ブラウザで **http://localhost:8080** を開く。
**成功**：CodeIgniter の **Welcome ページ**（"Welcome to CodeIgniter" の画面）が出る。
**失敗**：
- ページが出ない → `--host 0.0.0.0` を付け忘れていないか確認。
- 真っ白 → `writable/` の権限不足。`Ctrl + C` で止めて `chmod -R 777 writable/` してから再起動。→ [getting_started.md](./getting_started.md)

確認できたらサーバを止める（`Ctrl + C`）。

## ステップ3：コントローラとルートを1つ書く（本題）
**やること**：`/hello` に応答するコントローラを作り、ルートを定義する。
**なぜ**：CI4 の流れ「ルート → コントローラ → レスポンス」を体験するため。

### 3-1. コントローラを作る
```bash
cat > app/Controllers/Hello.php <<'EOF'
<?php

namespace App\Controllers;

class Hello extends BaseController
{
    public function index()
    {
        return 'Hello from a CodeIgniter controller!';
    }
}
EOF
```
- `namespace App\Controllers` ＋ `extends BaseController` が CI4 のコントローラの基本形。メソッドの戻り値（文字列）がそのままレスポンスになる。→ [controllers.md](./controllers.md)

### 3-2. ルートを定義
`app/Config/Routes.php` の末尾近くに1行追加する:
```bash
cat >> app/Config/Routes.php <<'EOF'

// /hello で来たら Hello コントローラの index を呼ぶ
$routes->get('hello', 'Hello::index');
EOF
```
- `$routes->get('hello', 'Hello::index')` ＝「`/hello` で来たら `Hello` コントローラの `index` を呼べ」。`::` の左がコントローラ、右がメソッド。→ [routing.md](./routing.md)

### 3-3. 起動して確認
```bash
php spark serve --host 0.0.0.0 --port 8080
```
ブラウザで **http://localhost:8080/hello** を開く。
**成功**：`Hello from a CodeIgniter controller!` が表示される。→ ルートとコントローラが1本つながった。
**失敗**：404 が出る → 次のステップで扱う（むしろ好都合）。

ルート一覧で確認することもできる（別ターミナルで同じコンテナに入る）:
```bash
docker exec -it ci4-dev php spark routes
```
→ `GET hello` の行が出ていれば登録成功。

## ステップ4：わざと「ルート未設定の 404」と「baseURL 未設定のリンク崩れ」を起こして、直す
**なぜ**：どちらも CI4 でよく出会う失敗。**自分で起こして直す**と一生忘れない。

### 4-1. ルート未設定の 404
サーバを止めて（`Ctrl + C`）、**先ほど足したルート行をわざと消す**:
```bash
sed -i "/\$routes->get('hello', 'Hello::index');/d" app/Config/Routes.php
php spark serve --host 0.0.0.0 --port 8080
```
ブラウザで **http://localhost:8080/hello** を開く。
**結果**：`404 - Page Not Found`（`Controller or its method is not found` 等）が表示される。
**読み解き**：コントローラ `Hello.php` は存在するが、**「`/hello` でそれを呼べ」というルートが無い**。CI4 は既定で自動ルーティングがオフなので、ルートを書かないと URL がコントローラに繋がらない。

直す（ルートを書き戻す）:
```bash
cat >> app/Config/Routes.php <<'EOF'

$routes->get('hello', 'Hello::index');
EOF
```
サーバを止めて（`Ctrl + C`）再起動し、**http://localhost:8080/hello** を再読み込み。
**成功**：また `Hello from a CodeIgniter controller!` が返る。→ 404の原因＝「ルート定義漏れ」を体験で理解できた。→ [routing.md](./routing.md)

### 4-2. baseURL 未設定によるリンク崩れ
**やること**：`base_url()` でリンクを作るページで、`app.baseURL` を空にして崩れを見る。
**なぜ**：`app.baseURL` 未設定は CI4 のあるある。CSS/JS リンクやリダイレクトが崩れる原因になる。

確認用に、`base_url()` を出すルートを足す:
```bash
cat >> app/Config/Routes.php <<'EOF'

$routes->get('link', static function () {
    return 'baseURL = [' . base_url() . ']';
});
EOF
```
`.env` の `app.baseURL` を**わざと未設定のまま**にしておく（雛形ではコメントアウトされていて無効）。サーバを起動:
```bash
php spark serve --host 0.0.0.0 --port 8080
```
ブラウザで **http://localhost:8080/link** を開く。
**結果**：`baseURL = [...]` の中身が空、もしくは `http://localhost/`（意図と違うURL）になる。実アプリでは CSS/JS の `<link>` や `redirect()` がこのズレで崩れる。
**読み解き**：`app.baseURL` を設定しないと、`base_url()` が正しいベースURLを組み立てられない。

直す（`.env` に baseURL を設定。**末尾スラッシュ必須**）:
```bash
echo "app.baseURL = 'http://localhost:8080/'" >> .env
```
サーバを止めて（`Ctrl + C`）再起動し、**http://localhost:8080/link** を再読み込み。
**成功**：`baseURL = [http://localhost:8080/]` と、設定どおりに出る。→ baseURL の役割と「末尾 `/` 必須」を体験で理解できた。→ [config_env.md](./config_env.md)

## 片付け
サーバを止めて（`Ctrl + C`）、コンテナから出る:
```bash
exit
```
コンテナを消す（作ったファイルは `~/ci4-handson/myapp` に残ります）:
```bash
docker rm -f ci4-dev
# フォルダごと消すなら: rm -rf ~/ci4-handson
```
