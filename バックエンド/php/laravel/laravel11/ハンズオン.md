# ハンズオン：Laravel 11 で 0 から JSON を返すまで

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [controller.md](./controller.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- `composer create-project` でアプリを作り、`php artisan serve` で**ブラウザに表示**できる
- ルートとコントローラを足して、`/api/hello` で **JSON を返せる**
- `php artisan migrate`（SQLite）で**テーブルを作れる**
- わざと **APP_KEY 未設定エラー** と **migrate 前アクセスのエラー** を起こして、自分で直せる
- ここまでやると [getting_started.md](./getting_started.md) / [routing.md](./routing.md) / [controller.md](./controller.md) / [config_env.md](./config_env.md) が「読める」ようになる

**所要時間**：25〜35分　**前提**：Docker が動くこと（PHP / Composer を自分で入れる必要はありません）

---

## 準備：Docker が使えるか確認
```bash
docker version
```
**成功**：`Client:` と `Server:` の両方にバージョンが出る。
**失敗**：`Cannot connect to the Docker daemon` → Docker Desktop（またはdockerサービス）が起動していない。起動してから再実行。

作業用フォルダを作る:
```bash
mkdir -p ~/laravel-handson && cd ~/laravel-handson
```

---

## ステップ1：PHP + Composer が入ったコンテナに入る
**やること**：PHP と Composer が最初から入った公式イメージのコンテナに入り、その中で作業する。
**なぜ**：自分のPCに PHP や Composer を入れなくても、コンテナの中なら同じ環境がすぐ手に入るため。Laravel 11 は **PHP 8.2 以上必須**だが、このイメージは満たしている。
```bash
docker run -it --name laravel-dev \
  -p 8000:8000 \
  -v "$PWD:/work" -w /work \
  composer:2 bash
```
- `composer:2` は PHP 8 + Composer 入りの公式イメージ。
- `-p 8000:8000`＝PCの8000番をコンテナの8000番に繋ぐ（`artisan serve` の既定ポート）。
- `-v "$PWD:/work" -w /work`＝今のフォルダをコンテナの `/work` に貸して、そこを作業場所にする。

**成功**：プロンプトが `xxxx:/work#` に変わる。`php -v` で `PHP 8.2` 以上が出る。
**失敗**：`port is already allocated` → 8000番が使用中。`exit` して `-p 8001:8000` に変えて再実行（その場合ブラウザは http://localhost:8001）。

> **以降の `#` で始まるコマンドは、すべてこのコンテナの中で実行**します。

SQLite拡張を確認（Laravel 11 既定DBに必要）:
```bash
php -m | grep -i sqlite
```
**成功**：`pdo_sqlite` `sqlite3` が出る。
**失敗**：何も出ない → `docker-php-ext-install pdo_sqlite` を実行（composer公式イメージなら通常は既に入っています）。

---

## ステップ2：アプリを作って起動し、ブラウザで見る
**やること**：`composer create-project` で雛形を生成し、`php artisan serve` で起動する。
**なぜ**：「Laravel アプリが起動してブラウザに出る」状態をまず目で確認するため。

アプリを生成:
```bash
composer create-project laravel/laravel myapp
cd myapp
```
- `myapp` がアプリ名。Laravel 11 はスリム骨格で、`app/Http/Kernel.php` は無く、設定は `bootstrap/app.php` に集約されている。
- `.env` は生成時に自動コピーされ、`APP_KEY` も通常は自動生成される。

**成功**：`myapp/` フォルダができ、最後まで処理が走る。
**失敗**：`Could not find...` → ネットワーク未接続。接続を確認して再実行。

> ここで **わざと先にブラウザを見て、APP_KEYエラーを体験**します（次のステップ）。
> まず `.env` の `APP_KEY` を**わざと空にして**、エラーを起こします。

`APP_KEY` を空にする（後で直します）:
```bash
sed -i 's/^APP_KEY=.*/APP_KEY=/' .env
```

サーバを起動（コンテナ外から繋がるよう全アドレスで待ち受ける）:
```bash
php artisan serve --host 0.0.0.0 --port 8000
```
- `--host 0.0.0.0`＝コンテナの外（あなたのブラウザ）からアクセスできるようにする。**これを忘れるとブラウザから繋がらない**。

---

## ステップ3：わざと「APP_KEY 未設定」のエラーを起こして、直す
**なぜ**：`APP_KEY` 漏れは新規参画時に必ず出会う失敗。**自分で起こして直す**と一生忘れない。

ブラウザで **http://localhost:8000** を開く。
**結果**：`No application encryption key has been specified.` というエラー画面が出る。
**読み解き**：`APP_KEY` は暗号化・セッション・クッキーの前提。これが空だと暗号化系がすべて落ちる。

サーバを止めて（`Ctrl + C`）、キーを生成:
```bash
php artisan key:generate
```
**成功**：`Application key set successfully.` が出て、`.env` の `APP_KEY=base64:...` が埋まる。
**失敗**：`.env` が無いと言われる → `cp .env.example .env` をしてから再実行。

もう一度サーバを起動して、画面を開き直す:
```bash
php artisan serve --host 0.0.0.0 --port 8000
```
ブラウザで **http://localhost:8000** を再読み込み。
**成功**：今度は **Laravel の初期ページ**（ロゴ入りのウェルカム画面）が出る。→ APP_KEY の役割を体験で理解できた。

> 新規参画時の儀式は `composer install` → `cp .env.example .env` → `php artisan key:generate` → `php artisan migrate` の順。これでだいたい動く。→ [getting_started.md](./getting_started.md) / [config_env.md](./config_env.md)

確認できたらサーバを止める（`Ctrl + C`）。

---

## ステップ4：ルートとコントローラを足して JSON を返す（本題）
**やること**：`/api/hello` に応答するルートと、それを処理するコントローラを書く。
**なぜ**：Laravel の流れ「ルート → コントローラ → レスポンス」を体験するため。

### 4-1. API ルートを使えるようにする
Laravel 11 は既定で `routes/api.php` が**無い**ので、入れる:
```bash
php artisan install:api
```
**成功**：`routes/api.php` が作られる（途中で migrate するか聞かれたら `no` でOK。後でやります）。

### 4-2. コントローラを生成
```bash
php artisan make:controller HelloController
```
**成功**：`app/Http/Controllers/HelloController.php` が作られる。

中身を書き換えて、JSON を返すメソッドを入れる:
```bash
cat > app/Http/Controllers/HelloController.php <<'EOF'
<?php

namespace App\Http\Controllers;

class HelloController extends Controller
{
    public function index()
    {
        return response()->json([
            'message' => 'Hello, JSON!',
            'framework' => 'Laravel',
        ]);
    }
}
EOF
```
- `response()->json([...])` ＝配列を JSON にして返す（`Content-Type: application/json` も付く）。

### 4-3. ルートを定義
`routes/api.php` に1行追加する:
```bash
cat > routes/api.php <<'EOF'
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\HelloController;

Route::get('/hello', [HelloController::class, 'index']);
EOF
```
- `Route::get('/hello', [HelloController::class, 'index'])` ＝「`/api/hello` で来たら HelloController の index を呼べ」。`api.php` のルートは自動で `/api` が前に付く。→ [routing.md](./routing.md)

### 4-4. 起動して確認
```bash
php artisan serve --host 0.0.0.0 --port 8000
```
別ターミナルで同じコンテナに入って確認:
```bash
docker exec -it laravel-dev curl -s http://localhost:8000/api/hello
```
**成功**：`{"message":"Hello, JSON!","framework":"Laravel"}` が返る。→ ルートとコントローラが1本つながった。
**失敗**：`404` が返る → ルートのパス（`/api/hello`）か、`install:api` を実行したか確認。`php artisan route:list` でルート一覧を見る。

## ステップ5：わざと「migrate 前アクセス」のエラーを起こして、直す
**なぜ**：「テーブルを作る前にDBを使う」のは初心者が必ずやる失敗。**自分で起こして直す**と一生忘れない。

Laravel 11 の初期ユーザー一覧用ルートを使うため、まず**わざと migrate せずに**DBを使うルートを足す。サーバを止めて（`Ctrl + C`）追記:
```bash
cat >> routes/api.php <<'EOF'

Route::get('/users', function () {
    return \App\Models\User::all();
});
EOF
```
SQLite ファイルだけ作る（**テーブルはまだ作らない**）:
```bash
touch database/database.sqlite
php artisan serve --host 0.0.0.0 --port 8000
```
別ターミナルで叩く:
```bash
docker exec -it laravel-dev curl -s http://localhost:8000/api/users
```
**結果**：`SQLSTATE[HY000]: ... no such table: users` を含むエラーが返る。
**読み解き**：`users` テーブルを作るマイグレーションは雛形に入っているが、**まだ実行していない**。だからテーブルが無くてエラーになる。

サーバを止めて（`Ctrl + C`）、マイグレーションを実行:
```bash
php artisan migrate
```
**成功**：`Migrating: ..._create_users_table` → `DONE` のような行が出る（`users` テーブルが作られた）。
**失敗**：`database does not exist` → `touch database/database.sqlite` を忘れている。作ってから再実行。

もう一度サーバを起動して、叩き直す:
```bash
php artisan serve --host 0.0.0.0 --port 8000
```
```bash
docker exec -it laravel-dev curl -s http://localhost:8000/api/users
```
**成功**：今度は `[]`（空配列。ユーザーが0件のJSON）が返る。→ migrate 忘れの原因＝「マイグレーションはあるが未実行」を体験で理解できた。

> SQLite既定なのに `database/database.sqlite` を作り忘れて `migrate` が落ちる、もよくある。出たら **`touch database/database.sqlite` → `php artisan migrate`** が定石。→ [database.md](./database.md)

## 片付け
サーバを止めて（`Ctrl + C`）、コンテナから出る:
```bash
exit
```
コンテナを消す（作ったファイルは `~/laravel-handson/myapp` に残ります）:
```bash
docker rm -f laravel-dev
# フォルダごと消すなら: rm -rf ~/laravel-handson
```
