# ハンズオン：Gin で JSON を返し、`:id` パラメータを受け取る

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- `go mod init` → `go get gin` → `main.go` → `go run .` で**サーバを起動できる**
- `c.JSON()` で JSON を返し、`c.Param("id")` で **`/users/:id` を受け取れる**
- わざと **モジュール未init（go.mod が無い）/ ポート競合を起こして、自分で直せる**
- ここまでやると [getting_started.md](./getting_started.md) / [routing.md](./routing.md) / [context.md](./context.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Go 1.21+ が動くこと（`go version` で確認）。それ以外の知識は不要。

> Gin は「**`gin.Context`(`c`) で入出力する**」のが土台。`c.JSON()` で返す。→ [context.md](./context.md)

## 準備：Go が使えるか確認
```bash
go version
```
**成功**：`go version go1.21` 以上が出る。
**失敗**：`command not found` または 1.21 未満 → Go 1.21+ を入れる（[go.dev/dl](https://go.dev/dl/)）。

作業用フォルダ:
```bash
mkdir -p ~/gin-handson && cd ~/gin-handson
```

## ステップ1：モジュールを初期化して Gin を入れる
**やること**：`go mod init` でモジュールを作り、Gin を `go get` する。
**なぜ**：Go は「モジュール（`go.mod`）」単位で依存を管理する。**先に `go mod init` をしないと外部ライブラリを取り込めない**。

```bash
go mod init example.com/ginhandson      # モジュールパスは任意（リポジトリURL推奨）
go get github.com/gin-gonic/gin
```
**成功**：`go.mod` が出来て、中に `require github.com/gin-gonic/gin ...` の行が入る。`go.sum` も生成される。
```bash
cat go.mod
```
**失敗**：
- `go: cannot find main module` → `go mod init` を忘れている。ステップ1の先頭から実行。
- `go get` でネットワークエラー → 少し待って再実行。

---

## ステップ2：最小サーバを書いて起動する
**やること**：`/` で JSON を返すだけのサーバを作り、`go run .` で起動する。
**なぜ**：まず「Gin が HTTP で応答する」状態を確認するため。`gin.Default()` は Logger + Recovery 入りのルータ。→ [getting_started.md](./getting_started.md)

`main.go` を次の内容で作る:
```go
// main.go
package main

import "github.com/gin-gonic/gin"

func main() {
	r := gin.Default()                 // Logger + Recovery 入りのルータ

	r.GET("/", func(c *gin.Context) {  // GET /。c は *gin.Context（入出力の窓口）
		c.JSON(200, gin.H{"msg": "ok"})  // gin.H は map[string]any のショートハンド
	})

	if err := r.Run(":8080"); err != nil {   // :8080 で待受。errは握り潰さない
		panic(err)
	}
}
```
起動:
```bash
go run .
```
**成功**：起動ログ（`[GIN-debug] Listening and serving HTTP on :8080`）が出る。別タブで:
```bash
curl -s http://localhost:8080/
```
→ `{"msg":"ok"}` が返る。
**失敗**：
- `bind: address already in use` → ステップ5でわざと起こす内容。今は他のプロセスを止める。
- `go run main.go` で「他のファイルが見つからない」系 → `go run .`（ディレクトリ指定）で起動する。

Ctrl+C で止める。

## ステップ3：もう1つ JSON ルートを足す
**やること**：`/api/health` で構造化した JSON を返すルートを足す。
**なぜ**：`c.JSON(status, body)` が Gin の基本の返し方。ステータスと本文を同時に指定する。→ [request_response.md](./request_response.md)

`main.go` の `r.GET("/", ...)` の**下に**追記:
```go
	r.GET("/api/health", func(c *gin.Context) {
		c.JSON(200, gin.H{
			"status": "ok",
			"engine": "gin",
		})
	})
```
起動して確認:
```bash
go run .
```
```bash
curl -s http://localhost:8080/api/health
```
**成功**：`{"engine":"gin","status":"ok"}` が返る。
**失敗**：`404 page not found` → 追記位置が `r.Run(...)` より**後**になっている。`r.Run()` は最後に置く。

Ctrl+C で止める。

---

## ステップ4：パスパラメータ `/users/:id`（本題）
**やること**：URL の一部を変数として受け取るルートを足す。
**なぜ**：`/users/1` `/users/2` のように「形は同じで値だけ違う」URLを1つのハンドラで扱うのが**パスパラメータ**。REST API の基本。→ [routing.md](./routing.md)

`main.go` に追記:
```go
	r.GET("/users/:id", func(c *gin.Context) {
		id := c.Param("id")            // URL の :id 部分を取り出す
		c.JSON(200, gin.H{
			"userId": id,
			"name":   "user-" + id,
		})
	})
```
起動して確認:
```bash
go run .
```
```bash
curl -s http://localhost:8080/users/1
curl -s http://localhost:8080/users/abc
```
**成功**：
- `/users/1` → `{"name":"user-1","userId":"1"}`
- `/users/abc` → `{"name":"user-abc","userId":"abc"}`
→ **これが「URLの一部を変数で受け取る」証拠**。`:id` は何でもマッチする（型は文字列）。
**失敗**：`404` → `:id` の前のスラッシュ抜け、または追記位置が `r.Run` より後。

## ステップ5：わざと「モジュール未init」「ポート競合」を起こして直す
**なぜ**：この2つは Go / Gin 初心者が必ず出会う。「自分で起こして直す」と一生忘れない。

### 5-1. モジュール未init（go.mod が無い）
`go.mod` を**一時的にリネーム**して、無い状態を作る:
```bash
mv go.mod go.mod.bak
go run .
```
**結果**：`go: cannot find main module; see 'go help modules'`（または `go.mod file not found`）。
**読み解き**：Go は `go.mod` が無いと「ここはモジュールではない」と判断し、依存（gin）も解決できないのでビルドできない。「いきなり `go run` したら怒られる」の典型原因。

**直す**：`go.mod` を元に戻す:
```bash
mv go.mod.bak go.mod
go run .
```
```bash
curl -s http://localhost:8080/
```
**成功**：また `{"msg":"ok"}` が返る。→ **「最初に `go mod init` が要る」が腹落ちした**。
（もし元に戻せなくなったら、`go mod init example.com/ginhandson && go mod tidy` で作り直せる。）

Ctrl+C で止める。

### 5-2. ポート競合
**サーバを起動したまま**、別タブでもう1つ起動する:
```bash
go run .          # 2つ目
```
**結果**：`listen tcp :8080: bind: address already in use`。
**読み解き**：8080番は1プロセス占有。すでに掴んでいるプロセスがいる。

**直す（2通り）**：
```bash
# A) 犯人を探して止める（mac/Linux）
lsof -i :8080        # PID 確認
kill <PID>

# B) ポートを変える：main.go の r.Run(":8080") を r.Run(":8081") にして再起動
```
B で 8081 にした場合:
```bash
go run .
curl -s http://localhost:8081/
```
**成功**：8081 で `{"msg":"ok"}` が返る。→ **「ポートは1プロセス占有」を体験**。
