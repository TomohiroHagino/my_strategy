# ハンズオン：Express で JSON を返し、ルートパラメータを受け取る

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から動くところまで行けます。

## ゴール（終わったら何ができる？）
- `npm init` → `npm i express` → `app.js` → `node app.js` で**サーバを起動できる**
- `res.json()` で **JSON を返し**、`/users/:id` で**ルートパラメータを受け取れる**
- わざと **ポート競合 / 404ミドルウェアの順序ミスを起こして、自分で直せる**
- ここまでやると [getting_started.md](./getting_started.md) / [routing.md](./routing.md) / [middleware.md](./middleware.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Node.js 18 以上が動くこと（`node -v` で確認）。それ以外の知識は不要。

> Express は「**ミドルウェアの列を順に通る**」だけ。これが全ての土台。→ [request_flow.md](./request_flow.md)

## 準備：Node が使えるか確認
```bash
node -v
```
**成功**：`v18.x` 以上が出る（Express 5 は Node 18+ 必須）。
**失敗**：`command not found` または18未満 → Node 18以上を入れる（`nvm install 20` 等）。

作業用フォルダ:
```bash
mkdir -p ~/express-handson && cd ~/express-handson
```

## ステップ1：プロジェクトを初期化して Express を入れる
**やること**：`package.json` を作り、Express をプロジェクトローカルに入れる。ESM（`import`）で書く。
**なぜ**：Node はプロジェクト単位で依存を管理する。`-g`（グローバル）ではなくローカルに入れるのが正解。

```bash
npm init -y
npm pkg set type=module          # import 構文を使う（ESM）宣言
npm install express
```
**成功**：`node_modules/` と `package-lock.json` が出来る。`cat package.json` に `"type": "module"` と `"express"` が入っている。
**失敗**：`npm: command not found` → Node と一緒に npm が入る。Node を入れ直す。

---

## ステップ2：最小サーバを書いて起動する
**やること**：`/` で文字列を返すだけのサーバを作り、起動する。
**なぜ**：まず「ローカルで `localhost:3000` が動く」状態を最短で作るため。ここが土台になる。

`app.js` を次の内容で作る:
```js
// app.js （ESM）
import express from "express";

const app = express();
const port = process.env.PORT || 3000;   // ポートは環境変数で上書き可

app.get("/", (req, res) => {
  res.send("Hello Express 5");            // 文字列を返す
});

app.listen(port, () => {
  console.log(`listening on http://localhost:${port}`);
});
```
起動:
```bash
node app.js
```
**成功**：`listening on http://localhost:3000` が出る。別タブで:
```bash
curl -s http://localhost:3000/
```
→ `Hello Express 5` が返る。
**失敗**：
- `Cannot use import statement outside a module` → ステップ1の `npm pkg set type=module` が漏れている。実行して再起動。
- `EADDRINUSE :::3000` → ステップ5でわざと起こす内容。今は `PORT=3001 node app.js` で別ポート起動。

確認できたら **Ctrl+C で止める**。

---

## ステップ3：JSON を返す
**やること**：`/api/health` で JSON を返すルートを足す。
**なぜ**：実務の Express は HTML より **JSON API** が主役。`res.json()` が基本の返し方。→ [request_response.md](./request_response.md)

`app.js` の `app.get("/", ...)` の**下に**追記:
```js
app.get("/api/health", (req, res) => {
  res.json({ status: "ok", time: new Date().toISOString() });   // オブジェクト→JSON
});
```
起動して確認:
```bash
node app.js
```
```bash
curl -s http://localhost:3000/api/health
```
**成功**：`{"status":"ok","time":"2026-..."}` が返る。
**失敗**：`Cannot GET /api/health` → ルートを追記した場所が `app.listen(...)` より**後**になっている。`app.listen` は最後に置く。

Ctrl+C で止める。

---

## ステップ4：ルートパラメータ `/users/:id`（本題）
**やること**：URL の一部を変数として受け取るルートを足す。
**なぜ**：`/users/1` `/users/2` のように「同じ形で値だけ違う」URLを1つのハンドラで扱うのが**ルートパラメータ**。REST API の基本。→ [routing.md](./routing.md)

`app.js` に追記:
```js
app.get("/users/:id", (req, res) => {
  const id = req.params.id;             // URL の :id 部分を取り出す
  res.json({ userId: id, name: `user-${id}` });
});
```
起動して確認:
```bash
node app.js
```
```bash
curl -s http://localhost:3000/users/1
curl -s http://localhost:3000/users/abc
```
**成功**：
- `/users/1` → `{"userId":"1","name":"user-1"}`
- `/users/abc` → `{"userId":"abc","name":"user-abc"}`
→ **これが「URLの一部を変数で受け取る」証拠**。`:id` は何でもマッチする（型は文字列）。
**失敗**：`Cannot GET /users/1` → `:id` の前のスラッシュ抜け、または追記位置が `app.listen` より後。

## ステップ5：わざと「ポート競合」「404ミドルウェアの順序ミス」を起こして直す
**なぜ**：この2つは Express で必ず出会う。「自分で起こして直す」と一生忘れない。

### 5-1. ポート競合（EADDRINUSE）
**サーバを起動したまま**、別タブでもう1つ起動する:
```bash
node app.js          # 2つ目
```
**結果**：`Error: listen EADDRINUSE: address already in use :::3000` で2つ目が落ちる。
**読み解き**：3000番は1プロセスしか掴めない。すでに掴んでいるプロセスがいる、という意味。

**直す（2通り）**：
```bash
# A) 犯人を探して止める（mac/Linux）
lsof -i :3000        # PID 確認
kill <PID>

# B) ぶつからないポートで起動
PORT=3001 node app.js
curl -s http://localhost:3001/
```
**成功**：B なら `3001` で `Hello Express 5` が返る。→ **「ポートは1プロセス占有」を体験**。

### 5-2. 404ハンドラの順序ミス
Express は「**上から順にミドルウェアを通る**」。404ハンドラ（どれにも当たらなかった時の受け皿）を**ルートより前に置くと、全部そこで止まる**。これをわざと起こす。

すべて Ctrl+C で止め、`app.js` の `app.get("/", ...)` の**すぐ上**（つまりルート定義より前）に404ハンドラを置く:
```js
// ★わざと悪い位置：ルートより前に置く
app.use((req, res) => {
  res.status(404).json({ error: "not found" });
});

app.get("/", (req, res) => {            // ← これより上に404を置いてしまった
  res.send("Hello Express 5");
});
```
起動して確認:
```bash
node app.js
```
```bash
curl -s -i http://localhost:3000/        # 本来 200 のはず
```
**結果**：`HTTP/1.1 404 Not Found` ＋ `{"error":"not found"}`。**ちゃんと作った `/` まで404になる**。
**読み解き**：`app.use(...)` は**全リクエストに当たる**ミドルウェア。それをルート定義より前に置いたので、`/` に届く前に404で返してしまった。Express は順序が全て。

**直す**：404ハンドラを**一番下（全ルートの後）**に移動する:
```js
import express from "express";
const app = express();
const port = process.env.PORT || 3000;

app.get("/", (req, res) => res.send("Hello Express 5"));
app.get("/api/health", (req, res) => res.json({ status: "ok" }));
app.get("/users/:id", (req, res) =>
  res.json({ userId: req.params.id, name: `user-${req.params.id}` })
);

// ★404は必ず最後。どのルートにも当たらなかった時の受け皿
app.use((req, res) => {
  res.status(404).json({ error: "not found" });
});

app.listen(port, () => console.log(`listening on http://localhost:${port}`));
```
```bash
node app.js
```
```bash
curl -s -i http://localhost:3000/            # 200 OK + Hello Express 5
curl -s -i http://localhost:3000/nope        # 404 + {"error":"not found"}
```
**成功**：`/` は 200、存在しない `/nope` だけ 404。→ **「ミドルウェアは順序が全て・404は最後」が腹落ちした**。
