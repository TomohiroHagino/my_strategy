# ハンズオン：Nuxt 3 でページを作り、ルーティングと useFetch まで動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [pages_routing.md](./pages_routing.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から画面が出るところまで行けます。

## ゴール（終わったら何ができる？）
- `nuxi init` で Nuxt 3 の雛形を作って、**ブラウザに自分の画面が出る**
- `pages/` を使った**ファイルベースルーティング**でページを増やせる
- `useFetch` で**公開API**のデータを取って表示できる
- わざと **`pages/` を作ったのにルートが出ない**状態（`app.vue` の `<NuxtPage />` 忘れ）を起こして、自分で直せる
- ここまでやると [getting_started.md](./getting_started.md) / [pages_routing.md](./pages_routing.md) / [data_fetching.md](./data_fetching.md) が「読める」ようになる

**所要時間**：25〜35分　**前提**：Node 20+ が入っていること（Vue の基礎は [../../vue/vue3/](../../vue/vue3/) を軽く見ておくと楽）

---

## 準備：Node が使えるか確認
**やること**：Node のバージョンを見る。
**なぜ**：Nuxt 3 は新しめの Node を要求する。古いと `nuxi init` や `dev` で失敗する。
```bash
node -v
```
**成功**：`v20.x.x`（または v22 など）と出る。
**失敗**：
- `command not found` → Node 未インストール。[nodejs.org](https://nodejs.org/) の LTS を入れて再実行。
- `v18` 以下 → LTS（20+）に上げる。

ホームに移動:
```bash
cd ~
```

---

## ステップ1：nuxi で雛形を作る
**やること**：`nuxi init` で Nuxt 3 の雛形を生成する。
**なぜ**：Nuxt は Vue の上に「ルーティング・SSR・サーバAPI」を束ねたフレームワーク。雛形ツールが「動く土台」を一発で用意してくれる。
```bash
npx nuxi@latest init my-nuxt-app
```
途中でパッケージマネージャを聞かれたら **npm** を選ぶ（`Which package manager would you like to use?` → `npm`）。Git の初期化を聞かれたら好みで。
**成功**：`✔ Initialized project ...` と表示され、依存のインストールまで進む。
**失敗**：
- `npx: command not found` → Node を入れ直す。
- インストールが途中で止まる → ネットワーク確認後、`cd my-nuxt-app && npm install` を手動実行。

---

## ステップ2：開発サーバを起動する
**やること**：プロジェクトに入って `npm run dev`。
**なぜ**：雛形のまま起動して「動く土台」を目で確認するため。
```bash
cd my-nuxt-app
npm run dev
```
初回は Nuxt が内部ファイル（`.nuxt/`）を生成するため少し時間がかかる。
**成功**：ターミナルに次が出る。
```
  ➜ Local:    http://localhost:3000/
```
ブラウザで **http://localhost:3000** を開く。
**画面に見えるもの**：Nuxt のウェルカムページ（Nuxt のロゴと「Welcome to Nuxt!」風の初期画面）。

**失敗**：
- `Port 3000 is in use` → 表示された別ポートを開く、または他のアプリを止める。
- 真っ白＋赤エラー → `.nuxt/` 生成に失敗した可能性。`Ctrl+C` で止め、`rm -rf .nuxt && npm run dev` で作り直す。

> このあと保存するたびに**ブラウザが自動更新**される。`npm run dev` は起動したままにしておく。

---

## ステップ3：app.vue を自分の中身に置き換える
**やること**：`app.vue` を、自分で書いた最小の画面に丸ごと置き換える。
**なぜ**：Nuxt は `app.vue` が「最初の入口」。まずここで「自分が書いた画面が出る」を確認する。→ [getting_started.md](./getting_started.md)

エディタで `my-nuxt-app/app.vue` を開き、中身を**すべて消して**次に置き換える:
```vue
<template>
  <main style="padding: 24px; font-family: sans-serif;">
    <h1>これは自分のNuxtページ</h1>
    <p>app.vue を書き換えました。</p>
  </main>
</template>
```
保存する。
**画面に見えるもの**：ウェルカムページが消え、**「これは自分のNuxtページ」という見出し**だけのシンプルな画面に変わる。

**失敗**：
- 画面が真っ白 → `<template>` ごと消していないか確認。`app.vue` には最低限 `<template>` が要る。
- ウェルカムページのまま → 編集したのが `my-nuxt-app/app.vue` か確認（Nuxt のバージョンによっては `app/app.vue` の場合もある。`app.vue` を探して編集する）。

---

## ステップ4：pages/ でルーティングを有効にする
**やること**：`pages/index.vue` と `pages/about.vue` を作り、`app.vue` に `<NuxtPage />` を置く。
**なぜ**：Nuxt は「**`pages/` を置くとファイルベースルーティングが有効になる**」規約。フォルダ構成そのものがルートになる体験をする。→ [pages_routing.md](./pages_routing.md)

`pages/` フォルダを作る:
```bash
mkdir -p pages
```
`my-nuxt-app/pages/index.vue` を新規作成:
```vue
<template>
  <section>
    <h1>トップページ（/）</h1>
    <NuxtLink to="/about">About へ →</NuxtLink>
  </section>
</template>
```
`my-nuxt-app/pages/about.vue` を新規作成:
```vue
<template>
  <section>
    <h1>About ページ（/about）</h1>
    <NuxtLink to="/">← トップへ</NuxtLink>
  </section>
</template>
```
そして `app.vue` を「全ページ共通の外枠＋`<NuxtPage />`」に書き換える:
```vue
<template>
  <main style="padding: 24px; font-family: sans-serif;">
    <header><strong>My Nuxt App</strong></header>
    <hr />
    <!-- ここに pages/ の各ページが描画される -->
    <NuxtPage />
  </main>
</template>
```
保存する。
**画面に見えるもの**：
- **http://localhost:3000** → 「My Nuxt App」のヘッダの下に「トップページ（/）」と「About へ →」リンク。
- リンクを押すと **http://localhost:3000/about** に移動し、「About ページ（/about）」が出る。
- `pages/about.vue` を**置いただけ**で `/about` が増えた（ルータ設定ファイル不要）。

**読み解き**：`pages/index.vue` ＝ `/`、`pages/about.vue` ＝ `/about`。**ファイルの場所がそのままURL**になる。`<NuxtPage />` は「ここに pages の中身を差し込む」という穴。→ [pages_routing.md](./pages_routing.md)

**失敗**：このステップで `/about` が出ない場合は、次のステップ6でわざと再現するので、まずは進めてOK。

---

## ステップ5：useFetch で公開APIのデータを表示する
**やること**：トップページで `useFetch` を使い、公開APIのユーザー一覧を表示する。
**なぜ**：`useFetch` は Nuxt 標準のデータ取得。**SSRと相性が良く**（サーバで取ってHTMLに埋め込む）、`import` 不要で使える（自動インポート）。→ [data_fetching.md](./data_fetching.md)

`my-nuxt-app/pages/index.vue` を次に置き換える:
```vue
<script setup lang="ts">
type User = { id: number; name: string }

// useFetch は自動インポート（import 不要）。data に結果が入る
const { data: users, pending, error } = await useFetch<User[]>(
  'https://jsonplaceholder.typicode.com/users'
)
</script>

<template>
  <section>
    <h1>トップページ（/）</h1>
    <NuxtLink to="/about">About へ →</NuxtLink>

    <h2>ユーザー一覧（useFetchで取得）</h2>
    <p v-if="pending">読み込み中…</p>
    <p v-else-if="error">取得に失敗しました</p>
    <ul v-else>
      <li v-for="user in users" :key="user.id">{{ user.name }}</li>
    </ul>
  </section>
</template>
```
保存し、**http://localhost:3000** を開く（または再読み込み）。
**画面に見えるもの**：「ユーザー一覧（useFetchで取得）」の下に、**`Leanne Graham` などの名前が10件ほど**並ぶ。「ページのソースを表示」すると名前がHTMLに含まれている（**サーバ側で取得してから返している**証拠）。

**読み解き**：
- `useFetch` は `data`（結果）・`pending`（取得中か）・`error`（失敗したか）をまとめて返す。`v-if`/`v-else` でローディングやエラーを出し分けできる。
- `import` を書いていないのに `useFetch` が使えるのは Nuxt の**自動インポート**のおかげ。→ [components_autoimport.md](./components_autoimport.md)

**失敗**：
- ずっと「読み込み中…」 → ネットワーク遮断やAPI一時障害。ターミナルや F12 → Network で失敗を確認。
- `useFetch is not defined` → Nuxt の自動インポートが効いていない（`.nuxt/` 破損）。`Ctrl+C` → `rm -rf .nuxt && npm run dev` で再生成。

## ステップ6：わざと「pagesを作ったのにルートが出ない」を起こして直す
**なぜ**：「`pages/` を作ったのに表示が変わらない」は Nuxt 初心者の最頻出のつまずき。原因は `app.vue` の `<NuxtPage />` 忘れ。自分で起こして直すと一生忘れない。

`app.vue` から **`<NuxtPage />` を消す**（わざと壊す）:
```vue
<template>
  <main style="padding: 24px; font-family: sans-serif;">
    <header><strong>My Nuxt App</strong></header>
    <hr />
    <!-- <NuxtPage /> を消した -->
  </main>
</template>
```
保存して **http://localhost:3000** を再読み込みする。
**結果**：**ヘッダ（「My Nuxt App」）だけが表示され、トップページの中身（ユーザー一覧）が消える**。`/about` を開いても About の中身が出ず、ヘッダだけになる。エラーは出ない（だから気づきにくい）。
**読み解き**：`pages/` の各ページは、`app.vue` の中の **`<NuxtPage />` の位置に差し込まれる**。`<NuxtPage />` が無いと、ルーティングは内部的に動いていても**描画する穴が無い**ので、`app.vue` の中身だけが出る。これが「pages を作ったのに出ない」の正体。→ [pages_routing.md](./pages_routing.md)

直す（`<NuxtPage />` を戻す）:
```vue
<template>
  <main style="padding: 24px; font-family: sans-serif;">
    <header><strong>My Nuxt App</strong></header>
    <hr />
    <NuxtPage />
  </main>
</template>
```
保存する。
**成功**：再びトップにユーザー一覧が出て、`/about` も表示される。→ 「`pages/` を使うなら `app.vue` に `<NuxtPage />` が必須」を体験で理解できた。

> 関連の typo として、フォルダ名が `page/`（単数）や `Pages/`（大文字）だと**認識されない**。複数形・小文字の `pages/` を守る。→ [getting_started.md](./getting_started.md)
