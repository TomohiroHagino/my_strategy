# JavaScript 特有の現象と対策（落とし穴カタログ）

> JS（ES）で**言語の仕組みゆえに起きる古典的な現象**を「現象 / なぜ起きる / 対策」で網羅する。文法そのものの解説は [解説/es2024.md](./解説/es2024.md)、ここは**ハマって直すための辞書**。
> TypeScript固有は [../typescript/落とし穴.md](../typescript/落とし穴.md)、Node固有は [../../バックエンド/node/落とし穴.md](../../バックエンド/node/落とし穴.md)、React Native文脈は [../../モバイル/typescript_mobile/落とし穴.md](../../モバイル/typescript_mobile/落とし穴.md)。

## 1. 巻き上げ（hoisting）と TDZ
**現象**：宣言より前で変数/関数を参照しても、`var` はエラーにならず `undefined`、`let`/`const` は実行時エラー（`ReferenceError`）。
**なぜ**：宣言はスコープ先頭に巻き上げられる。`var` は巻き上げ時に `undefined` で初期化されるが、`let`/`const` は宣言行まで**TDZ（Temporal Dead Zone・一時的死角）**にあり参照不可。関数宣言は本体ごと巻き上がる。
```js
console.log(a); // undefined（var は巻き上げ＋undefined初期化）
var a = 1;
console.log(b); // ReferenceError（TDZ）
let b = 2;
```
**対策**：
- `var` を使わない。**`const` 既定・再代入する時だけ `let`**。
- 宣言は使う前に書く（巻き上げに頼らない）。
- ESLint の `no-use-before-define` / `no-var` で機械的に弾く。

## 2. `this` が呼び出し方で変わる（最頻バグ）
**現象**：メソッドを変数に代入したりコールバックに渡すと、`this` が外れて `undefined`/別物になる。
**なぜ**：`this` は「**どう呼ばれたか**」で実行時に決まる（定義場所では決まらない）。`obj.method()` ならレシーバ、単独 `fn()` なら `undefined`（strict）。
```js
const obj = {
  v: 10,
  show() { setTimeout(function () { console.log(this.v); }, 0); }, // this外れ→undefined
  showOK() { setTimeout(() => console.log(this.v), 0); },          // アロー→外側this維持→10
};
const f = obj.show; f();  // this が obj から外れる
```
**対策**：
- コールバックは**アロー関数**（自分の `this` を持たず外側を引き継ぐ）。
- 渡す前に `const bound = obj.method.bind(obj)`。
- クラスではフィールド構文 `handle = () => {...}` でメソッドを束縛。

## 3. ループ内クロージャが最後の値を共有
**現象**：`for` ループで作った関数が、全部ループ終了後の同じ値を参照する。
**なぜ**：`var` は関数スコープで**1つの束縛を共有**するため、後から実行されるクロージャは最終値を見る。
```js
// NG: var は共有 → 3,3,3
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
// OK: let はブロックごとに新しい束縛 → 0,1,2
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
```
**対策**：ループ変数は `let`（反復ごとに別束縛）。`forEach`/`map` でも各反復が独立スコープになる。

## 4. コールバック地獄（callback hell）
**現象**：非同期処理を入れ子のコールバックで繋ぐと、右に深くネストして読めない・エラー処理が分散する。
**なぜ**：かつて非同期の合成手段がコールバックしか無く、`fn(a, (e, r) => fn2(r, (e, r2) => ...))` と段々深くなる（"pyramid of doom"）。エラーは各コールバックの第1引数（error-first）で個別に拾うため抜け漏れやすい。
```js
// NG: 入れ子地獄
getUser(id, (e, user) => {
  if (e) return done(e);
  getPosts(user.id, (e, posts) => {
    if (e) return done(e);
    getComments(posts[0].id, (e, comments) => { /* さらに深く… */ });
  });
});
```
**対策**：
- **Promise** に直し、`.then()` チェーンで平坦化（各段の戻り値を次へ）。
- **`async`/`await`** で同期的な見た目に（最有力）。エラーは `try/catch` に集約。
```js
// OK: async/await
try {
  const user = await getUser(id);
  const posts = await getPosts(user.id);
  const comments = await getComments(posts[0].id);
} catch (e) { done(e); }
```
- コールバックAPIは `util.promisify`（Node）やラッパでPromise化する。

## 5. `await` の付け忘れ / 直列待ちで遅い
**現象**：(a) `await` を忘れて Promise（未解決）をそのまま使い、値が `[object Promise]`・`undefined` になる。(b) 独立した非同期を順番に `await` して無駄に遅い。
**なぜ**：`async` 関数は常に Promise を返す。`await` しないと中身でなくPromiseが手に入る。`await` を直列に並べると前が終わるまで次が始まらない。
```js
// NG(a): await漏れ → user は Promise
const user = getUser(id);  console.log(user.name); // undefined
// NG(b): 直列。合計 = a+b の時間
const a = await taskA(); const b = await taskB();
// OK(b): 並列。合計 = max(a,b)
const [a2, b2] = await Promise.all([taskA(), taskB()]);
```
**対策**：戻りがPromiseなら必ず `await`/`return`。**独立処理は `Promise.all` で並列化**。ESLint `no-floating-promises`（TS）/ `require-await` で検出。

## 6. 未処理のPromiseリジェクトとエラーのすり抜け
**現象**：Promiseの失敗を誰も `catch` せず、警告（`UnhandledPromiseRejection`）やNodeではクラッシュ。`forEach` 内の `async` も例外が外に出ない。
**なぜ**：reject は同期 `throw` と違い、`catch`/`try-await` が無いと伝播先が無い。`array.forEach(async ...)` は各Promiseを待たず捨てる。
```js
// NG: forEach は await を待たない／例外を拾えない
items.forEach(async (it) => { await save(it); }); // 例外が消える・完了も待てない
// OK: for...of で待つ、または並列なら Promise.all + map
for (const it of items) await save(it);
await Promise.all(items.map((it) => save(it)));
```
**対策**：`async` 関数の呼び出しは `await` か `.catch()`。一括は `Promise.all`/`allSettled`。Nodeは `process.on('unhandledRejection')` で握りつぶさず最低限ログ。

## 7. `==` の暗黙変換 / truthy・falsy
**現象**：`"" == 0`、`"0" == false`、`null == undefined` が true など直感に反する。
**なぜ**：`==` は型が違うと**暗黙変換してから**比較する。falsy は `false/0/""/null/undefined/NaN` の6つ。
**対策**：常に **`===`/`!==`**。null/undefinedだけ見たいなら `x == null`（両方true）を意図的に使うか `x ?? 既定`。存在チェックに truthy を使うと `0`/`""` を弾く事故に注意し、`if (x != null)` で明示。

## 8. `NaN` / `typeof null` / 数値の罠
**現象**：`NaN === NaN` が false、`typeof null === "object"`、`parseInt("08")` 等の予想外。
**なぜ**：`NaN` は自分自身とも等しくない仕様。`null` の typeof は歴史的バグ。
**対策**：NaN判定は `Number.isNaN(x)`。整数判定は `Number.isInteger`。`null` 判定は `x === null`。`parseInt` は基数を渡す（`parseInt(s, 10)`）。

## 9. 浮動小数の誤差
**現象**：`0.1 + 0.2 === 0.3` が false（`0.30000000000000004`）。
**なぜ**：JSの数値はIEEE 754倍精度。10進小数は2進で正確に表せない。
**対策**：**金額は最小単位の整数**（円・セント）で扱う。比較は許容誤差 `Math.abs(a-b) < 1e-9`。高精度が要るなら `decimal.js` 等や `BigInt`（整数のみ）。

## 10. 値 vs 参照（オブジェクトは参照渡し）
**現象**：オブジェクト/配列を代入・引数渡しすると同じ実体を共有し、片方の変更が他方に波及。`===` も中身でなく参照で比較。
**なぜ**：プリミティブはコピー、オブジェクトは**参照**が渡る。
```js
const a = { n: 1 }; const b = a; b.n = 99; // a.n も 99
[1,2] === [1,2]; // false（別オブジェクト）
```
**対策**：変更したくないなら**新しいオブジェクトを作る**（スプレッド `{...a, n: 2}` / `structuredClone(a)` で深いコピー）。このリポジトリの[コーディング規約（不変性）]とも一致。等価比較は中身を比べる関数で。

## 11. 破壊的メソッドで元配列が変わる
**現象**：`sort`/`reverse`/`splice` が**元の配列を変更**し、他所の参照に影響。
**なぜ**：これらは破壊的（in-place）。
**対策**：非破壊版 `toSorted`/`toReversed`/`toSpliced`（ES2023）や `[...arr].sort()`。`sort` は既定で**文字列比較**なので数値は比較関数 `(a,b)=>a-b` を渡す。

## 12. イベントループを塞ぐ（同期重処理で全停止）
**現象**：重いループや巨大JSONの同期処理中、UIが固まる／Nodeでは全リクエストが止まる。
**なぜ**：JSは**シングルスレッド**。同期処理が走っている間、イベントループは何も拾えない。
**対策**：重い計算は分割（`setTimeout`/`queueMicrotask`で譲る）、Web Worker / Node の Worker Threads に逃がす、ストリームで小分け。詳しくは Node 文脈 → [../../バックエンド/node/落とし穴.md](../../バックエンド/node/落とし穴.md)。

## 13. 分割代入・オプショナルチェインの取り違え
**現象**：`const { a } = undefined` で例外。`obj?.a.b` で `a` が無いと `b` で例外。
**なぜ**：分割代入は対象が `null/undefined` だと throw。`?.` は**その直後だけ**を短絡する。
**対策**：既定値 `const { a = 0 } = obj ?? {}`。連鎖は各段に `obj?.a?.b`。`??`（null/undefinedのみ）と `||`（falsy全部）を取り違えない。
