# JavaScript ES2024（言語解説）

## ひとことで言うと
動的型付け・プロトタイプベースのスクリプト言語で、関数が第一級・クロージャ・Promise/async-await による非同期・シングルスレッドのイベントループを土台にする。ES2024（ECMAScript 2024）は `Object.groupBy`・`Promise.withResolvers`・正規表現 `v` フラグなどを追加した版。

## このバージョンの位置づけ（リリース / サポート・LTS / どこで使うか）
- ECMAScript は毎年「ES2015, ES2016, …」と更新され、ES2024 は2024年6月承認の版。LTS の概念はなく、各実行環境（ブラウザ・Node・Deno・Bun）が順次機能を実装する。
- 「ES2024 対応か」は実行環境次第。新しい Node/モダンブラウザはほぼ対応済みだが、古い環境向けには Babel 等でトランスパイルする。
- 使う場所: ブラウザの UI 制御（DOM・イベント・fetch）、Node でのサーバ/ツール、ビルドツール。型付けは [../typescript/](../typescript/)、UI は [../react/](../react/) を参照。

```js
// 実行環境の確認
console.log(typeof Object.groupBy);      // "function" なら ES2024 対応
```

## 言語の基本（文法の要点）
変数は `const`（再代入不可）/ `let`（再代入可）で宣言する。`var` は関数スコープで巻き上げの罠があるため新規コードでは避ける。

```js
const name = "JS";
let count = 0;
count += 3;

// 関数は値として扱える（第一級）
const double = (n) => n * 2;          // アロー関数
function add(a, b) { return a + b; }  // 関数宣言

// 分割代入・スプレッド
const { x, y } = { x: 1, y: 2 };
const merged = { ...{ a: 1 }, b: 2 }; // { a: 1, b: 2 }
const nums = [1, ...[2, 3], 4];       // [1, 2, 3, 4]
```

- セミコロンは自動挿入されるが、明示する方が事故が少ない。
- 比較は型変換を避けるため `===` / `!==`（厳密等価）を使う。

## この言語の核心概念（他言語と違う・必ず押さえる）

### プロトタイプベース
- **何か**: オブジェクトは別のオブジェクト（プロトタイプ）へのリンクを持ち、自分に無いプロパティ/メソッドはそのリンクを辿って探す（プロトタイプチェーン）。`class` 構文はこの仕組みの糖衣で、内部はプロトタイプの繋ぎ替え。
- **具体コード**:

```js
const animal = { speak() { return "..."; } };
const dog = Object.create(animal); // dog の __proto__ は animal
dog.bark = () => "woof";
dog.speak();                       // "..."（自身に無いのでプロトタイプを辿る）
Object.getPrototypeOf(dog) === animal; // true

class Cat { speak() { return "meow"; } } // class も内部はプロトタイプ
const c = new Cat();
Object.getPrototypeOf(c) === Cat.prototype; // true
```

- **他言語と違う点/つまずき**: Java のような「クラス＝設計図」のクラスベースとは根本が違い、継承はオブジェクト同士のリンクで実現される。`class` を使ってもメソッドは `prototype` に1個だけ置かれ全インスタンスで共有される点が、フィールドをインスタンスごとに持つ言語と異なる。

### `this` の束縛（呼び出し方で変わる）← 最大のつまずき
- **何か**: `this` が何を指すかは「関数がどう呼ばれたか」で実行時に決まる（定義場所では決まらない）。メソッド呼び出しならレシーバ、単独呼び出しなら `undefined`（strict）/グローバル。アロー関数は自分の `this` を持たず、定義時の外側の `this` を引き継ぐ。
- **具体コード**:

```js
const obj = {
  value: 10,
  normal() { return this.value; },
  delayed() { setTimeout(function () { console.log(this.value); }, 0); }, // this が外れる→undefined
  delayedArrow() { setTimeout(() => console.log(this.value), 0); },       // 外側 this を維持→10
};
obj.normal();            // 10
const fn = obj.normal;
fn();                    // undefined（レシーバが外れた）
const bound = obj.normal.bind(obj);
bound();                 // 10（bind で this を固定）
obj.delayed();           // undefined
obj.delayedArrow();      // 10
```

- **他言語と違う点/つまずき**: 多くの言語で `this`/`self` はインスタンスに固定だが、JS では **呼び出し方次第で変わる**。メソッドを変数に代入したりコールバックに渡すと `this` が外れるのが最頻出バグ。対策は `bind` か、`this` を持たないアロー関数を使うこと。

### クロージャ
- **何か**: 関数は自分が定義されたスコープの変数を「閉じ込めて」保持する。外側の関数が終了しても、内側の関数が参照する変数は生き続ける。
- **具体コード**:

```js
function counter() {
  let n = 0;          // この変数を内側関数が閉じ込める
  return () => ++n;
}
const next = counter();
next(); // 1
next(); // 2（n は呼び出し間で保持される）

// プライベート変数の実現にも使う
function makeAccount(balance) {
  return { deposit: (x) => (balance += x), get: () => balance };
}
```

- **他言語と違う点/つまずき**: モジュールやプライベート状態、イベントハンドラの定番手段。`var` を使った `for` ループ内でクロージャを作ると、ループ変数が共有されて全部最後の値になる古典的な罠がある（`let` ならブロックごとに新しい束縛になり回避できる）。

### 巻き上げ（hoisting）と `var`/`let`/`const`・TDZ
- **何か**: 宣言はスコープ先頭へ巻き上げられる。`var` は巻き上げ時に `undefined` で初期化され、宣言前に参照してもエラーにならない。`let`/`const` も巻き上げられるが、宣言行までは「一時的死角（TDZ）」で参照するとエラー。`var` は関数スコープ、`let`/`const` はブロックスコープ。
- **具体コード**:

```js
console.log(a); // undefined（var は巻き上げられ初期化済み）
var a = 1;

// console.log(b); // ReferenceError（TDZ: 宣言前は触れない）
let b = 2;

for (var i = 0; i < 3; i++) {}
console.log(i); // 3（var は関数スコープに漏れる）
for (let j = 0; j < 3; j++) {}
// console.log(j); // ReferenceError（let はブロック内のみ）
```

- **他言語と違う点/つまずき**: 「宣言前に変数を使えてしまう（`var`）」は他言語に少ない挙動。新規コードでは `var` を避け `const`/`let` を使うのが定石。

### `==` vs `===` と truthy/falsy
- **何か**: `==` は両辺を暗黙に型変換してから比較する（直感に反する結果が出る）。`===` は型変換せず厳密比較。条件式では値が真偽に変換され、`false`/`0`/`""`/`null`/`undefined`/`NaN` が falsy、それ以外は truthy。
- **具体コード**:

```js
0 == "";       // true（暗黙変換）
0 == "0";      // true
"" == "0";     // false（直感に反する非推移性）
null == undefined; // true
0 === "";      // false（厳密比較なら型が違うので false）

if ("") console.log("not run"); // "" は falsy
if ([]) console.log("run");     // 空配列は truthy（オブジェクトだから）
```

- **他言語と違う点/つまずき**: `==` の暗黙変換は推移律すら崩れる（`"" == 0` かつ `"0" == 0` なのに `"" != "0"`）。**常に `===`/`!==`** を使う。空配列・空オブジェクトが truthy、`"0"` が truthy なのに `== false` で true になる等、falsy 判定の例外を押さえる。

### 値 vs 参照（オブジェクトは参照）
- **何か**: プリミティブ（number/string/boolean 等）は値としてコピーされる。オブジェクト・配列・関数は参照（住所）が変数に入り、代入・引数渡しで参照がコピーされる（中身は共有）。
- **具体コード**:

```js
let a = 1, b = a; b = 2;
console.log(a); // 1（プリミティブはコピー）

const o = { n: 1 };
const p = o; p.n = 9;
console.log(o.n); // 9（参照を共有＝同じオブジェクト）

function mutate(obj) { obj.n = 100; }     // 中身は変えられる
function reassign(obj) { obj = { n: 0 }; } // 再代入は呼び出し元に届かない
mutate(o);   console.log(o.n);  // 100
reassign(o); console.log(o.n);  // 100（差し替えは反映されない）
```

- **他言語と違う点/つまずき**: 「オブジェクトを渡したら中身が変わった」「コピーしたつもりが同じものを共有していた」が定番。独立した複製が欲しいなら `structuredClone(o)` やスプレッド `{...o}`（浅いコピー）を使う。再代入は呼び出し元に届かない点は Java の参照の値渡しと同じ。

## 型・データモデル
- プリミティブ: `number`（整数も浮動小数も同じ）/ `string` / `boolean` / `null` / `undefined` / `symbol` / `bigint`。
- オブジェクト: 連想配列的なキー値の集合。配列・関数・`Date` 等もオブジェクト。
- 動的型: 変数の型は実行時に決まり、再代入で変わる。

```js
let v = 42;
v = "now a string"; // 型エラーにはならない（動的型付け）

typeof 42;          // "number"
typeof null;        // "object"（歴史的バグだが仕様として残る）
Array.isArray([]);  // true（配列判定は typeof でなくこれ）
```

（プロトタイプベース・クラス継承の仕組みは「この言語の核心概念」を参照）

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  speak() { return `${this.name} barks`; }
}
new Dog("pochi").speak(); // "pochi barks"
```

### 高階関数（配列メソッド）

```js
const nums = [1, 2, 3, 4];
const result = nums
  .filter((n) => n % 2 === 0)  // [2, 4]
  .map((n) => n * 10)          // [20, 40]
  .reduce((sum, n) => sum + n, 0); // 60
```

// main.js

## 並行・非同期
JavaScript はシングルスレッド。重い I/O は待たずに進め、完了時にコールバックをイベントループが拾う。

### イベントループの要点
同期処理 → マイクロタスク（Promise の `then`）→ マクロタスク（`setTimeout` 等）の順で処理される。

```js
console.log("1");
setTimeout(() => console.log("4 (macro)"), 0);
Promise.resolve().then(() => console.log("3 (micro)"));
console.log("2");
// 出力順: 1, 2, 3 (micro), 4 (macro)
```

### Promise / async-await

```js
async function fetchUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`status ${res.status}`);
  return res.json();
}

// 並行: 独立した処理は Promise.all でまとめて待つ
const [a, b] = await Promise.all([fetchUser(1), fetchUser(2)]);

// どれか1つ成功すればよい / 全結果を集める
await Promise.race([p1, p2]);
await Promise.allSettled([p1, p2]); // 各々の成否を配列で
```

- CPU を本当に並列に使いたい場合は Web Worker（ブラウザ）/ worker_threads（Node）で別スレッドを起動する。

## 標準ライブラリ / ツールチェーン
- 実行環境: ブラウザ / Node.js / Deno / Bun。同じ言語仕様だが利用できる API（DOM か OS か）が異なる。
- パッケージ: npm（および pnpm / yarn）。
- ビルド: Vite / esbuild / swc。型付けは [../typescript/](../typescript/)。
- 組み込みオブジェクト: `Array` / `Object` / `Map` / `Set` / `JSON` / `Math` / `Date` / `RegExp` / `Intl`（国際化）。

```js
// よく使う組み込み
JSON.parse('{"a":1}');          // 文字列→オブジェクト
JSON.stringify({ a: 1 });       // オブジェクト→文字列
new Map([["a", 1]]).get("a");   // 1（任意キーの辞書）

```

## このバージョンの新機能・トピック（ES2024）
### Object.groupBy / Map.groupBy
配列をキー関数でグループ化する。

```js
const items = [
  { type: "fruit", name: "apple" },
  { type: "veg", name: "carrot" },
  { type: "fruit", name: "banana" },
];
const byType = Object.groupBy(items, (it) => it.type);
// { fruit: [{...apple}, {...banana}], veg: [{...carrot}] }

// オブジェクトをキーにしたい場合は Map.groupBy
const byObjKey = Map.groupBy(items, (it) => it.type);
```

### Promise.withResolvers
`resolve` / `reject` を外に取り出せる。外部イベントと Promise を橋渡しする時に便利。

```js
const { promise, resolve, reject } = Promise.withResolvers();
button.addEventListener("click", () => resolve("clicked"));
const result = await promise; // クリックされるまで待つ
```

### 正規表現 v フラグ（unicodeSets）
Unicode 集合演算と文字列リテラル集合が使える。

```js
// 集合の差: ギリシャ文字から記号を除く、のような演算が書ける
const re = /[\p{Letter}--\p{Script=Greek}]/v;
"a".match(re); // ラテン文字はマッチ、ギリシャ文字は除外
```

### その他 ES2024
- `Array.prototype.with` / `toSorted` / `toReversed` / `toSpliced`（厳密には ES2023 だが実務で広く使う非破壊メソッド）。ES2024 ではこれらに加え配列操作の非破壊化が定着。

```js
const arr = [3, 1, 2];
const sorted = arr.toSorted();  // [1, 2, 3]（元の arr は不変）
const replaced = arr.with(0, 9); // [9, 1, 2]（インデックス0を置換した新配列）
```
- 文字列の Unicode 正規化やグループ化の整備、`ArrayBuffer` のリサイズ対応など低レベル改善も含む。

## ハマりどころ
- `==` は暗黙変換で直感に反する（`"" == 0` が true 等）。常に `===` を使う。
- `typeof null === "object"`、`NaN === NaN` が false（判定は `Number.isNaN`）。
- 浮動小数の誤差（`0.1 + 0.2 !== 0.3`）。金額計算は整数（最小単位）や専用ライブラリで。
- `var` の巻き上げ・関数スコープ、`this` の動的束縛は古典的な罠。`const`/`let` とアロー関数で回避。
- 配列の破壊的メソッド（`sort` / `reverse` / `splice`）は元配列を変更する。非破壊版（`toSorted` 等）を使うと安全。
- 型が無いため大規模では壊れやすい。実務では [../typescript/](../typescript/) を載せるのが主流。
