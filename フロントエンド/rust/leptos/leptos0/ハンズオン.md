# ハンズオン：Leptos（Rust/WASM）で最小アプリを作り、signalカウンタまで動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [signals.md](./signals.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から画面が出るところまで行けます。
>
> ⚠️ **Rust の前提が要る**：このハンズオンは Rust（`cargo`）が使えることが前提。未導入なら最初の準備ステップで入れる。また Leptos は 0.x 系で API がよく変わるため、ここでは **0.7+ / CSR（ブラウザだけで動く）** に絞る。実装時は最新の公式 docs も確認すること。

## ゴール（終わったら何ができる？）
- `wasm32` ターゲットと `trunk` を入れて、**Rust を WASM にコンパイルしてブラウザで動かせる**
- 最小の Leptos アプリを `trunk serve` で立て、**ブラウザに自分の画面が出る**
- `signal` を使った**カウンタ**を作れる
- わざと **wasm ターゲット未追加**のビルド失敗を起こして、自分で直せる
- ここまでやると [getting_started.md](./getting_started.md) / [signals.md](./signals.md) / [view_macro.md](./view_macro.md) が「読める」ようになる

**所要時間**：30〜45分（Rust 初回ビルドは時間がかかる）　**前提**：Rust（`cargo`）が使えること（未導入でも準備ステップで入れる）

---

## 準備：Rust が使えるか確認
**やること**：`cargo` のバージョンを見る。
**なぜ**：Leptos は Rust 製。`cargo`（Rust のビルド/パッケージ管理）が無いと何も始まらない。
```bash
cargo --version
```
**成功**：`cargo 1.x.x` と出る。
**失敗**：`command not found` → Rust 未導入。次で入れる:
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# 案内に従いインストール後、シェルを開き直すか:
source "$HOME/.cargo/env"
cargo --version   # もう一度確認
```

ホームに移動:
```bash
cd ~
```

---

## ステップ1：wasm32 ターゲットと trunk を入れる
**やること**：ブラウザ向けのコンパイル先（`wasm32-unknown-unknown`）と、ビルドツール `trunk` を追加する。
**なぜ**：ブラウザは Rust を直接実行できない。**Rust → WebAssembly（wasm）** に変換し、それをブラウザに渡す必要がある。そのための「変換先（target）」と「ビルドツール（trunk）」を揃える。
```bash
# ブラウザ向けターゲットを追加（これを忘れるとビルドできない）
rustup target add wasm32-unknown-unknown

# CSR 向けビルドツール（初回は数分かかる）
cargo install trunk
```
**成功**：
- `rustup target add ...` → `info: downloading component` のあと完了。
- `cargo install trunk` → 最後に `Installed package trunk ...` と出る。
**失敗**：
- `cargo install trunk` が遅い／途中で固まる → ビルドに時間がかかるだけのことが多い。数分待つ。失敗したら再実行。
- `error: linker ...` → C コンパイラ等が不足。Linux なら `build-essential`、mac なら Xcode Command Line Tools を入れる。

確認:
```bash
rustup target list --installed | grep wasm32
trunk --version
```
**成功**：`wasm32-unknown-unknown` が一覧に出て、`trunk x.x.x` が表示される。

## ステップ2：プロジェクトを作る
**やること**：`cargo new` で空のバイナリプロジェクトを作る。
**なぜ**：Leptos アプリも普通の Rust プロジェクトとして始める。
```bash
cargo new leptos-handson
cd leptos-handson
```
**成功**：`Creating binary (application) ...` と出て、`leptos-handson/` に `Cargo.toml` と `src/main.rs` ができる。

---

## ステップ3：Cargo.toml に Leptos を足す
**やること**：依存に Leptos（CSR feature 付き）を追加する。
**なぜ**：`csr`（Client-Side Rendering＝ブラウザだけで動く）feature を有効にすると、`mount_to_body` などブラウザ用APIが使える。
`leptos-handson/Cargo.toml` を開き、`[dependencies]` 以下を次に置き換える:
```toml
[dependencies]
leptos = { version = "0.7", features = ["csr"] }
```
保存する。
**読み解き**：`features = ["csr"]` を**必ず1つ**有効にする。無いと `mount_to_body` 等が見つからない。`csr` と `ssr` を同時に有効にすると衝突する（1ビルド1モード）。→ [ssr_csr.md](./ssr_csr.md)

---

## ステップ4：最小の Leptos アプリを書く
**やること**：`src/main.rs` を、Leptos の最小アプリに置き換える。さらに trunk の起点 `index.html` を作る。
**なぜ**：`mount_to_body` で `<body>` 直下に描画を始めるのが CSR の最小形。`index.html` は trunk がビルドの起点にする。→ [getting_started.md](./getting_started.md) / [view_macro.md](./view_macro.md)

`leptos-handson/src/main.rs` を**すべて消して**次に置き換える:
```rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    view! {
        <main>
            <h1>"これは自分のLeptosページ"</h1>
            <p>"Rust が WASM になってブラウザで動いています。"</p>
        </main>
    }
}

fn main() {
    // CSR: <body> 直下にマウントして描画開始
    mount_to_body(App);
}
```
`leptos-handson/index.html`（**プロジェクト直下**、`src/` ではない）を新規作成:
```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
  </head>
  <body></body>
</html>
```
保存する。
**読み解き**：`view!` マクロの中の文字列は **必ずダブルクオートで囲む**（`"これは..."`）。`use leptos::prelude::*;` を忘れると `view!` や `mount_to_body` が見つからない。→ [view_macro.md](./view_macro.md)

---

## ステップ5：trunk serve でブラウザに表示する
**やること**：`trunk serve` で開発サーバを立てる。
**なぜ**：trunk が Rust を wasm にコンパイルし、`index.html` と束ねてローカルサーバで配信してくれる。
```bash
trunk serve --open
```
初回は wasm へのコンパイルで時間がかかる。
**成功**：ターミナルに次のような表示が出る。
```
   Compiling leptos-handson v0.1.0 ...
   ...
2024-xx-xx INFO 📡 serving static assets at -> /
2024-xx-xx INFO 📡 server listening at http://127.0.0.1:8080
```
`--open` でブラウザが自動で開く（開かなければ手動で **http://localhost:8080**）。
**画面に見えるもの**：**「これは自分のLeptosページ」という見出し**と説明文。これは Rust のコードが WASM になってブラウザで動いている画面。

**失敗**：
- `error[E0432]: unresolved import` 系 → `use leptos::prelude::*;` の書き忘れ。
- `Compiling` のまま長い → 初回は正常。数分待つ。
- ビルドが `target wasm32-unknown-unknown not found` で落ちる → ステップ6でわざと再現するので、まずは進めてOK（出たら直し方が分かる）。

## ステップ6：signal でカウンタを作る
**やること**：ボタンを押すと数が増えるカウンタを `signal` で書く。
**なぜ**：Leptos の核は「**signal（値の箱）が変わると、それを使っている view のその部分だけが更新される**」（細粒度リアクティビティ）。signal がその入り口。→ [signals.md](./signals.md)

`src/main.rs` の `App` を次に置き換える（`main` はそのまま）:
```rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    // signal(初期値) は (読み取り, 書き込み) のペアを返す
    let (count, set_count) = signal(0);

    view! {
        <main>
            <h1>"これは自分のLeptosページ"</h1>
            // count() で現在値を読む。クリックで set_count を呼んで更新
            <button on:click=move |_| set_count.set(count.get() + 1)>
                "押した回数: " {move || count.get()}
            </button>
        </main>
    }
}

fn main() {
    mount_to_body(App);
}
```
保存する（`trunk serve` 起動中なら自動で再ビルド・再読み込み）。
**画面に見えるもの**：`押した回数: 0` のボタン。**クリックするたびに 0 → 1 → 2 … と増える**。

**読み解き**：
- `signal(0)` は「読み取り（`count`）」と「書き込み（`set_count`）」の**ペア**を返す。
- 値を読むのは `count.get()`、変えるのは `set_count.set(...)`。
- `{move || count.get()}` のように**クロージャ**で囲むと、その部分だけが count の変化に追従して更新される（React のような全体再レンダリングはしない）。→ [signals.md](./signals.md)

**失敗**：
- ボタンを押しても増えない → `count.get()` や `set_count.set(...)` の書き方を確認。`{count.get()}`（クロージャ無し）だと初期値のまま固定されることがある。`{move || count.get()}` が確実。
- コンパイルエラー → `view!` 内の文字列がダブルクオートで囲まれているか確認。

## ステップ7：わざと「wasm ターゲット未追加」を起こして直す
**なぜ**：`wasm32` ターゲット未追加によるビルド失敗は、Leptos（や WASM 全般）で**最頻出**のつまずき。自分で起こして直すと一生忘れない。

まず `trunk serve` を **`Ctrl+C` で止める**。
わざとターゲットを削除する:
```bash
rustup target remove wasm32-unknown-unknown
```
もう一度ビルドを試す:
```bash
trunk serve
```
**結果**：ビルドが失敗し、次のようなエラーが出る。
```
error[E0463]: can't find crate for `core`
  = note: the `wasm32-unknown-unknown` target may not be installed
```
または
```
error: target 'wasm32-unknown-unknown' not found
```
**読み解き**：ブラウザ向けにコンパイルするには「**wasm32 という変換先**」が rustup に登録されている必要がある。これが無いと、Rust は wasm 用の標準ライブラリ（`core` 等）を見つけられず、ビルドの一番手前で失敗する。

直す（ターゲットを再追加）:
```bash
rustup target add wasm32-unknown-unknown
trunk serve --open
```
**成功**：またコンパイルが通り、ブラウザにカウンタが表示される。→ 「WASM ビルドには wasm32 ターゲットが必須」を体験で理解できた。

> 実務でも `error: target ... not found` 系が出たら、**まず `rustup target list --installed` で wasm32 が入っているかを疑う**のが定石。→ [pitfalls.md](./pitfalls.md)
