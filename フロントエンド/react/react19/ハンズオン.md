# ハンズオン：React アプリを0から作って、カウンタとAPI表示まで動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [state.md](./state.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から画面が出るところまで行けます。

## ゴール（終わったら何ができる？）
- Vite で React アプリを作って、**ブラウザに自分の画面が出る**
- ボタンを押すと数が増える**カウンタ**を `useState` で作れる
- **公開API**からデータを取って画面に並べられる
- わざと **key 無し警告**を出して、自分で直せる
- ここまでやると [getting_started.md](./getting_started.md) / [state.md](./state.md) / [lists_keys.md](./lists_keys.md) が「読める」ようになる

**所要時間**：20〜30分　**前提**：Node 20+ が入っていること（それ以外の知識は不要）

---

## 準備：Node が使えるか確認
**やること**：Node のバージョンを見る。
**なぜ**：Vite も React も Node の上で動く。古すぎると途中で失敗する。
```bash
node -v
```
**成功**：`v20.x.x`（または v22 など）と出る。
**失敗**：
- `command not found` → Node が未インストール。[nodejs.org](https://nodejs.org/) の LTS を入れて再実行。
- `v18` 以下 → 動く場合もあるが、新しめの LTS（20+）に上げると安全。

作業用フォルダの親に移動（ここでは Documents 直下で作業）:
```bash
cd ~
```

## ステップ1：Vite で React プロジェクトを作る
**やること**：Vite の `react-ts` テンプレートで雛形を生成する。
**なぜ**：React は素のHTMLでは動かず、JSX＋ビルド環境が要る。Vite がその足場を一発で用意してくれる。
```bash
npm create vite@latest my-app -- --template react-ts
```
- `my-app`＝作るフォルダ名、`-- --template react-ts`＝「TypeScript版のReactテンプレートで」という指定。
- **`--` を省くと**テンプレ指定が Vite に渡らず対話モードになる。npm 経由では `-- --template react-ts` と書く。→ [getting_started.md](./getting_started.md)

**成功**：`Scaffolding project in .../my-app...` と出て `Done.` で終わる。
**失敗**：
- `npm: command not found` → Node を入れ直す（準備ステップへ戻る）。
- 途中で止まって質問が出る → `--` を付け忘れている。`Ctrl+C` で中止し、上のコマンドをそのまま貼り直す。

---

## ステップ2：依存をインストールして開発サーバを起動する
**やること**：パッケージを入れて `npm run dev` する。
**なぜ**：雛形だけでは動かない。React 本体などの部品（`node_modules`）を入れ、開発サーバを立てて初めて画面が出る。
```bash
cd my-app
npm install
npm run dev
```
**成功**：ターミナルに次のような表示が出る。
```
  VITE v6.x.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
```
ブラウザで **http://localhost:5173** を開く。
**画面に見えるもの**：Vite と React のロゴ、`Vite + React` の見出し、`count is 0` と書かれたボタン。**ボタンを押すと数字が増える**（これは雛形に最初から入っているサンプル）。

**失敗**：
- `Port 5173 is in use` → 別のアプリが使用中。表示された別ポート（例 5174）を開く。
- ブラウザが真っ白 → ターミナルに赤いエラーが出ていないか確認。`npm install` が途中で失敗していたらもう一度実行。

> このあと編集するたびに、保存すると**ブラウザが自動で更新される**（HMR）。`npm run dev` は起動したままにしておく。

## ステップ3：画面を自分の中身に置き換える
**やること**：`src/App.tsx` を、自分で書いた最小の画面に丸ごと置き換える。
**なぜ**：雛形のサンプルを消し、「自分が書いたコードが画面に出る」を体験するため。

エディタで `my-app/src/App.tsx` を開き、中身を**すべて消して**次に置き換える:
```tsx
function App() {
  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>これは自分のReactページ</h1>
      <p>ここから手を加えていきます。</p>
    </main>
  );
}

export default App;
```
保存する。
**画面に見えるもの**：ロゴが消え、**「これは自分のReactページ」という見出し**と説明文だけのシンプルな画面に変わる。

**失敗**：
- 画面が真っ白＋ターミナルに赤いエラー → `export default App;` を消していないか確認。これが無いと Vite がコンポーネントを見つけられない。
- 文字が出ない → ファイルの拡張子は `.tsx`。`.ts` に変えると JSX が型エラーになる。

## ステップ4：useState でカウンタを作る
**やること**：ボタンを押すと数が増えるカウンタを、自分の手で書く。
**なぜ**：React の核は「**状態(state)が変わると画面が追従する**」。`useState` がその入り口。→ [state.md](./state.md)

`src/App.tsx` を次に置き換える:
```tsx
import { useState } from "react";

function App() {
  // count = いまの値、setCount = 値を変える関数。初期値は 0
  const [count, setCount] = useState(0);

  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>これは自分のReactページ</h1>
      <button onClick={() => setCount(count + 1)}>
        押した回数: {count}
      </button>
    </main>
  );
}

export default App;
```
保存する。
**画面に見えるもの**：`押した回数: 0` のボタン。**クリックするたびに 0 → 1 → 2 … と増える**。

**読み解き**：`count` を直接 `count++` してはいけない。**必ず `setCount(...)` で変える**。React は `setCount` が呼ばれたことを合図に画面を描き直す。直接書き換えても画面は更新されない。→ [state.md](./state.md)

**失敗**：
- ボタンを押しても増えない → `onClick={setCount(count + 1)}` のように `()` を付けて即実行していないか。**`onClick={() => setCount(count + 1)}`**（関数を渡す）が正しい。
- `useState is not defined` → 先頭の `import { useState } from "react";` を書き忘れている。

## ステップ5：fetch で公開APIのデータを表示する
**やること**：公開API（ユーザー一覧）からデータを取って、リストで表示する。
**なぜ**：実務のReactは「APIからデータを取って画面に並べる」が大半。その最小形を体験する。→ [data_fetching.md](./data_fetching.md)

`src/App.tsx` を次に置き換える:
```tsx
import { useState, useEffect } from "react";

type User = { id: number; name: string };

function App() {
  const [count, setCount] = useState(0);
  const [users, setUsers] = useState<User[]>([]);

  // 画面が出たあとに1回だけ実行される（API取得）
  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/users")
      .then((res) => res.json())
      .then((data: User[]) => setUsers(data));
  }, []); // ← 空配列＝「最初の1回だけ」

  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>これは自分のReactページ</h1>
      <button onClick={() => setCount(count + 1)}>押した回数: {count}</button>

      <h2>ユーザー一覧（APIから取得）</h2>
      <ul>
        {users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </main>
  );
}

export default App;
```
保存する。
**画面に見えるもの**：カウンタの下に「ユーザー一覧（APIから取得）」が出て、**`Leanne Graham` などの名前が10件ほど並ぶ**。一瞬遅れて表示されるのは、APIからの取得を待っているため。

**読み解き**：
- `useEffect(() => { ... }, [])` の **末尾 `[]`（依存配列）が「最初の1回だけ実行」**の合図。これが無いと毎回の描画で実行され、無限ループになりうる。→ [useeffect.md](./useeffect.md)
- `users.map(...)` で配列を `<li>` に変換して並べる。各要素の `key={user.id}` が「どの行がどれか」をReactに教える。→ [lists_keys.md](./lists_keys.md)

**失敗**：
- リストが空のまま → ネットワーク遮断やAPI側の一時障害。ブラウザの開発者ツール（F12）→ Network タブでリクエストが失敗していないか確認。
- `Failed to fetch` → URL のtypo。`https://jsonplaceholder.typicode.com/users` を正確にコピーする。

## ステップ6：わざと「key 無し警告」を出して直す
**なぜ**：`key` 無しの警告は React で必ず出会う。「自分で起こして直す」と一生忘れない。

`src/App.tsx` の `<li key={user.id}>` から **`key={user.id}` を消す**:
```tsx
{users.map((user) => (
  <li>{user.name}</li>   // ← key を消した
))}
```
保存し、ブラウザで **F12 を押して開発者ツールの Console タブ**を開く。
**結果**：赤または黄色の警告が出る。
```
Warning: Each child in a list should have a unique "key" prop.
```
**読み解き**：これは「リストの各要素に `key`（区別するための目印）を付けて」という警告。`key` が無いと、React はリストが変わったとき**どの行を更新すべきか正しく判断できず**、表示の取り違えやパフォーマンス低下につながる。

直す（`key` を戻す）:
```tsx
{users.map((user) => (
  <li key={user.id}>{user.name}</li>
))}
```
保存する。
**成功**：Console タブの警告が消える。→ key の役割＝「リスト要素の identity（同一性）の目印」を体験で理解できた。→ [lists_keys.md](./lists_keys.md)

> 実務でも「リスト描画したら key 警告が出る」は頻出。`key` には **配列の index ではなく、データ固有のID**（ここでは `user.id`）を使うのが原則。
