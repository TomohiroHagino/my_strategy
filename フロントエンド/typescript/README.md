# TypeScript（フロントエンド）

## 一言で
**JavaScript に静的な型を足した言語**（JSのスーパーセット）。コンパイル時に型チェックして、実行前にバグを潰す。エディタ補完・リファクタが強力になり、**今のフロント実務はほぼTS前提**。最終的にJSへトランスパイルされる。

## 特徴
- **JSの上位互換**：有効なJSはそのままTS。少しずつ型を足せる（漸進的型付け）。
- **構造的型付け**：「形が合えば同じ型」（名前でなく形）。
- **強力な型システム**：ユニオン / ジェネリクス / 型推論 / ナローイング / `keyof`・`typeof`・条件型。
- **実行時には型は消える**：型は開発時の安全装置。バリデーションは別途（zod等）。
- **エディタ体験**：補完・定義ジャンプ・安全なリネームが効く。

## どういう使い方をするのか
- **React / Vue / Next / Nuxt のコンポーネントを型付き**で書く（props・state・APIレスポンス）。
- API契約・ドメインモデルの型定義。
- 大規模・チーム開発での安全性確保。

## 強み / 弱み
- 強み：大規模で壊れにくい・補完が効く・自己ドキュメント化・リファクタ安全。
- 弱み：学習コストと記述量増・**型は実行時に消える**（外部データは別途検証が要る）・ビルド手順が増える。

## まず押さえる中核概念
- 基本型・配列・オブジェクト・`interface` / `type`
- ユニオン型（`A | B`）とナローイング（型の絞り込み）
- ジェネリクス（`<T>`）
- 型推論と `as`（アサーション）の注意
- `unknown` / `never` / オプショナル / `readonly`
- 実行時検証は zod 等で（型≠検証）

## エコシステム・周辺
- コンパイラ: `tsc`、設定: `tsconfig.json`
- 実行時検証: **zod**（型と検証を一本化）
- 土台: [../javascript/](../javascript/)、UI: [../react/](../react/) / [../vue/](../vue/)
