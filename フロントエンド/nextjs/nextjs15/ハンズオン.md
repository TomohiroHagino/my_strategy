# ハンズオン：Next.js（App Router）でページを作り、サーバ取得とルート追加まで動かす

> **このファイルの位置づけ**：他のファイル（[getting_started.md](./getting_started.md) / [server_client_components.md](./server_client_components.md) 等）は「分かっている人が引く辞書」。
> これは**手を動かして1回成功するための実習**。上から順にコピペすれば、0から画面が出るところまで行けます。

## ゴール（終わったら何ができる？）
- `create-next-app` で App Router の雛形を作って、**ブラウザに自分の画面が出る**
- `app/page.tsx` を編集して**トップページを書き換える**
- **Server Component で fetch** して、サーバ側で取得したデータを表示する
- `app/about/page.tsx` を足して**新しいルート（/about）を増やす**
- わざと **`"use client"` 付け忘れ**でボタンが動かない状態を作り、自分で直せる
- ここまでやると [app_router.md](./app_router.md) / [server_client_components.md](./server_client_components.md) / [data_fetching.md](./data_fetching.md) が「読める」ようになる

**所要時間**：25〜35分　**前提**：Node 20+ が入っていること（React の基礎は [../../react/react19/](../../react/react19/) を軽く見ておくと楽）

---

## 準備：Node が使えるか確認
**やること**：Node のバージョンを見る。
**なぜ**：Next.js 15 は新しめの Node を要求する。古いと `create-next-app` で失敗する。
```bash
node -v
```
**成功**：`v20.x.x`（または v22 など）と出る。
**失敗**：
- `command not found` → Node 未インストール。[nodejs.org](https://nodejs.org/) の LTS を入れて再実行。
- `v18` 以下 → LTS（20+）に上げる。

ホームに移動:
```bash
cd ~
```

## ステップ1：create-next-app で雛形を作る
**やること**：対話式に App Router の雛形を生成する。
**なぜ**：Next.js は React の上に「ルーティング・SSR・API」を足したフレームワーク。雛形ツールが TypeScript・ESLint・App Router をまとめて初期設定してくれる。
```bash
npx create-next-app@latest my-next-app
```
質問が出るので、次のように答える（**App Router を Yes にするのが最重要**）:
```
✔ Would you like to use TypeScript?        → Yes
✔ Would you like to use ESLint?            → Yes
✔ Would you like to use Tailwind CSS?      → Yes
✔ Would you like your code inside a `src/` directory?  → No（このハンズオンは No 前提）
✔ Would you like to use App Router?        → Yes  ★これが前提
✔ Would you like to use Turbopack for next dev?  → Yes
✔ Would you like to customize the import alias?  → No
```
**成功**：`Success! Created my-next-app at ...` と表示される。
**失敗**：
- `npx: command not found` → Node を入れ直す。
- 途中で固まる → ネットワークを確認して再実行。

> **`src/` を No** にしたので、このハンズオンでは `app/...` というパスで進める。Yes にした場合は `src/app/...` に読み替える。

## ステップ2：開発サーバを起動する
**やること**：プロジェクトに入って `npm run dev`。
**なぜ**：雛形のまま起動して「動く土台」を目で確認するため。
```bash
cd my-next-app
npm run dev
```
**成功**：ターミナルに次が出る。
```
  ▲ Next.js 15.x.x
  - Local:   http://localhost:3000
```
ブラウザで **http://localhost:3000** を開く。
**画面に見えるもの**：Next.js の初期スタートページ（Next のロゴ、`Get started by editing app/page.tsx` などのリンクが並ぶ画面）。

**失敗**：
- `Port 3000 is in use` → 表示された別ポートを開く、または他のアプリを止める。
- 真っ白＋赤エラー → `npm install` が失敗していた可能性。`npm install` を実行してから再度 `npm run dev`。

> このあとファイルを保存すると**ブラウザが自動更新**される。`npm run dev` は起動したままにしておく。

## ステップ3：トップページを自分の中身に置き換える
**やること**：`app/page.tsx` を、自分で書いた最小の画面に丸ごと置き換える。
**なぜ**：「`app/page.tsx` ＝ `/` の画面」という App Router の規約を体験するため。→ [app_router.md](./app_router.md)

エディタで `my-next-app/app/page.tsx` を開き、中身を**すべて消して**次に置き換える:
```tsx
export default function Home() {
  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>これは自分のトップページ</h1>
      <p>App Router の page.tsx を書き換えました。</p>
    </main>
  );
}
```
保存する。
**画面に見えるもの**：初期スタートページが消え、**「これは自分のトップページ」という見出し**の画面に変わる。

**失敗**：
- 画面が真っ白＋`The default export is not a React Component` → `export default` を消していないか確認。`page.tsx` は **default export の関数**が必須。
- 何も変わらない → 編集したのが `my-next-app/app/page.tsx` か、パスを再確認（`src/` を選んだ人は `src/app/page.tsx`）。

## ステップ4：Server Component で fetch する
**やること**：トップページで、サーバ側で公開APIからデータを取って表示する。
**なぜ**：App Router のコンポーネントは**既定でサーバ実行**。`async` 関数にして `await fetch` を書けるのが React 単体との大きな違い。→ [server_client_components.md](./server_client_components.md) / [data_fetching.md](./data_fetching.md)

`app/page.tsx` を次に置き換える:
```tsx
type User = { id: number; name: string };

// async コンポーネント＝サーバ側で実行され、await で取得できる
export default async function Home() {
  const res = await fetch("https://jsonplaceholder.typicode.com/users");
  const users: User[] = await res.json();

  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>これは自分のトップページ</h1>
      <h2>ユーザー一覧（サーバで取得）</h2>
      <ul>
        {users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </main>
  );
}
```
保存する。
**画面に見えるもの**：見出しの下に**ユーザー名が10件ほど並ぶ**。React 単体（useEffect）と違い、**最初の表示時点ですでにデータが入っている**（サーバ側で取得してからHTMLを返すため、一瞬の空白が無い）。

**読み解き**：
- コンポーネントの先頭に `"use client"` が**無い**ので、これは**Server Component**。サーバで `fetch` してHTMLを組み立てて返す。`useState`/`useEffect` は不要。
- ブラウザで「ページのソースを表示」すると、ユーザー名がすでにHTMLに含まれているのが確認できる（サーバレンダリングの証拠）。

**失敗**：
- リストが空 → API一時障害かネットワーク。ターミナルに `fetch failed` が出ていないか確認。
- `await is only valid in async functions` → 関数に `async` を付け忘れている。`export default async function` が正しい。

## ステップ5：ルートを増やす（/about ページ）
**やること**：`app/about/page.tsx` を新規作成して、`/about` でアクセスできるページを足す。
**なぜ**：App Router は「**フォルダ＝URL**」。`page.tsx` を置いた場所がそのままURLになる規約を体験する。→ [routing.md](./routing.md)

フォルダとファイルを作る:
```bash
mkdir -p app/about
```
`my-next-app/app/about/page.tsx` を新規作成して次を書く:
```tsx
import Link from "next/link";

export default function About() {
  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>About ページ</h1>
      <p>app/about/page.tsx を置いただけで /about になりました。</p>
      <Link href="/">← トップに戻る</Link>
    </main>
  );
}
```
保存し、ブラウザで **http://localhost:3000/about** を開く。
**画面に見えるもの**：**「About ページ」という見出し**と、トップへ戻るリンク。リンクを押すとトップに移動する。

**読み解き**：`app/about/` フォルダに `page.tsx` を置いただけで `/about` が出来た。ルータの設定ファイルを書く必要が無いのが App Router。→ [app_router.md](./app_router.md)

**失敗**：
- `/about` が **404** → フォルダ名かファイル名のtypo。`app/about/page.tsx`（小文字 `page`）を確認。フォルダを作っただけでは不十分で、**`page.tsx` が必須**。

## ステップ6：わざと `"use client"` 付け忘れでイベントが動かない状態を作って直す
**なぜ**：「Server Component ではブラウザのイベント（onClick）や useState が使えない」は Next.js 15 で最も多いつまずき。自分で起こして直すと腹落ちする。

`app/about/page.tsx` を次に置き換える（**わざと `"use client"` を付けない**）:
```tsx
import { useState } from "react";

export default function About() {
  const [count, setCount] = useState(0);

  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>About ページ</h1>
      <button onClick={() => setCount(count + 1)}>押した回数: {count}</button>
    </main>
  );
}
```
保存して **http://localhost:3000/about** を開く（または再読み込み）。
**結果**：画面に赤いエラーが出る。
```
You're importing a component that needs `useState`. This React hook only
works in a client component. To fix, mark the file (or its parent) with
the `"use client"` directive.
```
**読み解き**：`app/` 配下のコンポーネントは**既定でサーバ実行**。サーバには「クリック」も「状態の保持」も無いので、`useState` や `onClick` は使えない。**対話が要る部品だけ**、ファイル先頭に `"use client"` を書いて「これはブラウザ側で動かす」と宣言する必要がある。→ [server_client_components.md](./server_client_components.md)

直す（ファイルの**一番上の行**に `"use client"` を足す）:
```tsx
"use client";

import { useState } from "react";

export default function About() {
  const [count, setCount] = useState(0);

  return (
    <main style={{ padding: 24, fontFamily: "sans-serif" }}>
      <h1>About ページ</h1>
      <button onClick={() => setCount(count + 1)}>押した回数: {count}</button>
    </main>
  );
}
```
保存する。
**成功**：エラーが消え、**ボタンを押すと数字が増える**。→ 「対話が要る部品は Client Component（`"use client"`）」を体験で理解できた。

> 実務では「全部に `"use client"` を付ける」と Server Component の利点（サーバでのデータ取得・JS削減）が消える。**必要な葉の部品だけ**に留めるのが原則。→ [server_client_components.md](./server_client_components.md)
