# 設計（ソフトウェア設計・アーキテクチャ）

> 特定の言語・フレームワークに属さず、**どう分割し・どう依存させ・どうモデリングするか**という設計思想を置く場所。
> 言語/FWの「上」のレイヤ。[言語共通概念/](../言語共通概念/) が *言語レベルの挙動の違い*（値渡し・型・並行）を扱うのに対し、ここは *設計レベルの判断*（層・依存方向・ドメインモデル）を扱う。

## なぜ分けるか
DDD やクリーンアーキは Ruby でも Go でも Java でも通用する**言語横断の設計判断**で、各FWのリファレンス（rails7/ や laravel11/）に書くと重複し、どこに書いたか分からなくなる。設計思想は1か所に集約し、各FWからはここへリンクする。

## 項目
- [ddd.md](./ddd.md) … ドメイン駆動設計。**戦略的設計（境界づけられたコンテキスト・ユビキタス言語・コンテキストマップ）＋戦術的設計（エンティティ/値オブジェクト/集約/リポジトリ）** の2階建て。「戦術だけ真似ると命名規約になる」罠まで。
- [クリーンアーキテクチャ.md](./クリーンアーキテクチャ.md) … 依存性のルール（依存は内向き一方通行）＋DIP（依存性逆転）。ヘキサゴナル/オニオンとの関係、制御フローと依存フローが逆になる罠、DDDとの直交関係。
- [solid.md](./solid.md) … オブジェクト指向設計の5原則（SRP/OCP/LSP/ISP/DIP）。「5つは結局『変更に強くする』ための別角度の言い換え」。各原則を良い/悪いの対比で。
- [レイヤードアーキテクチャ.md](./レイヤードアーキテクチャ.md) … プレゼン/アプリ/ドメイン/インフラの古典4層。MVC・3層との関係、上→下依存がDIPでインフラを外へ追い出す方向に進化する橋渡し。
- [cqrsとイベントソーシング.md](./cqrsとイベントソーシング.md) … 読み書きでモデルを分けるCQRSと、状態でなくイベント列を真実とするES。**2つは別物・片方でも成立する**を強調。
- [デザインパターン.md](./デザインパターン.md) … GoF **23個を全網羅**（生成5／構造7／振る舞い11）。各パターンに実務頻度（★）を付け、よく使うものは擬似コード図つき。末尾に全23個の早見表、「パターン病＝当てはめにいく」罠まで。
- [モノリスとマイクロサービス.md](./モノリスとマイクロサービス.md) … モノリス / モジュラモノリス / マイクロサービスの比較と**境界の引き方**。DDDの境界づけられたコンテキストが分割線、コンウェイの法則、分散モノリスの罠。
- [エラー設計.md](./エラー設計.md) … Result/Option（値で返す）vs 例外（投げる）の**使い分けという設計判断**。「想定内の失敗か想定外のバグか」の線引き。言語ごとの仕組みは [../言語共通概念/エラー処理.md](../言語共通概念/エラー処理.md)。
