# 生成AI（LLMアプリ開発）

> **生成AI（主にLLM）を"組み込んで・動かして・運用する"側**の知見をまとめる場所。
> モデルそのものの中身（Transformer の理論・学習・量子化）ではなく、**API として呼んでプロダクトに載せる**ときに必要な実務——プロンプト設計・RAG・エージェント・評価・コスト/レイテンシ運用——に重心を置く。
> 「作って動かして運用する」というこのリポジトリ全体の方針の、生成AI版。

## まず立ち位置（このフォルダが扱う範囲）
```
 扱う      … API利用 / プロンプト設計 / RAG / エージェント(tool use) / 評価 / 監視 / コスト・レイテンシ運用
 扱わない  … モデルの学習・ファインチューニング詳細 / Transformer の数式 / GPU サービング基盤
           （= 将来 生成AI/モデル基礎/ を足すならそちら。今は「アプリ開発レイヤ」に集中）
```

LLM は「**確率的に次のトークンを予測し続けるテキスト生成器**」。DB のように決定的でも冪等でもない。だから普通のソフトウェアと違い、**出力がブレる前提で「設計・検証・監視」する**のがこのレイヤの肝になる。

## 項目（各ファイルへ）
- [llm基礎.md](./llm基礎.md) … LLM の動作原理を実務目線で。**トークン / コンテキストウィンドウ / 温度・top_p / 推論パラメータ / ストリーミング / 主要モデルの選び方**。まずここ。
- [プロンプト設計.md](./プロンプト設計.md) … **指示の書き方 / システムプロンプト / Few-shot / 構造化出力(JSON) / プロンプトインジェクション対策**。最小コストで品質を上げる第一手段。
- [rag.md](./rag.md) … **検索拡張生成**。埋め込み(embedding)・ベクトルDB・チャンク戦略・ハイブリッド検索・再ランク。「自社データに基づいて答えさせる」の定番。
- [エージェント.md](./エージェント.md) … **tool use / 関数呼び出し / ReActループ / マルチエージェント**。LLM に「外の世界を操作させる」設計。
- [mcp.md](./mcp.md) … **Model Context Protocol**。ツール/データ/プロンプトをLLMに"つなぐ"標準（Host/Client/Server・3 primitives・トランスポート・セキュリティ）。tool use の接続を標準化するレイヤ。
- [評価と監視.md](./評価と監視.md) … **eval（LLM-as-judge / ゴールデンセット）・ハルシネーション対策・トレース・オブザーバビリティ**。「ブレる出力」を測って守る。
- [運用とコスト.md](./運用とコスト.md) … **レイテンシ / プロンプトキャッシュ / トークン課金 / レート制限 / フォールバック**。本番で金と速度を破綻させないための運用。

> **🖐 ハンズオン（実習編）** → [ハンズオン/](./ハンズオン/)。上の各項目を **0からコピペで動かして1回成功する**実習（共通setup＋項目別の計8本）。実APIのクラウドLLM（**Claude / Gemini / ChatGPT**）を使い、主軸はClaude。各ステップに「やること/なぜ/成功/失敗の原因」＋わざと壊して直す章つき。まず [ハンズオン/setup.md](./ハンズオン/setup.md) から。

## 全体像（リクエスト1回の流れ）
```
ユーザー入力
  └─[入力検証・PII除去]→ プロンプト組み立て（システム＋文脈＋指示）
        └─（RAG なら）検索→関連文書を文脈に注入
              └─ LLM API 呼び出し（モデル/温度/最大トークン/tool定義）
                    ├─ tool 呼び出しが返る → ツール実行 → 結果を返して再度LLM（エージェントループ）
                    └─ テキスト/JSON が返る
                          └─[出力検証・スキーマ検証・ガードレール]→ ユーザーへ（ストリーミング）
  ※ 全段で トレース記録 / トークン・コスト計測 / レイテンシ計測（→ 評価と監視・運用とコスト）
```

## 設計判断の早見（どれを使うか）
| やりたいこと | まず使う | 重い手段（必要なら） |
|---|---|---|
| 出力の質を上げたい | **プロンプト設計**（指示・Few-shot・構造化出力） | ファインチューニング |
| 最新/社内情報に基づかせたい | **RAG**（検索して文脈に注入） | ファインチューニング |
| 外部システムを操作させたい | **tool use / 関数呼び出し** | フルエージェント＋MCP |
| 決まった形式で受け取りたい | **構造化出力 / JSONスキーマ** | パーサ＋リトライ |
| 嘘・暴走を抑えたい | **eval＋ガードレール＋温度↓** | ヒューマンインザループ |

> 原則：**安い順・軽い順に試す**。プロンプトで足りるならファインチューニングしない（YAGNI）。RAG で足りるなら学習しない。
