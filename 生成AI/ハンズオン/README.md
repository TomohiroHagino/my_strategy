# 生成AI ハンズオン（LLMアプリ開発・実習編）

> リファレンス（[../](../)）が「分かっている人の辞書」なのに対し、ここは **0からコピペで動かして1回成功する実習**。
> 各ステップに「やること / なぜ / こう出たら成功 / こう出たら失敗の原因」を付け、最後に**わざとエラーを起こして直す**章で定着させる。

## 前提・方針
- **実APIのクラウドLLM**を使う（**Claude / Gemini / ChatGPT**）。主軸の実例は **Claude（Anthropic API）**、要所で **Gemini / OpenAI の読み替え**を添える。
- 言語は **Python**（最も例が多く短い）。Node等でも考え方は同じ。
- **APIキーと少額の課金が要る**。各ハンズオンは**Haiku等の安いモデル＋短い出力**で、1回あたり日本円で数円〜数十円に収まるように設計。
- 環境構築は[setup.md](./setup.md)に集約（重複を避けるため、各ハンズオンはここを済ませた前提で始まる）。

## 進め方（順番）
```
0. setup.md          ← まずここ（キー取得・環境変数・疎通確認）必須
1. llm基礎.md         ← 最初のAPI呼び出し・トークン計測・温度・ストリーミング
2. プロンプト設計.md   ← system/Few-shot/構造化出力(JSON)・インジェクション体験
3. rag.md            ← 埋め込み→検索→文脈注入で「自社データに答えさせる」最小RAG
4. エージェント.md     ← tool use（関数呼び出し）でLLMに計算/検索をさせる
5. mcp.md            ← MCPサーバを1個作ってクライアントから叩く
6. 評価と監視.md       ← ゴールデンセット＋LLM-as-judge＋トークン/コスト計測
7. 運用とコスト.md     ← プロンプトキャッシュ・リトライ・レート制限対策を体感
```
上から順にやると積み上がる（2のJSON出力を4で使う、1のトークン計測を6/7で使う…）。

## 各ハンズオンの構成（共通フォーマット）
```
## ゴール（このハンズオンで何が動くか）
## 完成イメージ（最終的に動くコード/出力）
## ステップ1..N
   - やること / なぜ / 実行 / こう出たら成功 / こう出たら失敗の原因
## わざと壊して直す（エラー体験）
## 片付け / 次へ
```

## 安全・コスト上の注意
- **APIキーはコードに書かない**。環境変数（`export ANTHROPIC_API_KEY=...`）。`git add` に混ぜない。
- 各スクリプトに `max_tokens` を必ず付ける（課金暴走防止）。エージェント章は**ループ上限**も付ける。
- 動かしっぱなしにしない。検証が終わったらキーの利用状況をダッシュボードで確認する。
