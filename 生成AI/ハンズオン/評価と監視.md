> 対応する理屈 → [../評価と監視.md](../評価と監視.md)。前提 → [setup.md](./setup.md)。

## ゴール
**ゴールデンセットで自動採点（回帰検知）**・**LLM-as-judge で自由文を採点**・**トークン/コスト/レイテンシを記録**の3つを手で動かし、「ブレる出力を測って守る」を体得する。

---

## ステップ1：分類タスクをゴールデンセットで採点（ルールベース）
**やること**：入力と正解ラベルの固定データで、正答率を測る。
```python
# eval_rule.py
import anthropic
client = anthropic.Anthropic()

GOLDEN = [   # 代表例＋難しめの例を混ぜる
    ("解約したいです",        "cancel"),
    ("領収書を再発行して",    "invoice"),
    ("二重に請求されてる",    "billing_issue"),
    ("ありがとう、解決しました", "thanks"),
]
LABELS = "cancel / invoice / billing_issue / thanks / other"

def classify(text):
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=20, temperature=0,
        system=f"問い合わせを次のどれかに分類し、ラベルだけ出力: {LABELS}",
        messages=[{"role": "user", "content": text}])
    return "".join(b.text for b in r.content if b.type == "text").strip().lower()

ok = 0
for text, gold in GOLDEN:
    pred = classify(text)
    hit = gold in pred
    ok += hit
    print(f"{'OK ' if hit else 'NG '} 入力={text!r} 期待={gold} 予測={pred}")
print(f"正答率: {ok}/{len(GOLDEN)} = {ok/len(GOLDEN):.0%}")
```
**なぜ**：分類・抽出は**完全一致で安く確実に測れる**。プロンプトやモデルを変えたら再実行＝**回帰検知**。
**成功**：各行の OK/NG と正答率が出る。
**失敗の原因**：NGが多い → systemやラベル定義を改善し、**同じGOLDENで**再測定。場当たりに直さず数値で比べる。

## ステップ2：プロンプトを変えて回帰を比べる
**やること**：systemを少し変え、正答率が上がったか下がったかを**数値で**比較。
**なぜ**：「良くなった気がする」を卒業する。**evalは変更の良し悪しを数値で言う道具**。
**成功**：2つのsystemで正答率が並んで出て、優劣が判断できる。
**失敗の原因**：毎回違う入力で比べる → ゴールデンセットは固定。固定データで差を見る。

## ステップ3：自由文を LLM-as-judge で採点
**やること**：要約タスクの出力を、別のClaude呼び出しに基準付きで採点させる。
```python
# eval_judge.py
import anthropic
client = anthropic.Anthropic()

SOURCE = "弊社は本日、新しい有給制度を発表した。来年度から繰越上限が20日に拡大される。"

def summarize(text):
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=120,
        messages=[{"role": "user", "content": f"次を1文で要約: {text}"}])
    return "".join(b.text for b in r.content if b.type == "text").strip()

def judge(source, summary):
    rubric = f"""次の要約を採点。基準: (1)事実に忠実か (2)1文か (3)重要点(20日/来年度)を含むか。
0〜5点の整数と一言理由だけ返す。
原文: {source}
要約: {summary}"""
    r = client.messages.create(model="claude-opus-4-8", max_tokens=120, temperature=0,
        messages=[{"role": "user", "content": rubric}])   # judgeは別(できれば賢い)モデル
    return "".join(b.text for b in r.content if b.type == "text").strip()

s = summarize(SOURCE)
print("要約:", s)
print("採点:", judge(SOURCE, s))
```
**なぜ**：自由文は機械一致で測れない → **基準(rubric)を渡して別モデルに採点**させる。生成と評価を分けると独立性が上がる。
**成功**：点数＋理由が返る。要約をわざと崩すと点が下がる。
**失敗の原因**：judgeを盲信 → judge自体にバイアス。**人手評価と突き合わせて校正**する前提で使う。

## ステップ4：トークン・コスト・レイテンシを記録
**やること**：1回の呼び出しの実数を計測・記録する。
```python
# observe.py
import time, anthropic
client = anthropic.Anthropic()

# 料金（per 1M tokens）は変動するので必ず公式で最新確認。ここは概算の例
PRICE = {"claude-haiku-4-5": (1.0, 5.0)}   # (入力$/1M, 出力$/1M)

model = "claude-haiku-4-5"
t0 = time.time()
r = client.messages.create(model=model, max_tokens=200,
    messages=[{"role": "user", "content": "AIを3行で説明して"}])
dt = time.time() - t0

it, ot = r.usage.input_tokens, r.usage.output_tokens
pin, pout = PRICE[model]
cost = it/1e6*pin + ot/1e6*pout
print(f"入力={it} 出力={ot} 推定コスト=${cost:.6f} レイテンシ={dt:.2f}s")
```
**なぜ**：本番で**何が起きたか見る**には最低限これを記録する。コスト急増・遅延に早く気づける。
**成功**：トークン・推定コスト・秒が表示される。
**失敗の原因**：料金を焼き込んで放置 → 単価は変わる。`PRICE` は公式で更新。PIIをログに残さない（マスクする）。

## ステップ5：ガードレール（出力を実行時チェック）
**やること**：JSONで返すはずの出力を**スキーマ検証し、失敗なら1回だけ再試行**。
```python
import json
def get_json_with_retry(prompt, tries=2):
    for i in range(tries):
        r = client.messages.create(model="claude-haiku-4-5", max_tokens=200, temperature=0,
            messages=[{"role": "user", "content": prompt}])
        text = "".join(b.text for b in r.content if b.type == "text")
        try:
            return json.loads(text)                  # 通れば採用
        except json.JSONDecodeError:
            prompt += "\n※前回JSONとして不正だった。JSONのみを出力して。"  # エラーを添えて再試行
    raise ValueError("規定回数で有効なJSONが得られず")
```
**なぜ**：evalが事後/定期なのに対し、ガードレールは**1回ごとの実行時防御**。「LLM出力は信頼しない」をコードで担保。
**成功**：壊れたJSONが返っても再試行で復帰する。
**失敗の原因**：無限リトライ → 回数上限を必ず。

## わざと壊して直す
1. ステップ1で `temperature=1` に上げる → 分類がブレてNGが増える。**分類は温度0**に戻す＝evalが温度の悪さを検出した状態。
2. ステップ3で要約プロンプトを「3文で」に変える → judgeの(2)1文の基準で減点される。基準が効いていると分かる。
