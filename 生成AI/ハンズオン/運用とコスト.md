## ステップ1：プロンプトキャッシュで節約＆高速化
**やること**：長い共通文脈をキャッシュし、2回目以降が安く速くなるのを `usage` で確認する。
```python
# cache.py
import anthropic
client = anthropic.Anthropic()

BIG_CONTEXT = "（社内規程の長文…）" * 400   # 1024トークン以上ある共通の前置き

def ask(q):
    r = client.messages.create(
        model="claude-haiku-4-5", max_tokens=120,
        system=[{                                # 共通＝安定部分をキャッシュ対象に
            "type": "text", "text": BIG_CONTEXT,
            "cache_control": {"type": "ephemeral"},
        }],
        messages=[{"role": "user", "content": q}],   # 可変部分は messages 側（末尾）
    )
    u = r.usage
    print(f"write={u.cache_creation_input_tokens} read={u.cache_read_input_tokens} "
          f"uncached_input={u.input_tokens}")
    return r

ask("規程の要点は？")    # 1回目: write>0（キャッシュ書き込み）
ask("罰則はある？")      # 2回目: read>0（キャッシュ読み出し＝安い・速い）
```
**なぜ**：共通の長い接頭辞をサーバ側でキャッシュ。**安定部分を前・可変部分を後**に置くのがコツ（接頭辞が1バイトでも変わると無効）。
**成功**：1回目 `write` が立ち、2回目 `read` が立つ。
**失敗の原因**：
- 2回目も read=0 → **可変部分を前に置いた**／`datetime.now()` 等を接頭辞に混ぜた（無効化）。安定部分を完全固定する。
- そもそもwriteが0 → 接頭辞が短すぎ（最低トークン数未満）。`BIG_CONTEXT` を伸ばす。

## ステップ2：完全一致キャッシュ（自前・LLMを呼ばない）
**やること**：同じ質問は辞書から即返してLLMを呼ばない。
```python
import hashlib
_cache = {}
def cached_ask(q):
    key = hashlib.sha256(q.encode()).hexdigest()
    if key in _cache:
        print("（キャッシュヒット：API呼ばず）")
        return _cache[key]
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=120,
        messages=[{"role": "user", "content": q}])
    ans = "".join(b.text for b in r.content if b.type == "text")
    _cache[key] = ans
    return ans

cached_ask("営業時間は？"); cached_ask("営業時間は？")   # 2回目はAPIを呼ばない
```
**なぜ**：FAQ・定型質問は**コスト0・激速**。実務はRedis等に置く（[../../データベース/redis.md](../../データベース/redis.md)）。必ずTTLを付ける。
**成功**：2回目に「キャッシュヒット」が出る。
**失敗の原因**：TTL無しで永遠に残す → 古い答えを返し続ける。実務ではTTL必須。

## ステップ3：リトライ＋指数バックオフ
**やること**：一時エラー（429/5xx）を待って再試行する。
```python
import time, random, anthropic
client = anthropic.Anthropic()

def call_with_retry(prompt, tries=5):
    for i in range(tries):
        try:
            return client.messages.create(model="claude-haiku-4-5", max_tokens=100,
                messages=[{"role": "user", "content": prompt}])
        except anthropic.RateLimitError:                 # 429
            wait = min(2**i + random.random(), 30)       # 指数＋ジッタ
            print(f"レート制限。{wait:.1f}s 待って再試行({i+1}/{tries})"); time.sleep(wait)
        except anthropic.APIStatusError as e:
            if e.status_code >= 500:                     # サーバ側一時障害
                time.sleep(2**i); continue
            raise                                        # 4xxは再試行しない
    raise RuntimeError("リトライ上限")
```
**なぜ**：外部API依存＝**落ちる前提**。指数バックオフ＋ジッタで雪崩を防ぐ。
> Anthropic SDKは既定で429/5xxを自動リトライ（`max_retries`）。**まずSDK標準を使い**、独自制御は必要時だけ。
**成功**：通常時はそのまま返り、混雑時は待って再試行する。
**失敗の原因**：4xx（キー不正等）まで再試行 → 無駄。**4xxは即raise**、リトライは429/5xxだけ。

## ステップ4：モデルルーティング（タスクに最小のモデル）
**やること**：軽い分類は安いモデル、難しい推論だけ賢いモデルに振り分ける。
```python
def route(task_type, prompt):
    model = "claude-haiku-4-5" if task_type in ("classify", "extract", "summarize") \
            else "claude-opus-4-8"     # 難しい推論だけ上位
    r = client.messages.create(model=model, max_tokens=300,
        messages=[{"role": "user", "content": prompt}])
    print(f"[{model}] で処理")
    return "".join(b.text for b in r.content if b.type == "text")

route("classify", "『解約したい』を分類して")          # → 安いHaiku
route("reasoning", "この設計のトレードオフを多角的に分析して")  # → Opus
```
**なぜ**：**コスト削減の効く順の筆頭**。分類/抽出/要約は小型で十分なことが多い。賢い＝高い＆遅い。
**成功**：タスク種別で使うモデルが切り替わる。
**失敗の原因**：全部を最上位モデルで処理 → 桁違いに高い。**まず小型で足りるか試す**。

## ステップ5：出力を短くしてレイテンシ＆コストを下げる
**やること**：同じ質問を「冗長」と「簡潔指示＋小max_tokens」で比べる。
```python
import time
def measure(system, max_t):
    t0 = time.time()
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=max_t, system=system,
        messages=[{"role": "user", "content": "RAGとは？"}])
    dt = time.time() - t0
    print(f"出力tok={r.usage.output_tokens} {dt:.2f}s")

measure(None, 600)                          # 冗長
measure("1文で簡潔に。前置き禁止。", 80)      # 簡潔
```
**なぜ**：生成時間もコストも**出力長に比例**。「短く答えさせる」だけで両方下がる。
**成功**：簡潔版の方が出力トークンも秒数も小さい。

## わざと壊して直す
1. ステップ1で `BIG_CONTEXT` の先頭に `time.time()` の値を差し込む → 毎回キャッシュが無効化され read=0。**接頭辞に可変値を入れない**を体で覚える。戻す。
2. ステップ3で `except RateLimitError` を消す → 混雑時にそのまま落ちる。リトライ（かSDK標準）を戻す。
3. ステップ4で reasoning も Haiku に固定 → 難問の質が落ちる。賢いモデルに戻す＝**ルーティングの価値**。
