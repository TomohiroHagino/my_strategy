# AIコーディングエージェント（Claude Code を使いこなす）

> **AIコーディングエージェント（主に Claude Code）を"開発の道具として使い倒す"側**の知見をまとめる場所。
> [生成AI/](../生成AI/) が「LLMを**アプリに組み込んで作る**側」なら、ここは「**できあがったAIエージェントを開発作業で使う**側」。同じLLMでも立ち位置が真逆なので別軸として切り出す。
> 「作って動かして運用する」というこのリポジトリ全体の方針を、**開発そのものの生産性**に向ける版。

## まず立ち位置（このフォルダが扱う範囲）
```
 扱う      … Claude Code の使い方 / スラッシュコマンド / サブエージェント / フック /
            設定・メモリ(CLAUDE.md) / MCP連携 / plan mode / 実践ワークフロー / API・SDK連携
 扱わない  … LLMをアプリに組み込む実装そのもの（→ ../生成AI/）
            プロンプト工学の一般論（→ ../生成AI/プロンプト設計.md）
```

Claude Code は「**ターミナルで動く"エージェント型"のコーディング支援**」。チャットUIと違い、**自分でファイルを読み・編集し・コマンドを実行し・検証まで回す**。だから使いこなしの肝は「うまく聞く」ではなく、**「文脈をどう与え・どこまで自動化を許し・どう検証させるか」を設計すること**にある。

## 全体像（1タスクを回す流れ）
```
やりたいこと（自然言語 or /スラッシュコマンド）
  └─[文脈の供給] CLAUDE.md（常時）＋ 明示の参照(@file) ＋ 必要ならMCP/サブエージェントで調査
        └─[plan mode で計画] 探索→計画を提示→人が承認（破壊的・大規模ほど必須）
              └─[実装] Read/Edit/Write/Bash でファイル編集・コマンド実行
                    ├─ Hooks（PreToolUse: 検証/ガード, PostToolUse: 整形/型チェック）
                    └─ サブエージェント（独立調査・並列レビュー）
                          └─[検証] テスト・ビルド・レビュー（code-reviewer 等）
                                └─[コミット/PR]（人の指示があってから）
  ※ 長くなったら /compact or /clear で文脈を整理。永続知見は CLAUDE.md / メモリへ。
```

## 設計判断の早見（どの機能を使うか）
| やりたいこと | まず使う | 重い手段（必要なら） |
|---|---|---|
| 毎回同じ前提を読ませたい | **CLAUDE.md**（プロジェクト/ユーザー） | サブエージェントの専用プロンプト |
| 定型作業を再利用したい | **スラッシュコマンド / Skill** | サブエージェント化 |
| 大きめの変更を安全にしたい | **plan mode**（計画を承認してから実装） | TDD＋code-reviewer |
| 「毎回必ずやる」を強制したい | **Hooks**（整形・ガード・検証） | CI 側で再強制 |
| 文脈を汚さず深掘り/並列調査したい | **サブエージェント** | 複数サブエージェント並列 |
| 外部システムを操作させたい | **MCP** で接続 | 自作 MCP サーバ |
| CI/自動化に組み込みたい | **print モード(-p)** | **Agent SDK / API** |

> 原則：**安い順・軽い順に試す**（YAGNI）。CLAUDE.md とスラッシュコマンドで足りるなら、フックもサブエージェントも作らない。**自動化を増やすほど"暴走時の被害"も増える**ので、許可範囲は最小から広げる。

## 拡張の置き場所（全体像）
Claude Code の拡張は、**ユーザー全体（ホーム）**と**プロジェクト（リポジトリ）**の2階層に、同じ構造で置く。これを押さえると各ファイルの話が地図上で繋がる。
```
~/                                  ← ユーザー全体（全プロジェクト共通）
└── .claude/
    ├── settings.json               … 権限・フック・モデル・環境変数  → 05_設定とメモリ / 04_フック
    ├── CLAUDE.md                    … 自分のクセ・全PJ共通の前提       → 05_設定とメモリ
    ├── commands/                    … 自作スラッシュコマンド            → 02_スラッシュコマンドとスキル
    └── agents/                      … サブエージェント定義              → 03_サブエージェント

<repo>/                             ← プロジェクト（このリポジトリ専用）
├── CLAUDE.md                       … このリポの前提・規約（直下・コミット） → 05_設定とメモリ
└── .claude/
    ├── settings.json               … チーム共有の設定（コミット）
    ├── settings.local.json         … 個人の上書き（.gitignore）
    ├── commands/                   … このリポ専用コマンド
    └── agents/                     … このリポ専用サブエージェント
```
- 「同じ名前は**より具体的（local > project > user）が勝つ**」が全体の優先ルール（詳細は [05_設定とメモリ.md](./05_設定とメモリ.md)）。
- **MCP** はこの settings に接続先を登録して外部ツールを生やす（→ [06_mcp連携.md](./06_mcp連携.md)）。

## このリポジトリ自体との関係
- この学習リスト自体、Claude Code で執筆・整理している。**「書式テンプレを CLAUDE.md に書く → スラッシュコマンドで章を生成 → code-reviewer で整合性チェック」**のような使い方がそのまま実例になる。
- 設定・ルールの実体は `~/.claude/`（ユーザー全体）と各プロジェクトの `.claude/` に置かれる。
