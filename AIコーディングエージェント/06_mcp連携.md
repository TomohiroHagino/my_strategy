# MCP 連携（Claude Code から見た）

## ひとことで言うと
**Claude Code に外部のツール・データを"つなぐ"口が MCP**。ファイルシステムや git のような内蔵能力に加え、**GitHub・DB・Slack・社内API・ブラウザ操作**などを、MCP サーバを登録するだけで「使えるツール」として生やせる。規格そのものは [../生成AI/mcp.md](../生成AI/mcp.md)、ここでは**使う側の運用**に絞る。

## なぜ必要か / どこで効くか
- Claude Code 単体でもファイル編集・コマンド実行はできるが、**外部システムの操作・参照**はそのままではできない。
- MCP サーバを接続すると、**LLMが「ツール」として外部を読み書き**できるようになる（例：Issue 作成、DB クエリ、ドキュメント検索）。
- 1度サーバ化すれば **IDE・チャット・自作エージェントなど他のホストからも同じ口**で使える（再利用）。
- 効くのは：**チケット連携 / DB参照 / 社内ナレッジ検索 / デザインツール連携 / ブラウザ自動操作**。

> 位置づけ：Claude Code は MCP の **Host**。内部に **Client** を持ち、各 **Server**（能力提供側）と1対1で接続する。実行を許可するのは常にホスト側＝あなた。

## 接続のしかた（運用イメージ）
```
1. 使いたい MCP サーバを選ぶ（既製 or 自作）
2. 設定にサーバの「起動コマンド or URL」を登録
      - ローカル: stdio（子プロセス起動）
      - リモート: Streamable HTTP（URL接続）
3. 接続後、サーバが公開するツールが Claude Code から見えるようになる
4. ツール実行（特に書き込み系）は権限設定/承認で制御
```
- **ローカルツール**（ファイル・CLI・ローカルDB）は **stdio** が手軽。
- **リモート/SaaS** は **Streamable HTTP**（旧 HTTP+SSE 単体方式は置き換え済み）。
- 接続スコープは**プロジェクト単位・ユーザー単位**で分けられる（このリポだけ／全PJ共通）。

## サーバが公開する3要素（おさらい）
| 要素 | Claude Code 側での見え方 | 誰が起動 |
|---|---|---|
| **Tools** | 呼び出せる関数（Issue作成・クエリ実行 等） | モデルが判断して呼ぶ |
| **Resources** | 文脈に渡せるデータ（ファイル/レコード） | アプリ/ユーザーが選ぶ |
| **Prompts** | 再利用プロンプト（スラッシュ的） | ユーザーが起動 |

- 詳しい3 primitives・JSON-RPC・トランスポートは [../生成AI/mcp.md](../生成AI/mcp.md) を参照。

## どこで使うか（開発の具体例）
- **GitHub/GitLab**：Issue・PR の参照と作成。
- **DB**：スキーマ参照・読み取りクエリ（書き込みは特に慎重に）。
- **ナレッジ/ドキュメント**：社内Wikiや仕様を検索して文脈に注入。
- **ブラウザ/E2E**：画面を開いて操作・スクリーンショット（UI検証）。
- **デザイン連携**：デザインツールから仕様を取り込む。

## セキュリティ（使う側の最重要点）
MCP は**外部コードに自分の環境への接続口を与える**。導入＝攻撃面の増加。
- **信頼できるサーバだけ接続**：第三者製は任意コード実行・データ送出の経路になり得る。出所を確認。
- **権限最小化＋承認**：書き込み・削除・送信・課金系のツールは**承認制（ask）か deny**（→ [05_設定とメモリ.md](./05_設定とメモリ.md)）。
- **ツール汚染／プロンプトインジェクション**：サーバが返す説明文や本文に悪意の指示が混じり得る。**ツール結果はデータとして扱い、指示として信頼しない**。
- **秘密情報**：サーバに渡す認証情報は環境変数/シークレットマネージャで。ログに残さない。
- **監査**：どのサーバの何を・どの引数で呼んだか記録する。

## 強み / 弱み・限界
**強み**：
- **能力を後付けで拡張**できる。1サーバを多ホストで再利用。
- 接続が**標準化**され、差し替え・共有が容易。

**弱み・限界**：
- **層が増える**＝障害切り分けが難しくなる（プロトコル越しの不具合）。
- **発展途上**で仕様・対応が動く。最新を追う必要。
- **安全は自前**：MCP は接続を標準化するだけで、安全にしてくれるわけではない。

## ハマりどころ / アンチパターン
- **素性不明サーバを接続** → 任意コード実行・情報漏えい。信頼境界を引く。
- **危険ツールを承認なしで自動実行** → 不可逆事故。書き込み系は ask/deny。
- **何でも MCP 化** → 単一PJ内の処理なら内蔵ツールやスラッシュコマンドで十分（YAGNI）。MCP は他ホスト共有・外部接続が要るときに。
- **ツール説明が雑なサーバ** → 誤呼び出し。description の質が精度を決める。
