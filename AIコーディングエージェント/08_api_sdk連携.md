# API / SDK 連携

## ひとことで言うと
**Claude を"自分のコードやCIから呼ぶ"側**。対話ツールとしての Claude Code に対し、こちらは **Claude API（anthropic SDK）** や **Agent SDK** を使って、自動化・社内ツール・バッチに Claude を組み込む。LLMをアプリに載せる実装の話は [../生成AI/](../生成AI/) と地続き。

## なぜ必要か / どこで効くか
- 対話やヘッドレス(`-p`)で足りないとき——**繰り返し・無人・大量・制御の効いた実行**が要るとき——はプログラムから直接叩く。
- 効くのは：**CIでの自動レビュー / 定期バッチ（仕分け・要約）/ 社内向けの自作エージェント / 独自UIへの組み込み**。
- 「使う側（Claude Code）」と「作る側（API/SDK）」は**地続き**：Claude Code で得た"効く頼み方・検証の型"は、そのまま API 実装の設計に効く。

## 3つの組み込み口
```
① Claude API（anthropic SDK）  … 最も低レベル。1リクエスト＝メッセージ＋ツール定義を自分で組む
② Agent SDK                    … エージェント的な多段ループ（tool use・計画・検証）を組みやすくした層
③ Claude Code をヘッドレスで    … claude -p をスクリプトから呼ぶ（最小コストの自動化）
```
- **まず ③** で済むなら SDK を書かない（YAGNI）。制御・状態管理・独自UIが要るなら ① / ②。

## API 呼び出しの骨格（イメージ）
```python
# anthropic SDK イメージ（最新の引数・モデルIDは公式/ claude-api スキルで確認）
from anthropic import Anthropic
client = Anthropic()  # APIキーは環境変数 ANTHROPIC_API_KEY

resp = client.messages.create(
    model="（用途に応じたモデルID）",
    max_tokens=1024,
    system="あなたはレビュアー。指摘は重大度つきで箇条書き。",
    messages=[{"role": "user", "content": "この差分をレビュー: ..."}],
)
print(resp.content)
```
- **system** にロール・出力形式を固定し、**messages** に文脈を積む（[../生成AI/プロンプト設計.md](../生成AI/プロンプト設計.md)）。
- **max_tokens / temperature / top_p** などの推論パラメータの意味は [../生成AI/llm基礎.md](../生成AI/llm基礎.md)。

## モデル選択（2026時点の考え方）
| 用途 | 目安 |
|---|---|
| 主作業・バランス | Sonnet 系 |
| 最深の推論・難タスク | Opus 系 |
| 高頻度・軽量・並列ワーカー | Haiku 系 |
- **正確なモデルID・料金・コンテキスト上限・パラメータは変動する**。記憶で書かず、**`claude-api` スキルや公式ドキュメントで最新値を確認**してから実装する。
- コスト最適化の定石：**安いモデルで前さばき → 必要な部分だけ上位モデル**、共通部分は**プロンプトキャッシュ**。

## CI/自動化での型
```
入力（差分/Issue/ログ）
  └─[検証・PII除去] プロンプト組み立て（system＋文脈＋指示）
        └─ API 呼び出し（モデル/max_tokens/tool定義）
              ├─ tool 呼び出し → 実行 → 結果を返して再度（エージェントループ）
              └─ JSON/テキスト
                    └─[スキーマ検証・ガードレール]→ 後段（コメント投稿・ラベル付け等）
  ※ トレース・トークン/コスト計測・レイテンシ計測（→ ../生成AI/評価と監視.md）
```
- **出力は必ず検証**してから後段に流す（スキーマ検証・ガードレール）。LLMの出力を無検証で副作用に繋がない。

## セキュリティ / 運用
- **APIキーは環境変数/シークレットマネージャ**。コード・ログ・リポジトリに残さない。
- **入力検証・出力検証**を境界で必ず（外部データは信頼しない）。
- **レート制限・タイムアウト・リトライ・フォールバック**を実装（→ [../生成AI/運用とコスト.md](../生成AI/運用とコスト.md)）。
- **プロンプトインジェクション**：ツール結果・外部本文は指示でなくデータとして扱う（→ [../生成AI/プロンプト設計.md](../生成AI/プロンプト設計.md)）。

## 強み / 弱み・限界
**強み**：
- **無人・大量・制御の効いた**実行ができる。独自UI・社内システムに組み込める。
- ツール定義・スキーマ・キャッシュで**精度とコストを自分で設計**できる。

**弱み・限界**：
- **実装・運用の責任が全部自分**（検証・監視・コスト管理・セキュリティ）。
- **仕様/モデルが更新**される。バージョン差・移行に追従が要る。
- 確率的出力ゆえ**検証層が必須**。作り込みは Claude Code 対話より重い。

## ハマりどころ / アンチパターン
- **モデルID・料金を記憶で決め打ち** → 古い値で事故。最新を確認。
- **③で足りるのに最初から重いSDK実装** → 過剰。まずヘッドレスで試す（YAGNI）。
- **出力を無検証で副作用に接続** → 誤動作・事故。スキーマ検証・ガードレールを挟む。
- **キャッシュ未使用で同一プレフィックスを毎回送る** → コスト・レイテンシの無駄。
- **APIキー混入** → 漏えい。環境変数＋秘密スキャン。
