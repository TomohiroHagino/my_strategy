# Claude Code 基礎

## ひとことで言うと
**ターミナルで動く"エージェント型"のコーディング支援ツール**。チャットボットのように「答えを返す」のではなく、**自分でファイルを読み・編集し・コマンドを実行し・テストして検証まで回す**。人は「何をしたいか」と「どこまで任せるか」を与える側に回る。

## なぜ必要か / どこで効くか
- IDE のコード補完は「**今書いている行**」を助ける。Claude Code は「**タスク全体**（複数ファイルの変更・調査・リファクタ・バグ修正・テスト追加）」を助ける。粒度が一段大きい。
- 強みは **コードベースを横断して文脈を集め、計画を立て、変更と検証を一連で回せる**こと。逆に言えば「適切な文脈」と「検証の手段」を渡せないと精度が落ちる。
- 効くのは：**定型作業の自動化 / 不慣れな言語・FWの探索 / 大量の機械的修正 / バグの再現と修正 / ドキュメント生成 / レビュー**。

## 提供形態
| 形態 | 用途 |
|---|---|
| **CLI（ターミナル）** | 本体。対話REPL / バッチ(print)の両方 |
| **IDE拡張**（VS Code / JetBrains） | エディタ内から起動・差分確認 |
| **デスクトップ / Web(claude.ai/code)** | GUI で同等の操作 |

## 起動モード（最重要：3つを使い分ける）
```
┌ 対話モード（REPL）   … `claude` で起動。会話しながら進める。日常はこれ
├ print/ヘッドレス      … `claude -p "…"` 1発実行して標準出力に返す。CI・スクリプト向け
└ plan モード           … まず「計画」を立てさせ、人が承認してから実装。破壊的/大規模で必須
```
- **対話**：探索的な作業・試行錯誤に。途中で軌道修正できる。
- **print（`-p` / `--print`）**：入出力をパイプできる。`git diff | claude -p "レビューして"` のように**部品として組み込める**。CI・フック・自動化の主役。
- **plan**：「読む・調べる」だけ先にやらせ、**変更前に計画を提示**させる。承認するまでファイルを触らない。**やり直しコストの高い作業は必ずこれ**。

> 権限/モードの切り替えはセッション中に**Shift+Tab で循環**（通常 → 編集自動承認 → plan …）。詳細は [05_設定とメモリ.md](./05_設定とメモリ.md)。

## 基本操作（対話セッションの型）
```
1. 目的を伝える          「Xを実装したい」「このバグを直したい」
2. （大きければ）計画させる  plan mode で方針を出させて承認
3. 実装させる             ファイル編集・コマンド実行はツールとして実行される
4. 検証させる             テスト/ビルド/型チェックを回させる
5. レビュー → コミット     人の指示でコミット/PR（勝手に push させない）
```
- **具体的に頼む**ほど精度が上がる。「直して」より「`auth.ts` の `login` がnullで落ちる。再現テストを書いてから直して」。
- **中断**：Esc で実行中の動作を止めて方向転換できる。
- **ファイルの指し方（`@file`）** は、次の「コンテキスト管理」で扱う（文脈を渡す手段の一つなので、そこで説明する）。

## コンテキスト（文脈）管理 ── 使いこなしの本丸
LLM の出力品質は**与えた文脈の質**でほぼ決まる。Claude Code では文脈は主に4経路で入る。

| 経路 | 何が入るか | いつ |
|---|---|---|
| **CLAUDE.md** | プロジェクトの前提・規約・コマンド | 毎セッション自動 |
| **明示の参照** `@file` | 今このタスクで見るべき具体ファイル | 都度 |
| **ツール実行結果** | grep / Read / Bash の出力 | エージェントが自分で集める |
| **MCP / サブエージェント** | 外部データ・分離した調査結果 | 必要時 |

### `@file`（＝表の「明示の参照」）はどこに書く？ ── 対話プロンプトに直接打つ
上の表の **「明示の参照 `@file`」** を掘り下げる。`@` は**設定ファイルに書くものではない**。対話セッションで**自分がメッセージを打つ、その文章の中に直接書く**もの。「このファイルを見て」と言う代わりの、ファイル指定のショートカット。
```
> @src/auth.ts の login が null で落ちる。@tests/auth.test.ts も見て再現テストを足して直して
  ^^^^^^^^^^^^^                        ^^^^^^^^^^^^^^^^^^^^
  プロンプト（あなたが打つ文章）の中に @パス を混ぜるだけ
```
- `@` を打つと**パス補完**が出るので、そこからファイル/ディレクトリを選べる（タイプミスを防げる）。
- 役割：そのファイルの中身を**確実に文脈へ入れる**。「あのファイル」と曖昧に言うと探させる手間＆取り違えが起きるが、`@` なら一発で指せる（＝表の他経路「ツール実行結果」で探させるより速く確実）。
- ディレクトリ（`@src/`）を指せばその範囲を、複数 `@` を並べれば複数ファイルをまとめて渡せる。
- 似て非なるもの：
  - **`/` 始まり**＝スラッシュコマンド（`/clear` など。コマンド実行）。
  - **`@` 始まり**＝ファイル/ディレクトリ参照（今打っているメッセージに中身を添える）。
  - **CLAUDE.md 内の `@path`**＝別ファイルを常時取り込む“インポート”記法（→ [05_設定とメモリ.md](./05_設定とメモリ.md)）。**対話で打つ `@` とは別物**なので混同しない。

### 表の他の経路は「どこで設定する」か
`@file` がプロンプトに直接打つものなのに対し、表の他の経路は**置き場所や設定が別にある**。ここでは入口だけ示す（詳細は各ファイル）。
| 経路 | どこで用意するか | 詳細 |
|---|---|---|
| **CLAUDE.md** | リポジトリ直下の `CLAUDE.md` に書く（毎回自動で読まれる） | [05_設定とメモリ.md](./05_設定とメモリ.md) |
| **`@file`（明示の参照）** | **対話プロンプトに直接打つ**（上記） | この節 |
| **ツール実行結果** | 設定不要。エージェントが grep/Read/Bash で自分で集める | — |
| **MCP** | `settings.json` に**接続先サーバを登録**して外部ツール/データを生やす | [06_mcp連携.md](./06_mcp連携.md) |
| **サブエージェント** | `.claude/agents/` に役割を**定義**して切り出す | [03_サブエージェント.md](./03_サブエージェント.md) |
> つまり **`@file` だけが「その場で打つ」もの**で、MCP・サブエージェントは**事前に設定/定義しておく**もの。混同しやすいのでここで切り分けておく。

- **コンテキストウィンドウは有限**。長い会話・大量のファイル読み込みで埋まると、古い文脈が要約・脱落する。
- **`/clear`**：文脈をリセットして新規タスクへ（タスクが変わったら積極的に切る）。
- **`/compact`**：会話を要約して圧縮し、続きを継続する（同一タスクが長引いたとき）。
- コツ：**1セッション＝1タスク**に近づける。無関係な作業を同じセッションに混ぜない。

> 詳細原則は [09_ベストプラクティス.md](./09_ベストプラクティス.md)。

## 拡張思考（thinking）
- 難しい設計判断・デバッグでは**思考の深さ**を増やせる。「think / think hard / さらに深く」のように依頼すると内部推論の予算が増える（モデル・設定による）。
- plan mode と組み合わせると、**深く考えてから計画を出す**形になり、大きめの変更で効く。
- 使いどころは**複雑な問題のみ**。単純作業で深く考えさせてもコスト・時間の無駄。

## 主要モデルの選び方（2026時点の考え方）
| 用途 | 目安 |
|---|---|
| 日常の実装・主作業 | バランス型（Sonnet 系） |
| 最深の設計判断・難デバッグ・調査 | 推論重視（Opus 系） |
| 頻繁・軽量・並列ワーカー | 高速・低コスト（Haiku 系） |
- 正確なモデルID・料金・上限は**変動する**ため、`claude-api` スキルや公式で最新確認（→ [08_api_sdk連携.md](./08_api_sdk連携.md)）。
- 切り替えは `/model`。重い作業は推論重視、機械的作業は高速モデル、と**タスクで使い分ける**のがコスト最適。

## 強み / 弱み・限界
**強み**：
- **タスク全体を横断**して読む・直す・検証する一連を自走できる。
- ターミナル/CIに**部品として組み込める**（print モード）。
- 設定・コマンド・フック・サブエージェントで**自分の作業に合わせて拡張**できる。

**弱み・限界**：
- **確率的**で出力がブレる。同じ依頼でも結果が違う（→検証が前提）。
- **文脈が足りないと誤る**。コードベースの暗黙知は CLAUDE.md 等で明示しないと伝わらない。
- **コンテキスト上限**があり、長すぎると古い情報を失う。
- **嘘をつく/それらしく間違える**ことがある。テスト・レビューで必ず裏取り。

## ハマりどころ / アンチパターン
- **巨大タスクを丸投げ** → 文脈が溢れて迷走。**小さく分割**し、plan mode で区切る。
- **検証手段を渡さない** → 「できました」が嘘でも気づけない。テスト/ビルドを回させる。
- **1セッションに無関係作業を詰め込む** → 文脈汚染で精度低下。タスクごとに `/clear`。
- **危険操作を無制限に許可** → 不可逆事故。`--dangerously-skip-permissions` 常用は禁物（→ [05_設定とメモリ.md](./05_設定とメモリ.md)）。
- **出力を無検証でコミット** → バグ・秘密混入。レビューとテストを通す。
- **CLAUDE.md を作らず毎回口頭説明** → 同じ前提を毎回打つ無駄。規約は永続化する。
