# 設定とメモリ

## ひとことで言うと
**Claude Code の"挙動"と"文脈"を永続化する2本柱**。挙動＝`settings.json`（権限・フック・モデル・環境変数）、文脈＝`CLAUDE.md`／メモリ（プロジェクトの前提・規約をセッションをまたいで覚えさせる）。**毎回口で説明する手間をなくし、暴走を防ぐ**ための基盤。

## なぜ必要か / どこで効くか
- 同じ前提（使うコマンド・コーディング規約・ディレクトリ構成）を**毎セッション説明するのは無駄**。CLAUDE.md に書けば自動で読まれる。
- 何でも許可すると**不可逆事故**のリスク。権限設定で「やってよいこと」を絞る。
- 「整形は毎回」「危険操作は禁止」のような**自動化はフック**として settings に置く。
- 効くのは：**チーム共通のお作法の共有 / 事故防止 / 自動化の永続化**。

## 設定の置き場所（`.claude/` の全体像）
Claude Code の設定・拡張は、**ユーザー全体**（ホーム）と**プロジェクト**（リポジトリ）の2階層に、同じ構造で置く。
```
~/                                  ← ユーザー全体（全プロジェクト共通）
├── .claude/
│   ├── settings.json               … 権限・フック・モデル・環境変数（全PJ既定）
│   ├── CLAUDE.md                   … 自分のクセ・全PJ共通の前提
│   ├── commands/                   … 自作スラッシュコマンド（全PJで /xxx）
│   │   └── new-chapter.md
│   ├── agents/                     … サブエージェント定義（全PJ共通）
│   │   └── doc-style-checker.md
│   └── ...（memory/ なども環境による）
│
<repo>/                             ← プロジェクト（このリポジトリ専用）
├── CLAUDE.md                       … このリポの前提・規約（直下に置く・コミット）
├── .claude/
│   ├── settings.json               … プロジェクト共有設定（コミット＝チーム共有）
│   ├── settings.local.json         … 個人の上書き（.gitignore 対象）
│   ├── commands/                   … このリポ専用のスラッシュコマンド
│   │   └── release-notes.md
│   └── agents/                     … このリポ専用のサブエージェント
│       └── api-reviewer.md
└── （ソースコード …）
```
- **同じ名前のものは"より具体的"が勝つ**（優先順位）：
```
settings.local.json  ＞  <repo>/.claude/settings.json  ＞  ~/.claude/settings.json
（個人の上書き）          （プロジェクト共有）              （ユーザー全体の既定）
※ CSS の詳細度や .gitignore と同じ「具体 > 一般」の発想
```
- 使い分け：**全PJ共通の自分のクセ → `~/.claude/`** ／ **チームで共有したい規約 → `<repo>/.claude/`（コミット）** ／ **自分だけの実験 → `settings.local.json`（gitignore）**。

## settings.json の主な項目
| 項目 | 役割 |
|---|---|
| `permissions`（allow / deny / ask） | ツール実行の許可・拒否・確認 |
| `hooks` | 自動実行する処理（→ [04_フック.md](./04_フック.md)） |
| `model` | 既定モデル |
| `env` | 環境変数 |

```jsonc
{
  "permissions": {
    "allow": ["Bash(npm run test:*)", "Read", "Edit"],
    "deny":  ["Bash(rm -rf*)", "Read(./.env)"],
    "ask":   ["Bash(git push:*)"]
  },
  "model": "（用途に応じて）"
}
```
- **allow**：確認なしで実行してよいもの（信頼できる定型コマンド）。
- **deny**：絶対に実行させないもの（破壊的操作・秘密ファイルの読み取り）。
- **ask**：毎回人に確認するもの（push・デプロイなど外向き・不可逆）。
- 方針：**最小から始めて広げる**。安全な読み取り・テストは allow、外向き/破壊系は ask か deny。

## 権限モード（セッション中の運転モード）
```
default            … 変更・コマンドの度に確認（既定。安全）
acceptEdits        … 編集は自動承認（コマンドは確認）。信頼できる作業を速く
plan               … 読むだけ・計画のみ。実装前の探索（→ ワークフロー実践）
bypass(危険)        … 全確認をスキップ。基本使わない
```
- セッション中は **Shift+Tab で循環**して切り替えるのが手軽。
- **`--dangerously-skip-permissions` は常用しない**。隔離された使い捨て環境でのバッチなど、限定状況のみ。

## CLAUDE.md（プロジェクトメモリ）
**そのリポジトリでエージェントが毎回読むべき前提**を書く中心ファイル。リポジトリ直下に置く。
```markdown
# 例: CLAUDE.md
## このプロジェクトは
学習ノート集。各 .md は決まった書式テンプレに従う。

## 規約
- 文章は日本語。書式テンプレ（ひとことで/なぜ/本文/強み弱み/ハマりどころ/関連）を厳守
- ファイルは200-400行目安、800行上限
- 相互リンクは相対パスで張る

## やってほしくないこと
- 勝手に push しない / 無関係ファイルを触らない
```
- **`/init`** でリポジトリを解析して雛形を自動生成できる。そこから手で育てる。
- 階層：`~/.claude/CLAUDE.md`（全PJ共通の自分のクセ）＋ プロジェクトの `CLAUDE.md`（そのリポ固有）。
- **簡潔に・要点だけ**。長大にすると毎回コンテキストを食い、肝心の指示が埋もれる。
- 別ファイルの取り込み（`@path` などの参照）で分割もできる。肥大化したら分ける。

## メモリ（永続的な事実の記録）
- セッションをまたいで覚えておきたい**事実・好み・プロジェクト状況**を、ファイルとして残す仕組み（環境により `~/.claude/.../memory/` 等）。
- 向くもの：ユーザーの役割・好み、確定した方針、外部リソースへのポインタ。
- **向かないもの**：コードを読めば分かること、git 履歴に残ること、その場限りの話。それは保存しない。
- **重要な区別**：「今後Xしたら必ずYして」のような**自動挙動はメモリでは果たせない**。それは**フック（settings）の仕事**（→ [04_フック.md](./04_フック.md)）。メモリは"覚える"、フックは"実行する"。

## 強み / 弱み・限界
**強み**：
- 前提・規約を**一度書けば自動で効く**。説明コストの削減。
- 権限で**事故を構造的に防止**できる。
- 設定を**バージョン管理・共有**できる（`.claude/` をコミット）。

**弱み・限界**：
- **CLAUDE.md 肥大で逆効果**：長すぎると文脈を圧迫し指示が薄まる。
- **設定の階層を取り違える**と「効かない/効きすぎる」。優先順位を理解する。
- 権限を緩めすぎると**事故**、締めすぎると**確認地獄**。バランス調整が要る。

## ハマりどころ / アンチパターン
- **秘密情報を settings やコマンドに直書き** → リポジトリに漏れる。`env`/シークレットマネージャ＋ deny で `.env` 読み取り禁止。
- **CLAUDE.md に何でも詰め込む** → コンテキスト圧迫。要点だけ、肥大したら分割。
- **`--dangerously-skip-permissions` を日常使い** → 不可逆事故の温床。原則禁止。
- **自動化をメモリ/プロンプトで頼む** → 確実には効かない。フックに落とす。
- **local と project を混同** → 個人設定を共有したり、共有設定を個人で握ったり。置き場所を意識。
